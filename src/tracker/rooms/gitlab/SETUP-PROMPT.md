你要帮用户把 GitLab 配好。用户很可能从没用过 GitLab，也可能从没装过命令行工具。
按下面的顺序走，每一步都先说清「为什么做这一步」和「怎么算做完了」。

**任何 GitLab 细节以官网为准，不要凭记忆答。** 官方文档在 https://docs.gitlab.com/ ，
命令行工具（glab）的官方说明在 https://docs.gitlab.com/cli/ ——这一份里凡是官网已经写过的，都只给指路，不重抄。

## 一、顺序

1. **先探，再装**。跑 `glab --version` 和 `git --version`。有版本号就跳过安装，没有就照官网安装页装。
   判据：`glab --version` 打出具体版本号（形如 `glab 1.123.0`）。
2. **请用户自己造访问令牌**。这一步只能人做：把 https://gitlab.com/-/user_settings/personal_access_tokens 打开给他，
   范围**只勾 `api`**（个人令牌勾这一个就够用；为什么够，让用户看官网范围表下面那条脚注）。
   判据：用户手里有一串 `glpat-` 开头的令牌。
3. **登录**。`glab auth login --hostname <主机名> --stdin --git-protocol https --api-protocol https`，令牌从文件喂进去（见第二节第 2 条）。
   判据：`glab auth status` 打出登录名，并说明凭证已存进操作系统的凭据管理器。
4. **建一个沙箱项目**。`glab repo create <项目名> --private --skipGitInit`。
   判据：用 `glab api projects/<把完整路径编码后的字符串>` 能查到这个项目。
5. **收尾**。删掉喂令牌用的临时文件；把「用哪个主机、哪个项目」记下来，后面的活都要用这两个值。

## 二、官网不会说的坑

1. **装完别急着信「能找到 glab」**。宿主程序（编辑器、DSH 这类）是在**启动那一刻**读 PATH 的，
   所以刚装好的 glab，当前正开着的宿主仍然找不到它。判据：宿主自己的探测说找不到 glab 时，
   先用绝对路径跑一次 `glab --version` 证明装好了，再让用户重启宿主，或者把 `glab.exe` 放进宿主已经在用的工具目录里。
2. **令牌只显示一次，而且不要贴进对话**。让用户存成一行文本文件，用 `--stdin` 喂给 glab，喂完立刻删掉那个文件。
   令牌一旦进了聊天记录就算泄漏，只能请用户去官网把它 Rotate 掉重来。
3. **在别人的仓库目录里跑 `glab repo create` 会动到这个本地仓库**（它会做 git init 或加远端）。
   一律带 `--skipGitInit`，或者换一个空目录再跑。
4. **登录是持久的**。glab 把凭证放进操作系统的凭据管理器，配一次以后不用再喂令牌；换机器、换用户要重来一遍。
5. **接口回包里带密钥**。项目详情（`GET /projects/:id`）的回包里有 `runners_token` 这类凭据字段。
   要把回包存进仓库当测试样本时，先把这类字段剔除，不要原样提交。
6. **自部署与官网的差别主要落在主机名上**。同一套命令，把 `--hostname` 换成自部署实例的域名即可。
   用户提到「自部署」「极狐」时先问清主机名，不要默认 gitlab.com。
