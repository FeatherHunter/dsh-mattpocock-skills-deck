# 刷新机制的新家（src/refresh/）

> 归属：规格 #1419，骨架票 #1424。旧位置到新位置的完整对照见
> `docs/architecture/refresh-target-map.md`。

以前刷新相关的代码散在四个地方：`src/shared/refresh/`（17 个文件）、`src/host/refresh/`
（13 个）加 11 个宿主取数文件、客户端内核里的 9 个探测与心跳文件、3 个桥接文件。
改一个刷新行为要在四棵树之间来回跳，宿主逻辑与界面逻辑互相引用时也没有机器规则能拦住。
这个目录是搬家的新家：按“契约、内核、房间、登记”四层收拢，层与层之间有门禁守着（见下面
“机器规则”一节），搬完之后旧位置只剩转交，不再长新逻辑。

## 六个环节是怎么串起来的

一次刷新从触发到落定，走完下面六步。每一步只做一件事，下一步只读上一步交出来的东西：

1. 触发分类（contract）：这次刷新是定时到了、用户点了、还是外部事件敲门？只给事件定性，
   不动手干活。
2. 取数（rooms/host，宿主侧）：按分类去该去的地方拿数据（议题列表、评论、快照等），
   只在宿主进程里跑。
3. 行补丁（kernel）：把拿回来的数据算成“最小改动集”，决定哪些行要增删改。
4. 链合并（kernel）：多个改动撞在一起时按规则压成一个，避免界面闪烁。
5. 房间投递（rooms/host 发、rooms/client 收）：宿主算好的结果发给界面侧，界面侧只管收。
6. 渲染与心跳（rooms/client，界面侧）：界面把收到的改动渲染出来，并定时告诉宿主“我还活着”。

## 四层各装什么

- **contract/**：各层之间传话用的类型与分类（比如触发分类、行补丁的形状）。只放类型，
  不放任何会干活的代码；任何层都可以引用它。
- **kernel/**：纯计算（行补丁、链合并、预算、退避）。不碰文件、不碰网络、不读环境变量——
  给同样输入永远算出同样输出，这样单测不用搭环境。
- **rooms/host/**：必须在宿主进程里跑的逻辑（取数、快照、发投递）。
- **rooms/client/**：必须在界面进程里跑的逻辑（收投递、渲染、心跳）。
- **registry/**：装配点。宿主房间与界面房间互相不认识，由这里负责把两边连起来。

## 层边界（人话版，机器版见下一节）

1. 内核只算数：`kernel/` 里不出现文件、网络、进程、环境变量。
2. 两边房间零引用：宿主房间不引用界面房间，界面房间不引用宿主房间；
   两边要说话都经过登记（registry）与契约（contract）。
3. 外面不许深引房间与登记：新家之外的代码要用搬进来的东西，房间与登记的实现细节
  （`rooms/`、`registry/`）不对外；内核（`kernel/`）与契约（`contract/`）是公开的，
   deck 工具引预算数字、宿主闸引裁决与形状都走这两层（#1425 对规格地图第 24 行的修正：
   原文禁的是“房内部具体文件”，此前把内核也圈进来是错的）。
4. 例外：`src/host/index.ts` 里的旧探测处理段（wf.probe）在搬家完成前暂时留在原地，
   文件级门禁看不见函数段，它的搬迁由 #1429 负责，见目标地图 D4。

## 改动落在哪一层

| 想改的东西 | 落点 | 举例 |
|---|---|---|
| 事件怎么分类 | contract | 新增一种触发来源 |
| 算法怎么算 | kernel | 补丁合并规则、退避时长 |
| 宿主去哪拿数据 | rooms/host | 新增一个取数来源 |
| 界面怎么展示 | rooms/client | 快照渲染、心跳间隔 |
| 两边怎么连起来 | registry | 新增投递通道 |

## 机器规则与基线

上面“层边界”三条由 `tests/verify-dependency-rules.ts` 守着，规则定义在
根目录 `.dependency-cruiser.ts`，共四个条目（三组，零引用按方向拆成两条，
因为一条规则里多个目标条件是“同时成立”才判，两个方向必须分开写）：

- `refresh-kernel-no-io`：内核范围引了运行环境能力就判红。
- `refresh-host-room-no-client-refs`：宿主房间引用界面房间就判红。
- `refresh-client-room-no-host-refs`：界面房间引用宿主房间就判红。
- `refresh-outside-only-contract`：新家之外的代码深引房间或登记的实现细节就判红
  （规则名是 #1424 起的名字，沿用；禁的不是内核，见上层边界第 3 条）。

搬家中转期间，旧位置的文件暂时豁免，豁免清单在 `tests/refresh-baseline.json`。
这份清单只许缩、不许长：每次搬走一批，就删掉对应行；新文件不许进清单。
清单里每一行写着“为什么留”与“哪张票负责清掉”。

## 登记机制（构建、类型检查、测试怎么找到新文件）

- 构建清单是“逐文件登记”的（`scripts/build.mts`），搬一个文件过去，就在清单里加一行。
- 类型检查自动发现配置（`scripts/typecheck.mts`），搬过去的文件只要被某个已有配置覆盖
  就不用新建配置；空配置会被判红，所以不要为还没代码的目录建空配置。
- 测试加载约定优先（`scripts/ts-hook.mts`）：同名文件自动连上，不用登记。
