## Problem Statement

使用官方桌面版 + 本插件时，在 issue 数量较多的大仓库里正常用上一刻钟，界面会突然消失又自己回来，十几分钟十几次。不装插件就没事。插件日志里看到一分钟几十个外部小命令、每个等满 30 秒才放弃，以及一分钟两千多行技能检查记录。小命令太多 + 同一轮被反复问，是拖慢的主因；终端本身慢、杀毒多、内存超配只调阈值，不改回路。桌面杀界面的那一下是不是这些小命令造成的，还缺宿主侧证据。

来源：#960 诊断（含 AI 诊断区与两次补记）+ research/960-claim-verification.md（含五路深查与补记一至五）。报告人自带四合一补丁只作参考，不直接合入。

## Solution

从用户看：大仓库 + 弱终端下，点刷新、切会话、挂载面板不再越点越卡；慢的小命令不等满 30 秒就排队等，读的等得短、写的不提前杀；技能平时只查用到的几项，全量只在重查时查；连点只算一次，旧的没回新的就等旧的，不多起进程；日志关键行全留，量大合成一行。改完后同样的操作，小命令条数与同时在飞数先降下来，再看闪退还出不出。

## User Stories

1. As a 桌面版用户， I want 点刷新后只等一轮， so that 连点三次不会起三倍的进程。
2. As a 大仓库用户， I want 打开大仓库不比小仓库慢一个数量级， so that 日常能用。
3. As a 弱网用户， I want 慢网络下看到“未知、稍后”而不是“没登录”， so that 不被误导去重登。
4. As a 写操作用户， I want 建票改标签超时后知道到底写上没， so that 不敢重试也不会写两遍。
5. As a 刚建完仓库的用户， I want 建完点重查立刻看到新仓库， so that 不被旧结果骗。
6. As a 刚登录的用户， I want 登录完点重查立刻看到已登录， so that 不用等很久。
7. As a 刚装好技能的用户， I want 装完点重查立刻看到已安装， so that 不用等很久。
8. As a 切会话的用户， I want 切换会话不触发全量重查风暴， so that 切着不卡。
9. As a 多窗口用户， I want 两个窗口看同一仓库只花一份探测， so that 不抢名额。
10. As a 面板用户， I want 打开检查页秒显缓存、后台再补新， so that 不白屏。
11. As a 横幅用户， I want 横幅重查与检查页用同一份结果， so that 不问两遍。
12. As a 状态栏用户， I want 手动更新只刷一次链与快照， so that 不重复。
13. As a 维护者， I want 看到同时在飞数与耗时分布， so that 上限值不是拍脑袋。
14. As a 维护者， I want 超时、限流、登录失效分得清， so that 误报能定位。
15. As a 维护者， I want 关键日志全量、高频日志聚合， so that 事后有据可查又不刷屏。
16. As a 维护者， I want 写后、失败、超时的搭车规则可测， so that 改了不回归。
17. As a 本地 Markdown 后端用户， I want 这次改动不影响我的后端， so that 后端物理隔离不断。
18. As a 小仓库用户， I want 这次改动不让我变慢， so that 只治大仓库的病。

## Implementation Decisions

- 传输层准入：所有起外部小命令的地方共用同一道“同时在飞”计数，满了就等、不是失败；计数只算真起来的进程，排队等待不算；三路出站与只读的版本管理路都进同一口径；读写分桶，读桶大、写桶小。
- 分档超时：读的短、写的长、探活的最短；调用方透传的取消信号能杀掉排队与在飞；超时杀掉后记超时行，调用方按超时归网络档，不重试写操作。
- 技能按需：链上只问链条要的三项，全量二十多项只在重查与设置页问；查到的短时缓存，查不到与没查出来不存；技能变化广播按工作区分桶清，不全清；并发同键复用同一份，防惊群。
- 同钥匙搭车：钥匙 = 工作区键 + 后端 + 语言；旧的没回新的不起，只等旧的；写过东西之后不搭，失败不搭，超 30 秒不搭；短窗连点合并成“跑完再补一轮”；被合并的不算失败，记合并数；不同钥匙各跑各的，后台的不抢人的。
- 日志：关键与告警全量直通；高频成功明细降为按需（有变化才记 / 按计数聚合 / 按分钟聚合成一行）；等待与合并记合并数，不记失败；记账口径不变（起来之后才记）。
- 上限值先测再定：先拉耗时分布与同时在飞分布，再定读桶写桶各几个；报告里的 4 作下限参考，定版的 64 作上限参考，不直接二选一。

## Testing Decisions

- 好测试只看外部行为：并发压 N 路峰值不超过上限；同钥匙第二个 force 不新起进程；技能全量只在重查时问 N 项、平时只问 3 项；读超时与写超时各走各的档；失败搭车不传染；日志关键行全量、聚合行可数。不测内部队列数组长什么样。
- 测的模块：宿主电话层（探测、链、快照、列表）、传输层准入计数、退避与复用纯件、技能探测（命中/未命中/没查出来/广播清）。
- 先例：网关夹具的三向验证（现状绿/违规红/合规绿）、日志门禁（字段/开关/计数/覆盖）、退避与复用计数器的既有断言。新增缓存与队列按埋点纪律补日志点并同步附录对照表。

## Out of Scope

- 宿主杀界面的源码与日志取证（安装目录段落 + 宿主日志原文 + 时间对齐 + 长任务证明），仍缺，不在本规格。
- 杀毒名、内存数、代理配置的采集，不做。
- 上限最终取几，不等本规格定，等测量数据回来再拍。
- 界面文案与颜色不动；本地后端行为不动；服务端限流策略不动。
