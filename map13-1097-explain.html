1. 地图 #1076 是干什么的

地图标题：地图13收口：全域索引与旧票结账（状态：打开中，父票是 #1010）。

地图正文开头写了四句话，就是它的全部任务：

地图原话用人话解释
目的：让后来的人（和未来的 AI 会话）从一份索引读懂全域，同时给手写 JavaScript 清零、给旧票结账。写一份新人先读的索引，数清楚旧代码搬完没有，给历史遗留票一个交代。

交接给下一环：一个能被下一个改造项目安全接手的状态。下一个人接手时，不用再翻几十张旧票来猜。

目标里三件事具体指什么

第一件：全域索引。写出“一次调用经过八层”的全域索引，新人先读这一个文件。落点是 src/deck/README.md。第一版由地图01 的新开发票“一次调用全程索引”来写（#1094），本图 #1077 只负责核对：范围文件是否都归零、索引里每一段是否对得上真实文件与行号、旧票逐张结账。

第二件：手写 JavaScript 归零。核对仓里不再有手写 JavaScript（构建产物不计）。判据已经收窄成两条，见下面 #1078 一节。依据是两份棘轮名单：tests/handwritten-js-baseline.json（只许减不许增）与 tests/unmigrated-tests-baseline.json。

第三件：旧票结账。把 #1010 下面留下来的 27 张旧故障票逐张定去向：关、留、转。五张已修票要真仓回放后关闭，其余的标注去向（归谁、挂哪张新票、为什么不动）。

2. 对齐票 #1097 是干什么的

票标题：地图13收口讨论：收口判据与旧票结账口径（状态：打开中，父票 #1076，无评论，结论还没写）。它挡住两张开发票：#1077 与 #1078 都被 #1097 阻塞，结论不定就不能动手。

票面要定的三件：① 范围文件归零怎么数（以哪份清单为范围、只看本次范围还是全仓）；② 旧 27 张票逐张怎么结账（关、留、转，判据是什么）；③ 真仓回放怎么做（拿哪一天的导出包、走哪条调用）。

四个词的人话解释

(a) 收口是什么意思？
收口就是收尾。代码已经搬得差不多了，剩下的是“数清楚、写清楚、关清楚”，让下一个改造项目能安全接手。术语表里对应的词是“随重构收口”：一张旧故障票描述的问题，在本次重构负责的那段代码里不再存在；关闭这张票时，在票面写明由哪一次改写解决。它取代口语里的“吞掉”。已经修好但还没验收的票，不算收口。

来源：CONTEXT.md “随重构收口”词条（2026-10-12 定版）；#1076 边界“索引与结账，不再改产品行为”。

(b) 判据是什么意思？
判据就是“做到什么程度算过”，是能动手去跑的检查，不是形容词。例如归零的判据是两句：本次范围内的文件全部在新树且只有 TypeScript 真源、全仓新增手写文件只有 TypeScript；旧票的判据是关留转三向各满足什么条件；回放的判据是只看日志能定位到哪一步。判据不定，#1077 与 #1078 就没法开工。

来源：#1078 正文“判据收窄（对抗审查后）”；research/1010-adversarial-fixes.md 第43条验收口径。

(c) 旧票是什么意思？
旧票指 #1010 正文 Notes 里列的 27 张历史故障票（按 A–H 分组：父子边、整片调不动、通路额度闸、快照取数、登录态、链路回执、大仓库出站、旧脚本残余）。它们留在 #1010 下面，没有搬进新地图结构。注意两个数差：票面 A 组漏写了 #895（加上才是 27），而票结构文档写“28 张”是把并行改造票 #1012 也算进了分母。结账时要先正名单。

来源：#1010 正文 Notes “此前留下来的 27 张故障票（A–H 分组）”；research/1010-ticket-scope-1..5.md 五组判定；research/1010-ticket-structure.md 第十二节。

(d) 结账是什么意思？
结账就是给每张旧票定去向，一张不落。三个去向：关（问题已随重构消失，写明由哪次改写解决）；留（不归本次，照旧归各自的主人，只标注去向不强关）；转（问题还在但要另立新票承接，回标新票号）。#1010 的口径是“明确已可随重构收口的票，开发中发现即关闭并写明由哪次改写解决；不确定的票，等开发全部完成后人机协同逐张过”。

来源：#1010 维护者拍板评论“旧故障票处理”；#1078 做完“其余标注去向”。

讨论完会产生什么结果，如何帮到 #1076

产出是三条结论，写成能动手的话（清单是哪份、数法是哪条命令、旧票表长什么样、回放拿哪天包走哪条调用）。

落到三处才算讨论完毕（这是 #1097 票面自己定的做完判据）：① 本票评论写讨论过程与最终结论，一条一条写；② 地图 #1076 的 Decisions so far，要动手的人先读这里，没写进这里等于没定；③ 受影响的开发票正文或评论（只影响某一张就写进那一张）。三处都写完，本票才算讨论完毕。

如何帮到地图：结论一落，#1077 与 #1078 的阻塞就解开（它们正文都写“本图结论在两处：讨论票评论与 #1076 Decisions so far；冲突时以讨论结论为准”）。#1077 按结论核索引，#1078 按结论数归零并结账，地图 #1076 的做完标志逐项变绿。

来源：deck_issue_get #1097 全文（含“做完”“维护者没回话怎么办”“收尾时把结论落在三处”）；deck_issue_get #1077/#1078 “动手前先读”两节；#1076 Decisions so far 现状“暂无”。

#1078 地图13开发：手写 JavaScript 归零核对与旧票结账

最终目的：交出两样：归零核对通过，旧票按随重构收口结账。
