# 弹窗式提问工具

本项目不提供「弹窗式提问工具」——也就是面板或检查链在需要向人提问时，直接调起系统级问答框（类似 agent 侧的 `ask_user_question`）的那条路。需要人拿主意的问题，一律写在对话正文里。

## 为什么不在范围内

分三层看，任何一层单独成立都足以让它出圈：

1. **落点对不上**：`ask_user_question` 是 agent 侧的工具。面板与检查链这一侧根本调不到它；面板的动作类型只有注入提示、打开链接、远程调用、表单、刷新、向导这几种，唯一能让 agent 去提问的杠杆是「注入一段文字」。给动作表加一种类型，不会让 agent 真的去弹框。
2. **信息形态不匹配**：问答卡片只装得下选项标签和一小段自定义文本，装不下要给人读全的多段方案。问「A/B/C 选哪个」时，方案正文在对话里、卡片占着编辑器位置，人点选时看不到全貌，容易做无效决策（维护者 2026-10-28 的判断）。宿主的卡片现在是附着式的，旧理由「弹窗挡住正文解释」对今天的实现已不成立；本仓 `AGENTS.md` 的「提问方式」只是开发本仓时的约定、不随插件发布，也不能当产品理由。
3. **现有做法已经覆盖**：检查链的补充信息模板、讨论模板本来就是按对话正文提问的（`tpl.supplement` 的「问用户（逐条可直接回答）」、`tpl.discuss` 的「按本模板原有提问格式提出」）。真正需要补的是「什么时候该问」，不是「用什么控件问」。

不限制 AI 自由发挥：提示词里不写「不要用 `ask_user_question`」这类反向禁令。工具在会话里是否存在、AI 要不要调用，由宿主提供的工具清单和当下场景决定；本仓库只维持「动作模板把问题写在正文」这一既有写法。

如果以后要重新考虑，先改随包发布的提示词（`config/prompts/shared-sections.yaml` 的 `sharedTools` 增加提问分工）与动作会话的预设模式，再谈动作表；本仓 `AGENTS.md` 不随包发布，只改它不影响用户侧。
