Notion 是什么？和 GitHub 有什么不一样？
给新手的一份详细介绍

这份介绍只讲三件事：Notion 是什么，它和 GitHub 的根本差别，以及它对外提供哪些接口（API / CLI / 公共平台）。

一、Notion 是什么

一句话：Notion 是一本“活的笔记本 + 表格”，用来记事情、管任务、写文档。

你打开 Notion，会看到页面（Page）和数据库（Database）：

  • 页面：像一篇文档，可以写字、插图片、列清单、评论。一张任务票，在 Notion 里就是一个页面。
  • 数据库：像一张表格，很多页面排在一起，每一行是一张票，每一列是一个字段，比如标题、状态、负责人、日期、标签。
  • 数据源：较新的 Notion 把表格底下又分了“数据源（data source）”，一个表格下面可以有多个数据源。认准数据源编号（data source id）才不会找错，这就是为什么技术方案里写用 collection://<id> 来定位。
  • 内容块：页面里的正文不是一整坨文字，而是一个个小块（段落、标题、待办、图片）。程序读出来要把这些小块转成我们常见的 Markdown 才好显示。
打个比方：Notion 是你们团队共用的一本任务台账，本子在 Notion 的云上，不在你电脑里。

二、Notion 和 GitHub 的差别

GitHubNotion
主要管什么代码和围绕代码的协作。核心是仓库（存代码历史）和 Issue（记 bug 和需求）。事情和文档。核心是页面和数据库，记任务、写知识库、做计划。
版本管理有。Git 记录每一行代码谁改的、能回滚、能合并，是真正的版本管理。没有 Git 那种版本管理。只有页面历史记录，能看改过什么，但不能像代码那样分支合并。
一张票长什么样Issue：有标题、正文、标签、负责人、评论、状态（打开/关闭）。数据库里的一行：标题是名称字段，正文是页面内容，状态是单选字段，标签是多选，负责人是人员字段，父子/阻塞靠关系字段连起来。
关系Issue 之间有子任务、阻塞关系，语义比较固定。关系是自己连的。你说哪两列是“父项”“阻塞”，它就是什么，没有固定含义，所以不同团队叫法不一样。
权限仓库的读写权限，比较粗：能看、能写、管理员。页面级的分享和数据库权限，比较细：谁能看哪一页、谁能改哪个字段。
所以记住结论：Notion 不是 Git，也不是版本管理工具。Git 回答“代码变成什么样了”，Notion 回答“事情做到哪一步了”。我们插件里的“后端”指的就是“票存在哪里”，GitHub 是一种，Notion 是另一种。

三、接口是什么形式的

程序和 Notion 打交道，主要走 REST API，就是通过网址发请求、拿回 JSON 数据。官方文档在 developers.notion.com。

  • 查表格：按数据库 / 数据源编号查出一批页面，可以过滤和分页。
  • 读一页：按页面编号读属性（标题、状态、负责人）再读内容块。
  • 建页 / 改属性：新建一行、改某个字段（比如把状态从“进行中”改成“完成”）。
  • 评论：列出评论、新加一条评论。
  • 用户：查当前是谁、列出成员，用来做“认领人”。
  • 搜索：按标题搜页面和数据库。
  • 鉴权：两种。自己用的走 Integration Token（一串密钥，请求时放在请求头里）；给别人用的走 OAuth（点授权按钮，不直接碰密钥）。我们插件要求走已有渠道（连接器或环境变量），不自己发明存密钥的新格式。
  • 额度：Notion 按请求次数限流，不是按点数。用坏了会回限流错误，程序要等一会儿再试。对应到插件里就是 requests-only 那种口径。

四、有没有 CLI

有，但和 Git 的命令行不是一回事。

  • GitHub 有 gh，GitLab 有 glab，装在本机敲命令就能建票、看票，因为它们本来就是给程序员用的。
  • Notion 官方有一套 Notion CLI，可以从终端调 API，适合写脚本时用。但它比较新、功能偏调试和搭线，不像 gh 那样是人人必装的日常工具。
  • 日常用 Notion 还是网页和客户端为主，CLI 只是给开发者省事的。

五、有没有公共平台

有，两层意思：

  • 给人用的：Notion 网页版和客户端 + 模板市场，大家在上面建工作区、分享页面。这就是“公共平台”的本体。
  • 给程序用的：开发者平台（上面的 API 文档站）+ 集成库。你做好一个集成，可以设成只给自己工作区用（内部集成），也可以发布到集成库给别人安装（公开集成，走 OAuth 授权）。这和 GitHub 的 Marketplace / OAuth App 是一个思路。

六、还有什么新手该知道的

  • SDK：官方有 JavaScript / Python 的包，把发请求包了一层，不用手拼网址。社区也有很多现成的。
  • Webhook / 自动化：Notion 有自动化（状态变了自动做点什么），外部程序要实时知道变化，一般靠轮询（隔一会儿查一次）或自动化回调，不像 GitHub 那样 Webhook 那么成熟。
  • 导出：页面可以导出 Markdown / CSV / PDF，搬家时有用。
  • 和我们插件的关系：插件要新盖一间“Notion 屋”，学会上面这些接口，才能把 Notion 的一行当一张票来显示。今天只会 GitHub / GitLab / 本地文件，所以 Notion 的库还认不出来。

七、插件的 27 个接口映射到 Notion：哪些能做

我们插件不管后端是谁，只认同一套 27 个动作（24 个操作 + 3 个定位口，唯一真源在 src/tracker/contract/operations-catalog.ts）。后端对每一条只许回答“我实现”或“我不支持”，不许自己加私活。下面按新手能看懂的话逐条给判断。

先记结论：日常看票、建票、改票、评论这十来条可以直接做；父子、阻塞、标签颜色要打折；问仓库权限、放配色文件这两条建议直接报不支持。最小可跑集和本地小样例一样，只要 4 条（list / get / create / getDependencies）就能把主流程转起来。
插件要的动作Notion 对应做法判断新手话备注
preflight（路通不通）拿密钥问一次表格在不在、能不能读✅ 可以只查环境，不预判能不能建票。
list / listPage（列票/翻页）按数据源编号查一批行，支持过滤和分页✅ 可以排序固定按创建时间倒序，游标原样传回即可。
counts（数有多少张）同一查询多翻几页数出来⚠️ 能做但贵Notion 没有“只给数字”的接口，只能把行拿回来数，票多时会慢，要如实报截断。
get（读一张）读一行属性 + 读页面内容块 + 按需读评论✅ 可以正文块要转成 Markdown，样式会丢一点。
getDependencies（谁挡了我）读约定的关系列（如“阻塞”列）再反查“我挡了谁”⚠️ 打折Notion 的关系没有固定含义，必须先约定哪一列算阻塞，否则读不到。
create（建票）新建一行，标题、状态、标签一次写好，正文当内容块附上✅ 可以支持幂等键，避免重复建两行。
close / reopen（关闭/重开）把状态字段改成“完成”，或把页面归档；重开则恢复✅ 可以关闭原因要另找一处记，Notion 状态本身不存原因。
comment（评论）列评论、新加一条评论✅ 可以和 GitHub 评论基本一一对应。
update（改字段）一次改多个属性✅ 可以（子集）标题、正文、状态好改；空补丁不发请求。
setLabels（改标签）覆盖式写多选列✅ 可以传什么就是什么，不是增量加。
setAssignees（改负责人）写人员列✅ 可以人必须已在工作区里，否则写不上去。
setParent（挂到哪张地图下）写约定的“父项”关系列，null 表示移到根⚠️ 打折Notion 表格行没有原生父子，只能靠约定的一列来模拟。
setBlockedBy（改阻塞）写约定的“阻塞”关系列⚠️ 打折自己挡自己、转圈这两种必须在插件侧拦下，Notion 自己不拦。
getCurrentUser（我是谁）查集成自己是谁、列成员⚠️ 打折能认出机器人自己，但“当前操作的人”不如 GitHub 准。
initProject（建仓发布）新建一个数据库并配好列⚠️ 能做但重相当于帮用户搭一张新表，首版可以先不做。
listLabels（有哪些标签）读多选列的全部选项✅ 可以取不全必须整体报错，不许给残缺清单。
setLabelColors（改标签颜色）改选项颜色⚠️ 打折Notion 只有固定几种颜色，自定义的颜色值贴不上去。
getRepoPermissions（有没有写权限）问集成权限❌ 建议不支持Notion 是按页面和集成能力授权，折不成“能推/能整理”两格，诚实回不支持。
listSubIssues（一张地图下全部子票）按“父项”列过滤并翻页拉到底⚠️ 打折依赖同一约定列；拿不全要报 capped/missing。
ensureLabelColorsFile（放配色文件）往工作区放文件❌ 建议不支持颜色真源在 Notion 远端，放本地文件改了也不算数，和 GitHub 一样报不支持。
listMaps（一次取全量地图）查“类型是地图”的行✅ 可以内部写死查打开+关闭、标签含地图标记，撞上限如实报截断。
readBudget（读剩余额度）只读本地缓存，不碰 Notion✅ 可以唯一不记账的动作，永远放行。
定位口 getRepoKey / describe / issueAddress目录解析 / 表格身份 / 票的网址✅ 可以（其一为空）getRepoKey 恒回空（没有 owner/name 是合法答案）；地址回 Notion 页面链接。
落地顺序建议：第一批先做 preflight / list / listPage / get / create / update / comment / close / reopen / setLabels / setAssignees / listLabels / listMaps / readBudget；第二批再做关系三件（getDependencies / setParent / setBlockedBy / listSubIssues），前提是和用户约定好“父项”“阻塞”分别是哪两列；不做的如实报 unsupported，上层会自动降级，不算故障。
