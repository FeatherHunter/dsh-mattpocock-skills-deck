# 技能机制

[`writing-for-agents`](SKILL.md) 里专门讲技能的那一支：当你要写的文档是一份技能时，有哪些地方不一样（frontmatter、调用方式的选择、路由技能）。其余关于写法的内容，都是 `SKILL.md` 里那套通用的参考资料。

## 调用方式

两种选择，各自在两种负载之间做取舍：

- **模型调用式**技能保留 `description`，代理可以自己触发它，其他技能也能调用它。你仍然可以直接输入它的名字：模型调用总是_包含_人的调用；描述只增加代理发现它的能力，从不会剥夺人调用它的途径。描述是技能最顶层的上下文指针，而且被迫一直常驻加载：用常驻的上下文负载换取可发现性。一个内容全是参考资料、又采用模型调用的技能，也是共享参考资料的落脚处：其他技能可以调用它，于是几份技能都需要的参考资料可以只放在一个地方。具体做法：不写 `disable-model-invocation`，并写一条面向模型的描述，把触发它的各个分支都带上（`SKILL.md` 里写指针的规则在这里完全适用）。
- **用户调用式**技能把描述从代理够得到的范围里拿掉：只有人亲自输入它的名字才能调用它，其他技能都调用不到。它不花一点上下文负载，但要花认知负载：你就是那个必须记得它存在的索引。具体做法：设置 `disable-model-invocation: true`；`description` 转而面向人：一行摘要，不带触发条件清单。

只有当代理必须靠自己够到这份技能、或者另一份技能必须调用它时，才选模型调用。如果它只会由人手动触发，就做成用户调用式，不付任何上下文负载。

两份用户调用式技能都需要的共享参考资料，两边都放不下：它们都没有描述，谁也触发不了谁。把这份资料推到一个技能系统之外的普通文件里：那是任何技能都能指过去的外部参考资料。

## 按调用方式拆分

拆分里的「按调用方式」这一刀（按序列拆的那一刀在 `SKILL.md` 里）：当你有一个独立的引导词、可以靠它单独触发一份技能（一个你确实会在提示词里用到的触发词），或者另一份技能必须够到它时，就把这部分拆成一份模型调用式技能。新的常驻描述要花上下文负载，所以这种独立触达必须值回这份成本。

## 路由技能

当用户调用式技能多到你记不过来时，堆积起来的认知负载由**路由技能**来治：一份用户调用式技能，把其他技能都点出来，并说明各自什么时候该用，于是人只需要记住一份技能，而不是很多份。它只能提示，永远不能替你触发那些技能：用户调用式技能没有描述，除了人，什么都够不到它们。
