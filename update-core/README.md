# 更新核心（update-core）

独立 TS 更新模块的源码家：以后独立成包时整个目录拎走（538 落点决议）。

## 里面有什么

- `src/ports.ts`：插口定义（只放类型，唯一的运行时内容是一行模块标识）。
  核心只管做决定，插口由核心定，跑腿的活全在外面。
- `src/service.ts`：业务流程。只记得规矩（查状态读本地、查新版联网问一次、
  凭证加指纹、装前复核、请求编号去重、加锁串行、备份顺序、后台执行、重启确认、
  残留自愈），不动手装。零导入，依赖全当参数传。
- `src/commands.ts`：命令拼接（按钮强制官方源加精确版本，手工沿用本机源）。
  自包含零引用（同层互引门禁要求），类型引用只用 import type。
- `src/runtime.d.ts`：核心允许触碰的通用运行时形状（TextEncoder、URL）。
  只有 Node 宿主与浏览器闭包两边都有的能力才允许出现在这里。
- `build.mjs`：编译脚本。esbuild 只转译不打包，一对一生成
  `src/shared/update/` 下的同名 JS；另跑 `tsc --noEmit` 只做类型检查。
- `tsconfig.json`：类型检查配置（严格模式，不产出）。

## 给第二家的三条保证（538 决议）

1. 输出目标定死保守版本（ES2020），两边都跑得动。
2. 核心里不碰任何 Node 或浏览器专属能力，跑腿全在适配器。
3. 类型只用标准写法，不依赖特殊编译选项。

第二家用自己的工具链直接吃 TS 源码，我们的编译只服务 deck。

## 常用命令

- `node update-core/build.mjs`：类型检查加转译，生成物提交到 git。
- `node tests/verify-update-freshness.js`：新鲜度门禁
  （TS 改了而 JS 没重新生成就变红，另含只读行为契约自检）。

## deck 侧落点

- 纯逻辑进 `src/shared/update/`（文件之间不互相引用，同层互引门禁天然能过）。
- 宿主薄胶水进 `src/host/update.js`（跨层引用共享层允许；落盘与执行跑腿在 `src/host/updateStore.js`，同层边记基线）。
  胶水默认按命令行上报，Windows 下按钮安装走失败转手工（桌面检测后续票补）。
- 面板在设置页标题行：三态按钮、对话框两行字、开始更新后每秒轮询到待重启，装不了给原因加手工命令。
- 成品包 `files` 白名单不动（共享层整树进包、宿主整树复制）。
