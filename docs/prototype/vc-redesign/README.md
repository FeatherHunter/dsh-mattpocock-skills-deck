# 版本管理页重构原型

这是一个可以直接在浏览器里打开的静态页面，用来验证版本管理页的重构方案。页面里的数据来自本仓库真实的 git 记录（50 条提交、16 棵工作树、11 个未提交文件），界面上点暂存、提交、分支、工作树动作都不会真的改动仓库，结果条是本地模拟。

视觉基准是 `docs/design/20261026-version-control-unified-design.html`：外框是一张浅色纸面文档，里面嵌一块深色产品面板。原型把这个关系做成真实的页面结构，不是贴图。

两根不可让步的规矩：一是面板里不出现「复制命令去终端」这种中间步骤，所有动作都由面板自己执行；二是页面不绑定 GitHub 或其他托管平台，能力按 git 原语设计，后端换 GitLab 也一样能用。

## 视觉与皮肤

- 页面外框始终是设计稿的纸面样式（纸 `#f7f5ef`、墨 `#171a1f`、绿色强调 `#12703f`），不随产品皮肤切换。
- 产品面板有两套皮肤，结构与尺寸完全一致，只换颜色：
  - 深色（默认）：设计稿里的深色工程台账，面板 `#0c1118`、内层 `#111823`、前景 `#e7edf6`、绿色强调 `#3fb950`。
  - 浅色：同一份设计稿的纸面皮肤，面板是白纸 `#fffdf8`，字段与按钮退到米色，机框保持 `#efece2`。
- 顶部工具条可以现场切换宽度（300 / 380 / 460 / 520）与皮肤，两个开关都是分段控件，键位与真实页面一致。
- 全站不使用中点分隔符（U+00B7）：同步计数、时间事实、提交元信息、文件增删行数都拆成独立控件或独立行。源码与产物里搜这个字符应当为零。

## 怎么打开

直接双击或用浏览器打开本目录的 `index.html` 即可，不需要起服务器。`app.js` 是已经构建好的产物，`styles/app.css` 是手写样式。

默认面板宽度 460，接近仓库里记录的默认值。顶部工具条可以切换到 300、380、520，也可以切换深色与浅色皮肤。

也可以用 URL 参数直接打开某个状态，评审时用这个比手点三下再描述省事：

- `?width=380`：面板宽度，只接受 300 / 380 / 460 / 520
- `?theme=light`：皮肤，接受 dark 与 light
- `?view=changes`、`?view=commits`、`?view=worktrees`：打开时停在哪个视图
- `?open=<提交号>`：提交历史直接进某条提交的详情，例如 `?view=commits&open=a65498e89293c36f3f0781e38ee986d30bfe2418`
- `?filter=conflict`：改动视图只看某一组
- `?merge=1`：提交历史只显示合并提交
- `?q=日志`：在已加载的提交里筛选
- `?file=<路径>`：展开某个文件的逐行差异
- `?message=...`：预填提交说明
- `?demo=1`：给工作树视图补两棵演示用的异常工作树（被占用、目录不存在），正常数据里没有这两种
- `?confirm=1`：直接打开拉取前的确认气泡
- `?wt=abnormal`：工作树视图只显示需要处理的树，`?wt=all` 是默认的全部
- `?wtnote=0`：把工作树顶部那条可关闭的红字说明先收起来
- `?wtexpand=1`：展开工作树列表里的第一棵异常树，直接看到完整事实与三颗动作按钮
- `?wtpending=remove&wtpath=<路径>`：直接打开某棵工作树的移除确认卡，`unlock`、`prune` 同理
- `?branches=1`：打开分支页（覆盖在当前视图上），列表态
- `?branch=<分支名>`：分支页打开时直接进某条分支的详情
- `?bsub=create`、`?bsub=rename`：直接打开新建或重命名表单
- `?bpending=delete|switch`：配合 `?branch=` 直接打开删除或切换的确认卡
- `?ai=general`：直接打开「交给 AI」说明，`changes`、`worktrees`、`branches` 分别是另外三种入口口径
- `?aicopied=1`：让「交给 AI」说明直接显示复制完成后的状态，评审截第二张图用
- `?embed=1`：只留 520 宽的产品面板，去掉纸面外框，供文档插图使用

如果改了样式或脚本却看不到变化，是因为浏览器缓存了 `file://` 下的旧文件，把 `index.html` 里 CSS 与 app.js 链接末尾的版本号一起改一下，或者强制刷新。

## 交互态

每个可点控件都有悬停、按下、键盘聚焦、禁用四种状态，不只画静止样式：

- 按钮与图标按钮：悬停加深背景与边框，按下位移 1px，键盘聚焦出现绿色描边，禁用时褪色并把原因常驻在旁边。
- 页签：悬停有浅底，按下更深，选中项是 2px 绿色下划线，左右方向键可以切换。
- 筛选 chip：悬停提亮并换边框，按下位移，选中态用对应色调的淡底与描边。
- 文件行：行主体（展开差异）与暂存按钮是拆开的两个可点目标，各自有悬停、按下与聚焦；行主体可以按 Enter 或空格展开，但界面不写这条提示。
- 提交行：悬停缩进条上提亮，按下更深，选中时左侧出现 2px 绿条，Enter 打开详情；同样只做不提示。
- 提交详情：返回按钮悬停变蓝底，返回后恢复选中行与列表滚动位置。
- 搜索工具条：整条输入区用 focus-within 高亮；「只看合并」是带边框的胶囊开关，不是一段看起来不可点的文字。
- 拉取确认气泡：贴在被点的「拉取」按钮下方，没有整屏遮罩，也不锁滚动；只列前六个文件，超过时说明还有几个没有列出，取消与继续拉取是气泡里的两颗按钮。它是一层浮起来的小卡片，不是对话框。
- 工作树：顶部说明条是红字加关闭按钮；标题行右侧是「全部」与「需要处理」两个筛选胶囊；行内展开箭头点开详情，详情里有完整路径、分支、当前提交、状态原因，以及「解除锁定」「清理记录」「移除工作树」三颗动作按钮，全部在面板里直接执行。
- 工作树确认卡：点上面三颗动作中的任意一颗，展开区原地换成一张内联确认卡（危险动作用红色描边），列出这次会动什么、不会动什么；Esc 只收起这张卡，不改列表。确认后那一行直接按结果变化或从列表消失。
- 分支入口：顶部身份行里的分支名是按钮，点开是一个覆盖当前视图的分支页，不新增第四个页签。列表里标出当前分支与每个分支的领先/落后，点一行进详情；详情里有切换到此分支、合并到当前分支、重命名、删除分支四颗按钮，删除与「工作区有改动时切换」都先出内联确认卡。
- 新建与重命名分支共用一个表单，校验空名、空格与重名；提交后结果条贴在分支页底部，页面停在刚操作的那条分支上。
- 交给 AI 入口：同步带底部、改动页提交区提示行右端、工作树页底部、分支页底部各有一个入口，文案写当前这一页的难处，不写「智能助手」。悬停提亮，点开是一层盖住面板的说明卡片。
- 交给 AI 说明卡片：Esc、右上角关闭按钮、点背板三种关法；正文是一段可选中的纯文本，可以先用键盘选中再复制；点「复制这段说明」把整段写进剪贴板，底部换成一行绿色「已复制 N 个字符」。卡片打开时不会锁滚动，也不铺半透明遮罩。
- 窄宽度下入口自动降级：460 以下同步带入口压成单行，提交区那条入口隐藏，避免和文件列表抢高度；300 宽仍然可以从同步带、工作树页与分支页进入。
- 只读信息不做悬停反馈，包括同步计数、状态标签与工作树行，避免看起来像按钮。

## 交给 AI

这个页面里最难的地方不是点按钮，是不知道下一步该做什么。所以四个视图各留了一个入口，把此刻的完整状态写成一段给 AI 的说明，人只要复制过去就能接着谈：

- 说明分成九节：仓库与分支、工作区现状（逐个文件写清新增与删除行数）、其他工作树、本地分支、最近五条提交、我看到的现象、我想达到的结果、请你做什么、补充。最后三节留成填写的空白，等读者补上目标。
- 「请你」一节写了三条边界：先复述并指出可能的误解，再分步骤写清每一步改什么、怎么验证，涉及丢弃改动、覆盖历史或强推时先停下来问。
- 说明里带完整路径与文件清单，粘贴前可以删掉不想外发的部分。原型只负责复制，不会真的打开新对话；接进真实页面后，这一步应该直接进入新对话并带上这段说明，不需要人再复制。
- 入口文案按页面写：改动页问「拿不准怎么拆提交？」，工作树页问「不想自己排查？」，分支页问「分支关系太乱？」，同步带、工作树页与分支页各有一句总入口；没有异常时工作树页换成「没有需要处理的工作树，让 AI 解释一下」。

## 构建与类型检查

在仓库根目录执行：

```
node docs/prototype/vc-redesign/scripts/build.ts
node node_modules/typescript/bin/tsc -p docs/prototype/vc-redesign/tsconfig.json --noEmit
```

构建产物是 `app.js`，由 esbuild 打成单个 IIFE，目标 ES2020，不压缩。构建脚本会把源码里写 `./x.js` 的导入改指同目录的 `x.ts`，和仓库测试链的做法一致。

源码全部是可剥离类型的 TypeScript，没有 `enum`、构造函数参数属性这类需要真正转译的写法，浏览器端不需要额外的类型运行时。

## 和真实代码的关系

数据结构和判定规则对齐仓库里的真实模块，没有另起一套模型：

- 首屏数据、同步状态、动作是否可用的判定，来自 `src/shared/version-control/src/` 里的 `assemble()`、`judge()`、`describeTime()`、`splitPath()` 等纯函数；原型只是把采集好的输入喂进去，所以「按钮为什么禁用」的结论和线上一致。
- 真实页面入口是 `src/client/views/VersionControlTab.ts`，视图模块在 `src/client/views/versionControl/`，负责渲染、折叠、差异、写操作和文案。
- 宿主侧读写在 `src/host/versionControl.ts`、`versionControlWrite.ts`、`versionControlBasis.ts`、`versionControlCheck.ts`、`versionControlFiles.ts`。

原型没有直接引用客户端 DOM 模块，也没有把宿主代码打进浏览器，只复用共享核心的纯函数和类型。这样原型能跑在 `file://` 下，也避免和线上页面的渲染细节纠缠。

## 方案要点（与旧页面的差别）

- 顶部信息收成一条同步带：身份一行、同步计数一行、动作一行、原因与路径各一行；「读取于」和「远端依据」是两个带标签的事实，不再用中点把它们拼成一句话。
- 四个视图共用一条骨架：先说结论，再给证据（列表或提交），动作和结果贴着证据出现。
- 页签上的数字带单位，并且每个视图只统计自己那件事：改动是文件数，提交历史是已加载条数，工作树是棵数。
- 提交历史与提交详情用整页替换加明确的返回，不做左右两栏：面板最窄 300，两栏会把主题与路径截断。
- 合并提交先给「合并提交」这个结论，git 生成的英文原文降为一行小字保留下来。
- 工作树视图顶部固定当前工作树；被占用、目录不存在这类异常行排在最前，原因写在行内状态里；三颗动作直接在面板里执行，确认卡内联在展开区，不铺浮层。
- 分支是顶部身份而不是第四个页签：分支名点开以覆盖层呈现，切换、合并、重命名、删除都在这一层里完成；切完分支，顶部身份行立刻显示新名字。
- 面板里不出现「复制命令」：能被面板执行的动作就做成按钮，确认卡写明会动什么、不会动什么；确实超出面板边界的事情才用一句文案说明，不给半截命令让读者自己拼。
- 全部动作按 git 原语设计，按钮文案与判定不依赖 GitHub：领先/落后、合并、删除、解除占用这些概念换到 GitLab 或其他远端仍然成立。
- 一屏最多一个实心主按钮；推送这类同步动作在确实领先时用描边高亮，不用第二颗实心按钮。
- 禁用按钮旁边常驻原因，并且禁用时不再教「按 Enter 提交」。
- 行数差里的 0 不显示：纯新增文件不写「−0」，读者不用去找那 0 行在哪。
- 小字与次要灰都按 4.5:1 对比度重算过，深色与浅色两套皮肤分别定值，不直接套设计稿里只适合大字的灰。
- 每个视图都留了「交给 AI」的出口：把仓库、分支、每个文件的改动、其他工作树、最近提交和当前视线打包成一段说明，而不是只给一句「帮我看看 git」。入口文案写的是这一页具体的难处，读者不用先理解术语才知道该不该点。

## 还没有实现、需要宿主新增读写能力的提案

下面这些是设计稿里写了、原型没有做出来的，因为真实代码里没有对应的命令或读数，原型不画没有后端的按钮：

- 丢弃修改、加入 .gitignore、把冲突标记为已解决。
- 贮藏（stash）的创建、列出、恢复与丢弃。
- 修订上一条提交、撤销上一条提交、回退某条提交、拣选与变基。
- 在页面里真正执行分支与工作树的写操作：原型只模拟状态变化，真实宿主目前只有暂存、提交、拉取、推送四类写命令，分支与工作树需要新增读写能力。
- 远端管理（增删 remote、改上游、强推保护）与冲突解决向导。
- 全库提交搜索；原型里的筛选只作用于已经加载的提交，输入框文案写明了范围。
