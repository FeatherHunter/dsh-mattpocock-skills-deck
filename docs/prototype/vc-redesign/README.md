# 版本管理页重构原型

这是一个可以直接在浏览器里打开的静态页面，用来验证版本管理页的重构方案。页面里的数据来自本仓库真实的 git 记录（50 条提交、60 棵工作树、11 个未提交文件样本），界面上把文件加入这次提交、提交、切分支、丢掉未加入的改动、收起改动这些操作都不会真的改动仓库，结果条是本地模拟。

视觉基准是 `docs/design/20261026-version-control-unified-design.html`：外框是一张浅色纸面文档，里面嵌一块深色产品面板。原型把这个关系做成真实的页面结构，不是贴图。

两根不可让步的规矩：一是面板里不出现「复制命令去终端」这种中间步骤，所有动作都由面板自己执行；二是页面不绑定 GitHub 或其他托管平台，能力按 git 原语设计，后端换 GitLab 也一样能用。

第三条规矩是「就近」：入口点开的内容贴着入口出现，动作产生的结果贴着触发的按钮出现。分支列表贴着顶部身份行的分支名弹出，交给 AI 的说明贴着点开它的入口弹出，文件的更多动作贴着那一行展开，确认卡也留在行里；不再用整页切换或整屏卡片把相关内容推远。

## 视觉与皮肤

- 页面外框始终是设计稿的纸面样式（纸 `#f7f5ef`、墨 `#171a1f`、绿色强调 `#12703f`），不随产品皮肤切换。
- 产品面板有两套皮肤，结构与尺寸完全一致，只换颜色：
  - 深色（默认）：设计稿里的深色工程台账，面板 `#0c1118`、内层 `#111823`、前景 `#e7edf6`、绿色强调 `#3fb950`。
  - 浅色：同一份设计稿的纸面皮肤，面板是白纸 `#fffdf8`，字段与按钮退到米色，机框保持 `#efece2`。
- 顶部工具条可以现场切换宽度（300 / 380 / 460 / 520）与皮肤，两个开关都是分段控件，键位与真实页面一致。
- 全站不使用中点分隔符（U+00B7）：同步计数、时间事实、提交元信息、文件增删行数都拆成独立控件或独立行。源码与产物里搜这个字符应当为零。

## 怎么打开

直接双击或用浏览器打开本目录的 `index.html` 即可，不需要起服务器。`app.js` 是已经构建好的产物，`styles/app.css` 是手写样式。

默认面板宽度 460，接近仓库里记录的默认值。顶部工具条可以切换到 300、380、520，也可以切换深色与浅色皮肤。

也可以用 URL 参数直接打开某个状态，评审时用这个比手点三下再描述省事：

- `?width=380`：面板宽度，只接受 300 / 380 / 460 / 520
- `?theme=light`：皮肤，接受 dark 与 light
- `?view=changes`、`?view=commits`、`?view=worktrees`、`?view=stash`：打开时停在哪个视图
- `?open=<提交号>`：提交历史直接进某条提交的详情，例如 `?view=commits&open=a65498e89293c36f3f0781e38ee986d30bfe2418`
- `?filter=conflict`：改动视图只看某一组
- `?merge=1`：提交历史只显示合并提交
- `?q=日志`：在已加载的提交里筛选
- `?file=<路径>`：展开某个文件的逐行差异
- `?message=...`：预填提交说明
- `?demo=1`：给工作树视图补两棵演示用的异常工作树（被占用、目录不存在），正常数据里没有这两种
- `?confirm=1`：直接打开拉取前的确认气泡
- `?wt=abnormal`：工作树视图只显示需要处理的树，`?wt=all` 是默认的全部
- `?wtnote=0`：把工作树顶部那条可关闭的红字说明先收起来
- `?wtexpand=1`：展开工作树列表里的第一棵异常树，直接看到完整事实与三颗动作按钮
- `?wtpending=remove&wtpath=<路径>`：直接打开某棵工作树的移除确认卡，`unlock`、`prune` 同理
- `?branches=1`：打开贴着分支名弹出的分支浮层，列表态
- `?branch=<分支名>`：分支浮层打开时直接进某条分支的详情
- `?bsub=create`、`?bsub=rename`：直接打开新建或重命名表单
- `?bpending=delete|switch|rebase`：配合 `?branch=` 直接打开删除、切换或变基的确认卡
- `?menu=<路径>`：展开某个文件的更多动作菜单
- `?cpending=discard|ignore|delete-untracked|discard-all|resolve-ours|resolve-theirs&cpath=<路径>`：直接打开某个文件的丢弃、忽略、删除未跟踪、解决冲突的确认卡；`discard-all` 不需要路径
- `?commitmenu=<提交号>`：展开某条提交的更多动作菜单
- `?commitconfirm=<提交号>`：直接打开「撤销这次提交」的确认卡
- `?stashdemo=1`：给「收起的改动」视图补三条演示记录，正常打开时是空的
- `?stashpending=drop&stashid=stash@{0}`：直接打开丢弃某条收起记录的确认卡
- `?ai=general`：直接打开「交给 AI」说明，`changes`、`worktrees`、`branches` 分别是另外三种入口口径
- `?aicopied=1`：让「交给 AI」说明直接显示复制完成后的状态，评审截第二张图用
- `?embed=1`：只留 520 宽的产品面板，去掉纸面外框，供文档插图使用
- `?manage=1`：打开管理索引，九张卡对应九个二级页
- `?page=<页面名>`：直接打开某个二级页。页面名有 `branch-tags`（分支与上游）、`remote`、`submodules`、`maintenance`、`migrate`、`config`、`hooks`、`diagnostics`、`platform`、`rebase`、`conflicts`、`task`、`search`
- `?flow=rebase|conflicts|task`：直接打开变基、冲突处置或长任务演示
- `?palette=1`：打开命令面板；`?pquery=<词>` 预填筛选词，例如 `?palette=1&pquery=11.6`
- `?page=search&pq=<词>`：带搜索词打开全库搜索；`pq` 在其它页面上是页面内的筛选词
- `?cap=<编号>`：打开这条能力所在的页面并高亮它，例如 `?cap=11.6`
- `?capopen=<编号>`：直接展开某条能力的四段式确认卡，例如 `?page=maintenance&capopen=11.5`
- `?danger=<编号>`：直接打开不可逆动作的整页核对，例如 `?page=maintenance&danger=11.6`
- `?rebase=1&rebasestep=<步数>`：开始变基演示并推进到第 N 步
- `?conflicts=1`：打开冲突处置演示；`?task=1&taskp=<百分比>`：打开长任务演示并推进到某个进度
- `?search=<词>`：带搜索词打开全库搜索，空值表示只打开页面
- `?pfilter=<类别>`：搜索页只看某一类命中，取值 `all`、`commit`、`branch`、`tag`、`cap`

如果改了样式或脚本却看不到变化，是因为浏览器缓存了 `file://` 下的旧文件，把 `index.html` 里 CSS 与 app.js 链接末尾的版本号一起改一下，或者强制刷新。

## 管理页、整页流程与命令面板

四个页签只放每天都要用的四件事（改动、提交历史、工作树、收起的改动）。其余能力不往页签里塞，也不藏在菜单深处，而是收进一层管理页，再从全局入口直达：

- 顶部身份行右侧有四颗常驻图标：复制仓库路径、交给 AI（四角星）、放大镜（命令面板）、齿轮（管理）。四颗固定在身份行末端、不换行，长分支名由左边截断；窄到 300 宽时「复制仓库路径」让出位置，其余三颗在任何宽度都保留。
- 打开任意二级页（管理索引、九个分区与四个整页流程）时，同步计数、三个同步动作与四个页签一起让位：页面直接从身份行下方铺开，返回键并进标题行左端，不再单独占一行。退出后原来的页签、筛选词与滚动位置都还在。
- 管理索引是九张卡：分支与上游、远端、子模块、仓库维护、迁移与导入、配置、钩子、诊断、平台能力与边界。每张卡写明这一页收了几条能力、主要解决什么，点进去是二级页。索引顶部另有命令面板与全库搜索两个短入口。
- 分支与上游页列出 62 条本地分支与 40 个标签：当前分支、上游、领先落后、尖端提交各占一列，点一行回到分支浮层看详情。标签单独一段，写明每个标签指向哪条提交、是否已并入当前分支。分支浮层列表头也有一颗「标签与上游」按钮通到这一页。
- 远端页列出三个远端各自的拉取与推送地址、跟踪的分支数，以及拉取、抓取、推送三颗同步按钮；地址与列表都来自真实采集，不是占位。
- 仓库维护页先给仓库体量读数（loose 对象、pack 内对象、pack 数、pack 体积、可回收条数），再给无损整理动作与一个危险区；迁移与导入页给克隆、归档、离线包三种搬运方式与备份建议。
- 配置页按身份、行尾、钩子路径、凭证四组折叠，每项写明当前值、来源与改法；属性规则、邮件映射这类只读配置只展示不画按钮。钩子页列出 14 个钩子文件与各自的启用状态（当前全是 sample 文件），并提供手动运行入口。诊断页给版本、提交数、分支数、标签数等读数，以及 fsck、二分定位、reflog 三种只读诊断的形态。
- 平台能力与边界页把必须交出去的四类事情（编辑器与外部工具、任意命令、文件选择器与长任务、系统权限与密钥）和六条平台能力逐条写明「面板不做的原因」，没有操作入口就直说没有，不画半截按钮。
- 四个整页流程：交互式变基有六步待办（冻结工作区、选新基座、整理待办、逐步应用、校验、完成或回滚），可中途去冲突处置页，也可中止回到开始前；冲突处置按文件列出「选当前分支、选对方、打开外部编辑器、标记已解决」，全部标记后「继续合并」才可用；长任务给克隆、归档、离线包三个向导与一条进度条，可推进也可取消；全库搜索一次搜提交、分支、标签与能力四类，结果点开直接落到对应页面或行。
- 每条能力在页面底部按同一形状列出：编号、名称、级别、归属、对应 git 命令，以及「入口在哪、打开什么、结果落在哪」三行事实。只读能力只标「只读诊断」，不给可点按钮；可演示的能力点「演示」会在行内换出四段式确认卡，写清会动什么、不会动什么、恢复路径，取消按钮拿默认焦点，确认后结果贴在这条能力下面。
- 同一条能力只留一个主入口：页面上面已经按真实数据或流程列成动作行的能力（例如维护页的整理动作、迁移页的克隆与归档入口），底部清单只在说明里点名「这 N 条已在上方列出」，不再重复画一遍行。顶部动作行的确认卡与执行结果也直接贴在那条动作下面，读者不用被送到页面底部去看变化。
- 不可逆动作（例如清理不可达对象）多一道整页核对：会动什么、可逆性与恢复路径、执行前该核对的读数逐条列出，最后要求手敲「确认清理」四个字才能执行。这道核对页与主流程共用同一套页面骨架，不是弹窗。
- 命令面板（Ctrl 或 Command 加 K）搜 162 条能力的名称、编号、命令与落点，每行写明「在哪个页面、哪一步能找到它」，回车打开第一条；选中后跳到对应页面并高亮那一条能力。能力落点表来自 research/1589-capability-gap-map.md，原型只为已经画出入口的能力提供可点路径。

## 交互态

每个可点控件都有悬停、按下、键盘聚焦、禁用四种状态，不只画静止样式：

- 按钮与图标按钮：悬停加深背景与边框，按下位移 1px，键盘聚焦出现绿色描边，禁用时褪色并把原因常驻在旁边。
- 页签：悬停有浅底，按下更深，选中项是 2px 绿色下划线，左右方向键可以切换。
- 筛选 chip：悬停提亮并换边框，按下位移，选中态用对应色调的淡底与描边。
- 文件行：行主体（展开差异）与「加入」按钮、更多按钮是拆开的三个可点目标，各自有悬停、按下与聚焦；行主体可以按 Enter 或空格展开，但界面不写这条提示。
- 文件更多菜单：贴着这一行向右下展开的小卡片，里面按这一行「能不能丢、能不能忽略、是不是未跟踪、有没有冲突」列出动作，没有的动作不画；再点一次更多按钮或点外面收起。动作旁边带一行后果说明，例如「丢弃后这次修改就找不回来」。
- 文件动作的确认卡：丢弃、忽略、删除未跟踪文件、解决冲突这些危险动作先在那一行下面换出确认卡，写清会动什么、不会动什么；取消或按 Esc 只收起卡片，不改数据。分组头的「丢弃全部」确认卡贴在分组头上，同样先确认再动手。分组标题右侧的动作（全部加入、丢弃全部）装在同一组里靠右排，组内只隔 6px，不会各自把空白平分、让第一颗看起来像居中。
- 提交行：悬停缩进条上提亮，按下更深，选中时左侧出现 2px 绿条，Enter 打开详情；行尾的更多按钮贴着这一行展开菜单，里面有回退这次提交、拣选到当前分支、撤销这次提交、复制提交 ID，合并提交不能拣选、只有最新一条能撤销，菜单里直接写清原因。
- 撤销提交的确认卡：贴着那条提交出现，说明撤销后改动会回到「已加入这次提交」、提交说明会填回输入框、如果已经推送过则会落后一个提交；确认后列表与顶部同步计数一起变化。
- 提交详情：返回按钮悬停变蓝底，返回后恢复选中行与列表滚动位置。
- 搜索工具条：整条输入区用 focus-within 高亮；「只看合并」是带边框的胶囊开关，不是一段看起来不可点的文字。
- 拉取确认气泡：贴在被点的「拉取」按钮下方，没有整屏遮罩，也不锁滚动；只列前六个文件，超过时说明还有几个没有列出，取消与继续拉取是气泡里的两颗按钮。它是一层浮起来的小卡片，不是对话框。
- 工作树：顶部说明条是红字加关闭按钮；标题行右侧是「全部」与「需要处理」两个筛选胶囊；行内展开箭头点开详情，详情里有完整路径、分支、当前提交、状态原因，以及「解除锁定」「清理记录」「移除工作树」三颗动作按钮，全部在面板里直接执行，确认卡也内联在展开区里。
- 分支浮层：顶部身份行里的分支名是按钮，点开贴着这个按钮弹出分支列表，不再盖住整个面板。列表里标出当前分支与每个分支的领先/落后，点一行进详情；详情里有切换到此分支、合并到当前分支、变基到这里、重命名、删除分支五颗按钮，删除、有改动时切换、变基都先出内联确认卡。分支浮层点外面或按 Esc 收起，收起后原视图与滚动位置还在。
- 收起的改动：第四个页签，列出每条收起记录的编号、说明、时间和包含的文件，行内三颗按钮「放回工作区」「放回并删掉记录」「丢弃记录」；两种放回都会把改动恢复出来，其中「放回并删掉记录」同时把这条记录从清单里移除，丢弃记录要贴行确认；每条记录下面直接列文件路径，不用再点开一层。改动视图提交区右上角有「收起改动」，把已加入与未加入的文件一起收进清单，提交说明留空时用 `WIP on <分支名>`。页签本身只写名字与条数，悬停会补一句它装的是什么：「收起的改动：0 条 · 把暂时不想提交的改动打包收起来，之后能放回工作区」。
- 交给 AI 入口：身份行右侧的四角星是通用入口，另外在改动页提交区提示行右端、工作树页底部、分支浮层底部各有一个就地入口，文案写当前这一页的难处，不写「智能助手」。点开贴着入口出现浮层，不再盖住整个面板。
- 交给 AI 浮层：Esc、右上角关闭按钮、点外面三种关法；正文是一段可选中的纯文本，可以先用键盘选中再复制；点「复制这段说明」把整段写进剪贴板，底部换成一行绿色「已复制 N 个字符」。浮层打开时不会锁滚动。
- 窄宽度下入口自动降级：460 以下改动页提交区那条就地入口隐藏，避免和文件列表抢高度；300 宽时身份行收起「复制仓库路径」，交给 AI、命令面板与管理三颗仍在。300 宽时文件行只留文件名，更多菜单与确认卡自动收窄，收起记录行改竖排。
- 只读信息不做悬停反馈，包括同步计数、状态标签与工作树行，避免看起来像按钮。
- 管理索引卡与二级页：整张卡可点，悬停抬升、按下位移；二级页左上角返回键回到上一页，Esc 也逐层退回（先关命令面板，再收危险核对，再收能力确认卡，最后回上一页），退回后原来的页签与滚动位置不变。
- 能力行：行首编号是只读小字，点「演示」才展开四段式确认卡；取消按钮拿默认焦点，Esc 只收卡片不动数据；执行后结果贴在该行下面，标签写「（原型模拟）」，不假装真的改了仓库。顶部动作行与底部清单用的是同一套卡和结果条，收起卡片后焦点回到刚才点的那颗按钮。
- 危险动作的整页核对：输入框不填或填错时执行按钮保持禁用，旁边常驻一句要敲的四个字是「确认清理」；点取消直接回到维护页。
- 命令面板：打开后输入框自动聚焦，列表随输入减少，回车打开第一条，Esc 或点遮罩关闭；选中能力后跳到对应页面并短暂高亮，顶部结果条写清落到了哪个页面。
- 二级页、整页流程与命令面板在 439 与 359 两档宽度下重新排布：对象行从两列改竖排，键值表与能力事实从两列改单列，确认输入框占满整行。

## 界面叫法与 git 原名的对照

原型里有两处 git 名字容易让人看不懂，所以界面换了一套更直白的说法。git 命令保持原名，只出现在能力清单的 `command` 列和文档里。

| 界面上 | git 里叫什么 | 为什么改 |
| --- | --- | --- |
| 加入 / 移出 / 已加入 / 未加入 / 全部加入 / 全部移出 | `git add` / `git restore --staged`，git 管这块叫暂存区 | 「暂存」很容易被读成「临时保存」，和 stage（把改动放进下一次提交）的意思正好相反 |
| 收起的改动 / 收起改动 / 收起记录 / 放回工作区 / 放回并删掉记录 / 丢弃记录 | `git stash` / `git stash push` / `git stash apply` / `git stash pop` / `git stash drop` | 「贮藏」是 stash 的直译，和「暂存」只差一个字；两个词并排出现时，读者很难分清哪个是哪个 |

- 这套叫法只写在界面上：能力清单 `command` 列仍是 `git add`、`git stash`，方便对照命令。
- 真实插件还没换成这套词；这次只改原型，等维护者点头后由规格与实施票决定是否跟进。

## 交给 AI

这个页面里最难的地方不是点按钮，是不知道下一步该做什么。所以几个视图各留了一个入口，把此刻的完整状态写成一段给 AI 的说明，人只要复制过去就能接着谈：

- 说明分成九节：仓库与分支、工作区现状（逐个文件写清新增与删除行数）、其他工作树、本地分支、最近五条提交、我看到的现象、我想达到的结果、请你做什么、补充。
- 只自动填当前仓库已知的必要信息：仓库根与当前工作树路径、分支与上游、超前与落后、每个文件的新增删除行数、其他工作树、本地分支与是否已合并、最近五条提交、界面停在哪一页。
- 「我看到的现象」「我想做什么」「补充」三节留空由人填写：现象一节只留一句「界面停在：…」，想做与补充只给括号提示和方向示例，不替读者编目标。
- 「请你」一节写了三条边界：先复述并指出可能的误解，再分步骤写清每一步改什么、怎么验证，涉及丢弃改动、覆盖历史或强推时先停下来问。
- 说明里带完整路径与文件清单，粘贴前可以删掉不想外发的部分。原型只负责复制，不会真的打开新对话；接进真实页面后，这一步应该直接进入新对话并带上这段说明，不需要人再复制。
- 入口文案按页面写：改动页问「拿不准怎么拆提交？」，工作树页问「不想自己排查？」，分支页问「分支关系太乱？」；身份行右侧的四角星是不带问题句的通用入口；没有异常时工作树页换成「没有需要处理的工作树，让 AI 解释一下」。

## 和真实代码的关系

数据结构和判定规则对齐仓库里的真实模块，没有另起一套模型：

- 首屏数据、同步状态、动作是否可用的判定，来自 `src/shared/version-control/src/` 里的 `assemble()`、`judge()`、`describeTime()`、`splitPath()` 等纯函数；原型只是把采集好的输入喂进去，所以「按钮为什么禁用」的结论和线上一致。
- 真实页面入口是 `src/client/views/VersionControlTab.ts`，视图模块在 `src/client/views/versionControl/`，负责渲染、折叠、差异、写操作和文案。
- 宿主侧读写在 `src/host/versionControl.ts`、`versionControlWrite.ts`、`versionControlBasis.ts`、`versionControlCheck.ts`、`versionControlFiles.ts`。

原型没有直接引用客户端 DOM 模块，也没有把宿主代码打进浏览器，只复用共享核心的纯函数和类型。这样原型能跑在 `file://` 下，也避免和线上页面的渲染细节纠缠。

162 条能力的清单来自 `research/1588-git-full-capability-surface.md`（逐条给出命令、级别、前置状态与面板里怎么表达），落点和差距来自 `research/1589-capability-gap-map.md`；原型按这两份笔记把每条能力放到具体页面，入口与结果位置都写在能力行里，不靠记忆。

## 方案要点（与旧页面的差别）

- 顶部信息收成一条同步带：身份一行（右边四颗全局入口固定不换行）、同步计数一行、动作一行，禁用与警告原因只在有原因时出现；工作树完整路径不再单独占一行，收进仓库名的悬停提示与复制按钮里。「读取于」和「远端 origin」是两个带标签的事实，读者一眼看出这个时间是跟哪个远端比的。
- 二级页是整页替换，不是浮在页签上面的浮层：打开时同步带只留身份行、页签整行收起，页面紧接齿轮下方铺开；返回键并进标题行，退出后视图、筛选与滚动位置原样复原。这样从齿轮点进去的页面不会被页签和路径推远。
- 四个页签（改动、提交历史、工作树、收起的改动）共用一条骨架：先说结论，再给证据（列表或提交），动作和结果贴着证据出现。
- 改动页顶部用三张统计卡说清「几个文件冲突、几个已加入这次提交、几个未加入」，数字用红/绿/蓝区分，整张卡就是筛选开关；同一份读数的说法与提交历史、分支浮层保持一致。
- 同步读数写成并排的两个短读数「超前 2 · 落后 0」，不再用彩色胶囊；0 也照写出来，数字位置不会因为有没有落后而跳。
- 提交区底部压成一行：左边是禁用原因或提交提示，中间是「交给 AI」入口，右边是提交按钮；不再让两段文字各自占一行。
- 行内菜单按内容宽度收窄并贴行尾右对齐，菜单项文字也右对齐；确认卡里「涉及 N 个文件」用危险色，不可逆动作看一眼就知道分量。
- 界面文案不用分号断句：一句一个句号，长解释拆成两条并排的短句，读者不用自己断句。
- 页签上的数字带单位，并且每个视图只统计自己那件事：改动是文件数，提交历史是已加载条数，工作树是棵数，收起的改动是条数。
- 提交历史与提交详情用整页替换加明确的返回，不做左右两栏：面板最窄 300，两栏会把主题与路径截断。
- 合并提交先给「合并提交」这个结论，git 生成的英文原文降为一行小字保留下来。
- 工作树视图顶部固定当前工作树；被占用、目录不存在这类异常行排在最前，原因写在行内状态里；三颗动作直接在面板里执行，确认卡内联在展开区，不铺浮层。
- 分支不是第四个页签，也不是覆盖整页：顶部身份行的分支名点开一个贴着它的浮层，切换、合并、变基、重命名、删除都在这一层里完成，浮层不遮住下面正在看的列表；切完分支，顶部身份行立刻显示新名字。
- 面板里不出现「复制命令」：能被面板执行的动作就做成按钮，确认卡写明会动什么、不会动什么；确实超出面板边界的事情才用一句文案说明，不给半截命令让读者自己拼。
- 全部动作按 git 原语设计，按钮文案与判定不依赖 GitHub：领先/落后、合并、变基、拣选、删除、解除占用这些概念换到 GitLab 或其他远端仍然成立。
- 一屏最多一个实心主按钮；推送这类同步动作在确实领先时用描边高亮，不用第二颗实心按钮。
- 禁用按钮旁边常驻原因，并且禁用时不再教「按 Enter 提交」。
- 行数差里的 0 不显示：纯新增文件不写「−0」，读者不用去找那 0 行在哪。
- 小字与次要灰都按 4.5:1 对比度重算过，深色与浅色两套皮肤分别定值，不直接套设计稿里只适合大字的灰。
- 每个视图都留了「交给 AI」的出口：把仓库、分支、每个文件的改动、其他工作树、最近提交和当前视线打包成一段说明，而不是只给一句「帮我看看 git」。入口文案写的是这一页具体的难处，读者不用先理解术语才知道该不该点。
- 常驻页签只收高频四件事，低频但重要的能力收进管理索引：九张卡一屏列清 14 个域各自落在哪，不把 162 条能力全摊进一个长菜单里。
- 每条能力都要交代入口、打开什么、结果落在哪三件事；只读能力不给假按钮，面板之外的能力明写「没有操作入口」和原因。同一条能力只留一个主入口：页面上方已经按动作或真实数据列出的，不在底部清单里重复，避免点一处却要在另一处找变化。
- 危险动作按后果分两档：能撤销的用行内四段式确认卡，不可逆的多一道整页核对并要求手敲确认词，取消按钮永远拿默认焦点。
- 页面不绑定托管平台：远端、标签、子模块、钩子、配置这些能力按 git 原语命名，平台能力单独一页写明边界。

## 还没有实现、需要宿主新增读写能力的提案

下面这些是原型已经画出界面、但真实宿主还没有对应命令或读数的部分。原型用本地模拟与结果条替代，不假装已经存在：

- 修订上一条提交（`git commit --amend`）的预填与改写。
- 在页面里真正执行分支、工作树与收起的改动的写操作：原型只模拟状态变化，真实宿主目前只有把文件加入这次提交（`git add`）、提交、拉取、推送四类写命令，分支、工作树、收起改动、丢弃、回退、拣选、变基都需要新增读写能力。
- 远端管理的真实读写与冲突解决：原型里已经有远端页、冲突处置页与子模块页，按钮和结果都是本地模拟；宿主侧还缺增删远端、改上游、强推保护与冲突解决这一组命令。
- 全库搜索的宿主能力：原型里有全库搜索页，能搜提交、分支、标签与能力四类，宿主侧还没有对应的全库搜索命令；四个页签里的筛选仍只作用于已经加载的提交，输入框文案写明了范围。
- 仓库维护、迁移与导入、配置、钩子、诊断、平台能力六页背后的命令：这些页面把「该有什么」画出来了，宿主侧还缺对象计数、垃圾回收、打包、克隆归档、配置读写、钩子清单与手动运行这些能力；危险区与核对页只演示流程，不会真的执行。
- 能力清单里的 162 条并非全都可点：原型只给已经画出入口的能力可点路径，其余在行里写明「面板之外」或「只读诊断」，等宿主能力补齐后再补入口。
- 未跟踪文件的体积与类型（需要宿主额外读一次文件信息）。
- 真实的加载中、失败重试、已到最早三类提交列表状态，以及写操作的 120 秒票据流程。
- 真正打开新对话：原型里「交给 AI」只能把说明复制到剪贴板，接入宿主后需要会话入口，点一下直接带着这段说明进入新对话。

这些在原型里要么用文案说明边界，要么用本地模拟的结果条替代，不会假装已经存在。
