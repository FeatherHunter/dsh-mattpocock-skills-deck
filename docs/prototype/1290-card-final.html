定稿卡（甲）＋ 主体文本的四种设计

这一版按你说的改了两处：左侧对齐——地图面板和技能链面板左边框都从 x=12 起，两块内容的起笔也在同一条线（x=26：地图里「需求」胶囊的左边、技能链里第一个节点的左边）；状态句用色——「目标大而模糊 / 目标明确清晰」跟「探索地图 / 实施地图」同色（紫 / 蓝），不再是白字。

主体文本这一块，职责已经定下来：回答「点下去会发生什么、最后给我什么」（做法 + 产物）。 「心里话」那一路跟状态句重复（探索那张的「拿不准」就是「大而模糊」的口语版）， 「开场白预告」把会话的第一句话写死在卡上、以后改技能链就要改文案， 「处境 + 后果」两句要占满右栏、卡要长到 250 以上，还把「不用点进去看」的理由直接送给了用户。 下面「庚」段是这一路的三组候选文案，都按真实尺寸排在卡里。

另外三个问题的答案也在这儿：承接关系不写进卡里（卡底的技能链已经画出来了：探索那条链的末尾同样是 /to-spec、/to-tickets）； 眉标保持同色淡一档（两张卡名只差「探索 / 实施」两个字，眉标上色才能一眼分清是哪一类）； 当前这一稿修了一处排版硬伤——原来按固定字数硬切，会把「给你」拆到两行，现在按中文避头尾规则分行。

戊主体文本的四种设计

卡片里现在有三个文字位置，各答一个问题：眉标答「这是哪一类」，状态句答「我处在什么状态」。剩下第三个问题——主体文本该答什么，才是要定的事。四种设计的差别就在这里。

己四种设计的对照

我的倾向是「做法 + 产物」：状态句已经占了「处境」这个位置，主体文本再写一遍心里话就是重复；而用户点下去之前真正想知道的是「点下去会发生什么、最后给我什么」。但这句话必须落在两行以内，而且要短。

庚「做法 + 产物」这一路的三组候选下面每组都按真实尺寸排在卡里

三组都守同一条规矩：不撞卡名（探索那张不出现「实施地图」四个字，实施那张不出现「探索」）、 不重复状态句（不出现「模糊 / 明确 / 拿不准 / 没想透」这类词）、 开头就能一眼分辨（分头 vs 对着文档）、两行以内（一行最多 12 个字）。

辛四个未决问题 + 一个事实问题的答案

四个未决问题都有答案了；最后一件本来不是设计问题、是事实问题，也查清了：探索那条会话会一路走到 /to-tickets （父规格 #1290 §F：探索地图「完成」态的内部流程是「核对路清 → 提醒 /to-spec → 提醒 /to-tickets」，两个技能都由人手动跑）。 所以文案不能靠「只说一份需求」来暗示拿不到票——甲组正文只承诺「把没定的问清楚」，既不承诺也不排除后面的规格与票； 承接关系仍旧交给卡底的技能链去说。
