## 0. 维护者已经给过的两次裁决（先读这里，别重走弯路）

**第一轮**（十个方向 `474-map-detail-ten-directions.html`）：
「只有 D7 探案板视觉效果比较好也有创意，但是也有一些 BUG。此外其他 9 个方案都不好。」
→ 星空 / 战棋迷雾 / 等高线 / 连载手稿 / 任务控制台 / 地铁线路图 / 折页地图 / 蓝图 / 梯田花园 **全部否定**。
→ 读出来的取向：**维护者要的是「手上的东西」—— 真实材质、可以钉、可以撕、可以封的物件感。抽象图表一律不接受。**

**第二轮**（三条探案板优化线 P1/P2/P3 + 三条天马行空线 W1/W2/W3）：
「P1 可以打 70 分，其他的都是 0 分。」
→ 只有 `474-P1-evidence-wall.html`（精修证据墙）及格，P2 时间线主轴、P3 卷宗柜、W1 矿井剖面、W2 航班信息板、W3 量子概率云 **全部 0 分**。

**第二轮附带的硬裁决，是这一轮最重要的约束：**

> 「原型不一定要有明确的层级关系，比如第一层第二层直到终点。这种不是我喜欢的想法。」

也就是说：**「层」这个派生量不许当页面的骨架。**
数据里当然还是能算出层（`blockedBy` 的最长路径深度），但它是给程序看的，不是给眼睛看的。

**明令禁止的骨架用法（做了就 0 分）：**

- 按层分行 / 按层分列（P1 现在就是按层分行，这是它没拿满分的头号原因）
- 按层分抽屉、分页签、分章节
- 把层当 X 轴或 Y 轴（时间线主轴、跑道、走廊）
- 票上挂「第 3 层」这种徽章
- 阶梯感、漏斗感、由浅入深的纵深（矿井剖面就是死在这里）
- 等高线、地铁线路图、仪表盘这类「把关系画成图」的做法

**允许的、也是这一轮要探索的：**

- **关系不做骨架，只做线索**：谁挡着谁，用绳、用批注、用交叉索引表达，而且**平时可以收着，需要时才显形**（悬停、拿起、聚焦、拉开绳结）。
- **位置由「档案状态」或「人的手」决定**，不由层决定。
- **目的地永远清晰**这一条不能动（#474 的第一条理念）。

**维护者在这一轮点名的三个方向（他原话）**：

> 「比如可以考虑那种无限画布的背景板的感觉、又或者探案板上的卡片可以拖拽、卡片之间可以通过拖拽能看到其上下关系等等，要发挥想象力」

1. **无限画布的背景板** —— 板子可以拖、可以缩放，无穷大，不是一屏塞满。
2. **卡片可以拖拽** —— 用鼠标把卡挪来挪去，位置留在那儿。
3. **拖拽时能看见它的上下关系** —— 拿起一张卡，能立刻看见「谁挡着它、它挡着谁」。这是把关系从布局里搬到**动作**里的关键，务必想办法做出来。

**维护者还点了两条要求**：

> 「我希望你提供更多档案袋、办案的那种感觉的原型。」
> 「不仅里面上需要新颖，UI 技术上也要很高级。」

即：**概念要新，手上功夫也要硬**。光换一套皮肤不算数，交互与渲染技术本身要够高级（第 6 节给了技术菜单）。

## 1. 这是什么产品

`dsh-mattpocock-skills-deck` 是一个装在「DeepSeek Harness」桌面应用里的插件。它在应用**右侧边栏**里画一块面板（宽 360–810 像素，由用户拖），
把仓库里的 issue 当成「票」展示。面板的入口是状态栏上的一颗胶囊，用户点开它、进到「地图详情页」。

**「地图」是什么**：仓库里有一类 issue 打了 `wayfinder:map` 标签，它是一张「导航图」——它有一个**目的地**（写在正文的 `## Destination` 一节里），
下面挂着一批子票（子 issue）。子票之间有阻塞关系（`blockedBy`）：A 没关掉，B 就动不了。

**这一页要回答四个问题**：终点在哪 / 我现在能做什么 / 哪些路还没走过 / 走过的路留下了什么痕迹。

**这一页的硬约束（真机实测定的）**：点开面板到看见内容 **≤ 300 毫秒**。因此：
**不许引入任何第三方库、不许联网、不许用 CDN。** 一个 HTML 文件，双击就能打开，全部代码自己写。

## 2. 设计理念（来自 issue #474，维护者原话）

> 「**目的地清晰而模糊**」：目的地是清晰的（比如「去泰国旅游」，到泰国这件事明确），通往它的路是模糊的（怎么去、哪条通哪条不通，全是待探索）。
> 一张诚实的地图必须同时呈现这两样：**看得见的终点，和诚实的未知**。否则用户会误以为「都规划好了」，推进全靠脑补。

五条必须守住的语义：

1. **终点永远清晰**：不管雾怎么盖，目的地始终明亮可见。
2. **未知必须诚实**：没走过、走不通、还没想过的地方要看得出是「不知道」，不能伪装成待办。
3. **走亮留痕**：走过的路留下看得见的痕迹，回头看就是「我认真探索过的领域」。
4. **雾本身是信息**：想过但没走通的分支继续盖着，不为了「全亮」去走没意义的路。
5. **不许只靠颜色区分状态**（色弱用户）：形状、纹理、文字、图标、印章至少再占一样。

## 3. 票的四个状态（全项目统一，不许改语义）

| 状态 | 判定 | 含义 |
|---|---|---|
| **走亮** | `state === 'CLOSED'` | 已经走完的路 |
| **照亮中** | 开着，且有 `claimedBy` | 正在推进的那一张，周围是「视野」 |
| **现在能做** | 开着，没人认领，且它的阻塞者全都关了 | 现在就能开工的下一站 |
| **雾里** | 开着，且它至少有一个阻塞者还开着 | 路画出来了，但通不通不知道 |

**注意**：上表里没有提到「层」。判定某一票是不是「雾里」，只需要看**它自己的前置有没有关掉**，不需要知道它在第几层。
这就是这一轮能做「去掉层骨架」的根据：四个状态全都是**局部**判断出来的。

## 6. 六个人分别做什么

六个人都在**同一个世界：办案与档案**。六种不同的实物载体、六种不同的高级交互。**不要互相抄。**

### C1 · 无限画布探案板（软木板 ＋ 拖拽提链）

**世界**：一块**无穷大**的软木板。板子本身可以拖着走、可以缩放，卡片钉在上面，红绳在卡之间连着。
不是一屏塞满，而是「板上还有地方，还没查完」。

**状态映射**：
- 走亮 = 已经办结的档案卡，盖了红章、卡角有折痕，被红绳连进主线
- 照亮中 = 正在办的那一张：台灯/热区照亮它，卡是**拿起来**的（浮得更高、影子更远）
- 现在能做 = 卡上贴了一张绿色的便利贴「可以动手了」
- 雾里 = **还没拆封的证物袋**（半透明塑料袋 + 封口条 + 里面看不清的纸），点一下才有反馈

**必须做到的三件事**（维护者点名的）：

1. **无限画布**：空白处按住可以拖动板子，滚轮以光标为中心缩放（0.5×–2.5×），拖到边界会回弹，右下角有小地图（mini-map）显示当前视野在哪。
2. **卡片可拖拽**：`pointerdown` + `setPointerCapture` 按住卡片拖，松手带一点惯性然后弹回稳定；位置存进 `localStorage`，刷新还在。
3. **拖拽时看见上下关系**：**拿起一张卡的那一刻，它的关系要立刻显形**——
   谁挡着它（上游）：这些卡的绳被绷直、卡被「拽」向被拿起的卡一点；
   它挡着谁（下游）：这些卡整条链一起亮起/抖一下，绳上浮出箭头。
   松手后关系重新收起来，回到安静状态。

**高级技术（至少用上 3 条）**：滚动/缩放的相机变换（`translate3d` + `scale`，`will-change`）、
rAF 惯性物理（速度 + 阻尼）、视口裁剪（屏幕外的卡不画）、`ResizeObserver`、SVG 层的正交布线（红绳不许穿过卡片）、
`content-visibility`、`touch-action: none`。

**诚实点**：雾不是一团模糊，而是**一个封着的袋子**——你能看出「这里有个东西，但还没拆」。

### C2 · 卷宗夹（打开一份刑事案卷）

**世界**：整页就是**一份摊开的案卷**（牛皮纸夹子）。封皮上有案号（＝地图号 #604）、案由（＝目的地标题）。
里面夹着：物证袋、现场照片、装订的纸页、批注条、回形针、封条。

**状态映射**：
- 走亮 = **已归档的卷页**：盖了「已结」的红章，有手写结论（用真实决策文字）
- 照亮中 = **正在批注的那一页**：压着一支笔、有荧光笔痕迹、页脚有「现任经办人」
- 现在能做 = 夹着一张绿色便签「可以动手」，被回形针别着
- 雾里 = **封着的证物袋**：透明袋 + 封口胶条 + 上面用记号笔写着「待查」。点一下可以拆封（有撕开的动效），拆开后才看见里面那张票的内容

**必须做到**：**卷宗是能打开的**——一个信封翻盖（3D 翻转，`perspective` + `rotateX`）打开时露出里面的东西；
标题栏（＝案由）**永远在视野里**（可以钉在顶部、可以是文件夹的书脊）。

**高级技术（至少用上 3 条）**：内联 SVG 滤镜做真纸纹/牛皮纸纤维（`feTurbulence` + `feColorMatrix`，`filter: url(#paper)`，零图片资源）；
`@property` 注册自定义属性来做**盖章动画**（章先是斜着、半透明，猛地按下去、震一下、留下墨点的溢边）；
`mix-blend-mode: multiply` 做碳素复写与墨迹；
`clip-path` + `polygon()` 做撕口锯齿；`backdrop-filter` 做证物袋的塑料光泽。

**诚实点**：封着的袋子**必须能看出它被谁压着**（袋子边角露出别的卷页/写着「等 704 结」的便签），
但**不能把「第几层」写出来**。

### C3 · 案情桌面（斜俯视的一张办公桌 ＋ 台灯）

**世界**：一张俯视的办公桌（深色木纹/毛毡垫）。桌上摊着案情板、散着照片、压着卷页，**一盏台灯**照着一小块地方。
**光就是「已知」**：灯照着的地方看得清，灯没照到的地方沉在暗里（这就是雾，而且**是物理上成立的雾**）。

**状态映射**：
- 走亮 = 已经归档、叠好、压平的纸（有「已结」章）
- 照亮中 = **正被灯照着的那一张**（灯的光圈天然地落在它身上）
- 现在能做 = 露出一角、上面压着一张绿色便签
- 雾里 = 沉在暗处、只看得见轮廓的纸堆 / 封着的袋子

**必须做到**：**灯随光标移动**（或者用方向键/拖拽移动灯座），光圈用 `mask-image: radial-gradient(...)` 跟着指针走，
并且移动时**有阻尼**（不是硬跟手，灯罩有重量）。光照到哪，哪里的东西就显出细节（细节程度可以随距离变化）。
**目的地永远是桌上最亮的那一点**（可以是一张单独打亮的照片、桌角立着的名牌），跟灯在哪无关。

**高级技术（至少用上 3 条）**：跟随指针的 `mask-image` 光圈 + rAF 插值；`mix-blend-mode: soft-light` 做灯罩的暖光锥；
多重 `drop-shadow` 模拟纸张的层叠抬升（拿起纸时影子变大变远）；SVG `feDropShadow`/`feTurbulence` 做桌面质感；
`pointerType === 'pen'` 时用 `event.pressure` 改变手写批注的粗细。

**诚实点**：暗处的东西**不许点不动**（#474 明确要求「雾不挡点按」）——点暗处的纸堆，它能被翻出来看。

### C4 · 案情报告（打字机打的卷宗 ＋ 涂黑解密）

**世界**：一份**打字机打出来的调查报告**，纸上有打孔、有装订线、有胶带粘的附件、有页边批注。
每一张票＝报告里的一段条目（有编号 605 / 607 这种，就是票号）。

**状态映射**：
- 走亮 = **已经打完并盖章的条目**：墨迹实、下面有「结论：……」一行（用真实决策文字）
- 照亮中 = **正在打的那一条**：光标在闪，后面还有半行没打完
- 现在能做 = 条目是空的虚线框，页边批注写着「可以动手」
- 雾里 = **涂黑的段落**：整段被黑条盖住（`▮▮▮▮▮`），你只知道这里有一段，不知道写的是什么；点一下可以「解密」，黑条滑开露出真内容

**必须做到**：**打字机效果**——条目文字逐字出现（用 CSS 自定义属性 `--i` 配 `animation-delay: calc(var(--i) * 28ms)`，
或者 Web Animations API），而且**只在第一次出现时打一次**，不要循环（循环会烦人）。
**上下关系怎么办**（因为不许画层）：用**页边批注**「参见 704」＋一条页边竖线，
鼠标悬停某条时，它引用的和被引用的条目**在页边同时亮起来**（像校对时用的红线）。

**高级技术（至少用上 3 条）**：逐字打字（`--i` + `animation-delay`，或者 `Element.animate` stagger）；
`mix-blend-mode: multiply` 做碳素复写第二张纸；`clip-path` 做胶带/纸张毛边；
`animation-timeline: view()`（滚动驱动，Chrome 115+）做条目进视野时淡入（**必须有降级：不支持时直接显示**）；
`text-wrap: pretty` / `font-variant-numeric`；`@container` 查询在 400 宽时把页边批注收进条目里。

**诚实点**：涂黑是**最诚实的雾**——它不是「没有」，是「有，但还没解密」。这一条要做得让人一眼看懂。

### C5 · 暗房（照片正在显影）

**世界**：一间**暗房**。红光（safelight）、显影盘、晾照片的绳子和木夹子。
每一张票＝一张相纸（或者一个胶卷盒）。

**状态映射**：
- 走亮 = **已经显影定影的照片**：图像清晰、颜色正常，用木夹子晾在绳上
- 照亮中 = **正在显影盘里晃的那张**：画面从空白慢慢浮出（动效），而且微微摇晃
- 现在能做 = 显影盘旁边**空着的位置**，摆着一张还没放进去的相纸（旁边压着一张绿色便签）
- 雾里 = **还没曝光的相纸**：全黑（或者在红色安全灯下看不清），上面只有用记号笔写的一行小字；点一下才有反应

**必须做到**：**显影动效**——点一张未曝光的相纸放进显影盘，画面**从空白/全黑逐渐显出内容**
（可以用 `mask-image` + 模糊/对比度动画，或者 SVG 滤镜渐变，不要用真图片，用文字排版成「照片」的样子也行）。
**目的地＝绳子上最亮的那张照片**（或者墙上唯一亮着的一张），永远看得见，不参与显影。

**高级技术（至少用上 3 条）**：`filter: brightness()/contrast()/blur()` 动画做显影；
`mix-blend-mode: screen` 做暗房红光；绳子上的照片用 rAF 做**钟摆摆动**（`Math.sin(t)` 带阻尼），
拖动一张时旁边的照片跟着晃（物理联动）；`clip-path` 做照片的齿孔边；SVG `feTurbulence` 做颗粒感。

**诚实点**：未曝光的相纸**看起来就该是「什么都还不知道」**，但**不能看起来像废纸**——它是有编号的、被认真放好的。

### C6 · 索引卡柜（档案室里的卡片抽屉）

**世界**：图书馆/档案室那种**索引卡柜**（card catalog）。每张票＝一张索引卡，插在抽屉里，
卡片上打字写着票号与标题，下面有打勾的小格。

**状态映射**：
- 走亮 = **卡已经填满**：方格上打了勾、卡角有归档的红戳、被移到抽屉后半段（或者夹了「已结」的书签）
- 照亮中 = **有一张卡被抽出来半截**：露在外面，卡上压着经办人的名字
- 现在能做 = 卡上贴着一张绿色小旗「可以动手」
- 雾里 = **一张空白的索引卡**：只有票号和标题，格子空着，纸偏白；你只知道「这里有一张卡要写」

**必须做到**：**抽卡与瀑布**——这是索引卡柜最好看的地方：抽屉里的卡是**互相叠着的**，只露出卡的上沿（写着票号），
鼠标划过时**上面的卡被推开、下面的卡露出来**（真实的扇形/瀑布效果，用 3D transform 或者层叠偏移实现）；
点住一张卡往上一抽，它能被**整个抽出来**看详情，抽出来的那格后面的卡会**自动前倾补位**。
**抽出来的那一刻，能看见它的上下关系**：卡背面（或者卡的侧面）印着「等谁 / 挡住谁」的交叉索引行。

**高级技术（至少用上 3 条）**：卡片瀑布用 `transform: translateY() rotateX()` 逐张错开（`--i` 常数），
配合 `transition` 做真实的手感；抽出的卡用 Web Animations API 或 `Element.animate` 做**离手飞起再落下**；
`perspective` + `transform-style: preserve-3d`；卡纸纹理用内联 SVG 滤镜；`@container` 查询适配 400/810；
键盘可达：`↑/↓` 在卡之间移动焦点，`Enter` 抽卡。

**诚实点**：空白卡**不能看起来像「加载失败」**——它是「还没写」，不是「没有」。

## 7. 高级技术菜单（这一轮必须有真功夫，挑着用）

以下是**手写、离线、单文件**就能做到的高水平做法，选你用得上的。**不许为了用技术而用技术**：
每一条技术都必须让「办案的感觉」更强，否则不许加。也不许因此掉进图形图表的坑里（见第 0 节禁列）。

1. **无限画布相机**：pointer 拖动平移 + 滚轮以光标为锚点缩放（`scale` 变换要按光标位置反推位移），rAF 做惯性，视觉上无穷。
2. **拖拽物理**：`setPointerCapture` + 速度采样 + 弹簧阻尼（`v += (t - x) * k * dt; v *= 阻尼^dt`），松手自然收住。
3. **关系显形**：拿起一张卡时，沿 `blockedBy` 向上、沿反向索引向下做遍历，用 `--d` 自定义属性做错峰点亮（`transition-delay: calc(var(--d) * 40ms)`）。
4. **红绳布线**：正交折线（L 型/绕行），**不许穿过卡片矩形**；SVG `<path>` 用二次曲线做圆角；箭头指向被阻挡的一方。
5. **Canvas 挖雾**：整块遮罩 + `globalCompositeOperation = 'destination-out'` + 径向渐变，按 `devicePixelRatio` 缩放，只在需要时重绘。
6. **内联 SVG 滤镜做真材质**：`feTurbulence` 生成软木/牛皮纸/毛毡/颗粒纹理，`feColorMatrix` 上色，`feDropShadow` 做纸张抬起——
   零图片、零网络、GPU 缓存，比贴图更高明。
7. **`@property` 动画**：注册 `<angle>` / `<number>` 类型的自定义属性，让「盖章角度」「雾的浓度」「灯的亮度」这类东西可插值、可过渡。
8. **`mask-image` 跟随指针**：台灯光圈、放大镜、手电筒；用 rAF 做阻尼跟随，别硬跟手。
9. **`mix-blend-mode` / `backdrop-filter`**：`multiply` 做碳素复写与墨水；`screen` 做暗房红光；`backdrop-filter: blur()` 做塑料证物袋的光泽。
10. **滚动驱动动画**：`animation-timeline: view()` 让条目/卡片进入视野时淡入淡出（**必须写降级**，浏览器不支持时直接可见）。
11. **`@container` 查询**：面板被拖到 400 时换布局（真的响应容器宽度，不是响应窗口）。
12. **Web Animations API**：`element.animate()` 做可打断的过渡，比 CSS 类切换更适合拖拽松手这种场景。
13. **`content-visibility: auto` + `contain-intrinsic-size`**：20 张以上卡片时保性能。
14. **`ResizeObserver` / `IntersectionObserver`**：容器变宽变窄、卡片进出视野时精准响应。
15. **指针压力**：`pointerType === 'pen'` 时用 `event.pressure`（0–1）决定笔迹粗细，鼠标时取固定值。
16. **程序化生成图形**：条形码、指纹、印章、齿孔——都用 CSS/SVG 现算，不许贴图。

**性能红线**：rAF 里不许反复读 `offsetWidth`/`getBoundingClientRect()` 造成强制同步布局；批量改样式用 `transform`/`opacity`；
20 张卡时拖拽要跟得上手。

## 8. 交付契约（六个人完全一样）

1. **一个文件**：`docs/prototype/474-<你的编号>-<英文短名>.html`（编号如 `C1`，短名用英文小写，如 `infinite-board`）。
   单文件自包含：不许 `<script src>`、不许 `<link href>`、不许联网、不装任何包、不用定时器轮询。
2. **双击即开**：用 Chrome / Edge 打开就完整可用；所有数据内联在文件里。
3. **自适应**：宽度 400 与 810 都要能用（面板会被用户拖窄拖宽）；`?w=400` 与 `?w=810` 都要正确渲染。
4. **URL 参数**：至少支持 `?w=`（宽度）、`?s=active|empty|big`（状态）、`?bar=0`（隐藏底部控制条，用于截图）。
5. **键盘可达**：Tab 能走遍所有可交互元素，Enter/Space 等同于点击；`←` `→` 不被拦截（除非焦点在输入框）。
6. **诚实渲染**：数据缺字段时按空渲染，不许抛错；`tickets: []` 时给「一个还没开始的案子」的状态，不是白屏。
7. **自检**：写完后用 node + playwright 跑一次自检（脚本写法可参考 `docs/prototype/../.tmp-474-live/shot10.cjs`），确认：
   - 页面加载无 JS 报错（`pageerror` / `console.error` 都为空）；
   - `?w=400` 与 `?w=810` 下 `document.body` 无横向滚动（`scrollWidth <= clientWidth + 2`）；
   - 四个状态的票**都出现在 DOM 里**（用你自己给的 class 名或 data 属性断言，例如 4 张票对应 4 个节点）；
   - 三份样本（active / empty / big）都要能正常渲染，一份都不能抛错。
8. **产出截图**：810 宽与 400 宽各截一张 PNG（大样本 `big` 也截一张 810 的），放到 `docs/prototype/474-shots/` 下，
   文件名 `c1-<短名>-810.png` / `c1-<短名>-400.png` / `c1-<短名>-big810.png`（编号换成你自己的）。
9. **自己动手验一遍你点名的交互**：你承诺的拖拽/平移/抽卡/显影，必须真的用 playwright 做一次指针操作验证它生效（例如拖完 `getBoundingClientRect()` 变了），
   把原始输出贴在回报里。**没验过的交互不许写进回报。**

## 9. 不要做的事

- 不要改别人的文件、不要动 `src/` 与 `host.js`（那是插件本体，本次只做原型）。
- 不要 `git add` / `git commit`。
- 不要安装 npm 包（`playwright` 与 `node` 已装好，直接用）。
- 不要为了好看牺牲那五条语义（尤其：终点必须永远可见；雾不许伪装成待办；状态不许只靠颜色）。
- **不要用层当骨架。**（第 0 节的禁列，逐条自查。）
- 不要写只有自己看得懂的简称；页面上的中文要让人第一眼读懂。

## 10. 完成后回报什么

用一段话回报：① 文件路径；② 你的概念一句话；③ 三个最关键的设计决定；④ 你自己知道的最弱的一处；
⑤ 自检脚本的原始输出（含指针操作验证）。**不许把没做的事说成做了。**
