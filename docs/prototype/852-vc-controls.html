一 · 面板顶部动作

读数据与推拉，是这一页唯一常驻的一排按钮
重读一次 · 只读，不改仓库
vc.reload
旁边常跟着一行 读到于 …（vc.readAt）：{when} 取刚刚 / {n} 分钟前 / {n} 小时前 / {n} 天前。
拉取 · 面板只做快进
vc.action.pull
禁用时悬停说明来自 vc.block.*：工作区有未提交的改动 / 有文件卡在冲突里 / 裸仓库 / 游离头 / 仓库里还有没做完的操作。
推送 · 按钮文案随上游情形换
vc.action.push · vc.action.pushSetUpstream · vc.action.pushRecreate
同一个位置，三种情形：已有上游 → 推送；这个分支还没设过上游 → 设为上游并推送；本地记着的上游在远端已经没了 → 重建上游并推送。

二 · 暂存与提交

未提交改动区里的两个动作
单行暂存
vc.action.stage
只出现在未暂存那一段的每一行右边；冲突行不出现（那行给的是 vc.row.conflictTerminal：冲突：去侧栏终端处理）。
全部暂存
vc.action.stageAll · vc.block.nothingToStage
没有可暂存的东西时禁用，悬停说明是 没有可暂存的东西。
提交（按钮上带文件数）
vc.action.commit · vc.block.nothingStaged
暂存区空时禁用，说明是 暂存区是空的，没有可提交的内容；卡在冲突里时是 有文件卡在冲突里，先处理完再继续。

三 · 提交说明输入框

面板里唯一的输入
正常 / 已填 / 禁用
vc.commitArea.placeholder · vc.commitArea.hint
下面那行常驻说明：提交的是暂存区里的内容；没有暂存的文件不会跟着走。
点了提交但没写说明
vc.commitArea.needMessage
! 先写一句提交说明

四 · 确认块（写在面板里，不是弹窗）

先预检、再让你点头，然后才动仓库
拉取确认
vc.confirm.pullTitle · vc.confirm.pullBody · vc.confirm.ttl · vc.confirm.cancel
要拉取这个分支
只做快进：把远端的新提交接到本地。需要合并时面板会停下来，指你去侧栏终端。
git pull --ff-only origin main
这次确认 120 秒内有效；过期了重新看一眼再点。
推送确认 · 已有上游
vc.confirm.pushTitle · vc.confirm.pushBody
要推送这些提交
推到 origin/main。
git push origin main:main
这次确认 120 秒内有效；过期了重新看一眼再点。
推送确认 · 第一次推送（要设上游）
vc.confirm.pushSetUpstreamTitle · vc.confirm.pushSetUpstreamBody
第一次推送：要把它设为上游
把本地 main 推到 origin/main，并把它设为上游。
git push --set-upstream origin main:main
这次确认 120 秒内有效；过期了重新看一眼再点。
推送确认 · 上游在远端已经没了（重建）
vc.confirm.pushRecreateTitle · vc.confirm.pushRecreateBody
原来那个上游已经不存在了
远端分支 origin/main 已经不在了（原来的上游已经不存在）：会把本地 main 推上去，并把它设为上游。
git push --set-upstream origin main:main
这次确认 120 秒内有效；过期了重新看一眼再点。
仓库有多个远端时：先让你挑一个
vc.pickRemote.title · vc.pickRemote.body
这个仓库有多个远端，选一个再推
面板不替你挑远端；选中之后会重新预检，确认框里会写清推到哪。

五 · 进行中 / 完成 / 失败 / 不确定

执行结果只有这四种说法
正在执行
vc.op.running
执行期间按钮变灰不可再点；面板不自动重试，也不自动接着做。
做完了 · 各动作的回执
vc.op.doneStage · vc.op.doneCommit · vc.op.donePull · vc.op.donePush · vc.op.donePushSetUpstream · vc.op.donePushRecreate · vc.op.modeFastForward · vc.op.modeUpToDate
✓ 已暂存 2 个文件 ✓ 已经提交了
✓ 拉取完成 已经快进到远端最新 ✓ 推送完成
✓ 第一次推送完成，已经把它设为上游 ✓ 已重建上游：把本地 main 推到了 origin/main
拉取还有第二种回执：本来就是最新的（vc.op.modeUpToDate）。
没做成 / 结果不确定
vc.op.failed · vc.op.unknown
× 没做成 ? 结果不确定
「结果不确定」是刻意与「没做成」分开的一档：这一步可能已经发生，所以下面必须写清该先看什么。

六 · 失败面（15 类，每类都要有「接下来该怎么办」）

这一段是这一功能最容易写得像报错堆的地方：每条失败都只给两句 —— 出了什么事、你去哪儿处理
远端不认凭据
vc.writeErr.noCredential / .limit
× 远端不认这台机器上的凭据，需要重新登录 面板不替你保存或输入凭据：去侧栏终端跑一次 fetch 或 push，按提示登录，成功后回来点刷新。
权限或服务端规则
vc.writeErr.noPermission / .limit
× 远端拒绝了这个动作（权限或服务端规则拦下了） 面板改不了远端的规则：确认用的是哪个账号，要换账号请去侧栏终端。
远端规则（钩子或保护分支）
vc.writeErr.remoteRule / .limit
× 远端规则拦下了这次推送（钩子或保护规则） 上面那句是远端原话，按它处理；面板改不了远端的规则，也不用换账号。
本地与远端都动过
vc.writeErr.conflict / .limit
× 本地和远端都有新提交，直接拉会打架 面板不替你合并：去侧栏终端跑 git pull，处理完冲突再回来。
拉取不能快进
vc.writeErr.notFastForward / .limit
× 远端的新提交已经取回来了，但本地和它分开了，不能快进 面板只做快进：合并或变基去侧栏终端。
推送时远端有新提交
vc.writeErr.notFastForwardPush / .limit
× 远端有你本地还没有的提交，直接推会被拒 先在侧栏终端 fetch 或 pull 把远端的新提交取回来，再合并或变基。
网络断了或超时
vc.writeErr.network / .limit
× 网络断了或者超时了，这一步没做完 面板不自动重试：检查网络后再点一次。
确认过期 / 仓库变了
vc.writeErr.stale / .limit
× 这次确认已经过期，或者仓库在你确认之后又变了 面板不替你猜：重新看一眼当前状态，再点一次。
这一步现在做不成
vc.writeErr.notReady / .limit
× 这一步现在做不成，宿主把原因写在悬停提示里了 面板不替你改仓库：按悬停里那句做完再回来。
结果可能已经发生
vc.writeErr.moved / .limit
? 这一步的结果不确定：提交可能已经发生，先看提交历史再决定 面板不替你猜结果：看一眼提交历史，确认了再决定要不要再提交。
说不清原因
vc.writeErr.unknown / .limit · vc.fail.raw
× 这次失败面板说不清原因 原始说明：{msg}
上面那句是宿主的原话：按它处理；面板不自动重试。
动作被规则挡住（写之前就拦下）
vc.block.nothingToStage · nothingStaged · conflicts · dirtyTree · noUpstream · upstreamGone · detachedHead · midOperation · behindRemote · bareRepo · unknown
禁用原因没有可暂存的东西
禁用原因暂存区是空的，没有可提交的内容
禁用原因有文件卡在冲突里，先处理完再继续
禁用原因工作区有未提交的改动，先提交再拉取
禁用原因这个分支还没有上游
禁用原因这个分支的上游在远端已经不存在了
禁用原因现在不在任何分支上（游离头指针），这一步做不了
禁用原因仓库里还有没做完的操作，先处理完
禁用原因远端有你本地还没有的提交，先拉取再推送
禁用原因这是个裸仓库（没有工作树），这些操作都做不了
禁用原因这一步现在做不了
提交前的三条提醒（不拦，只提醒）
vc.warn.detachedHead · vc.warn.midOperation · vc.warn.basisUnknown
!现在不在任何分支上，提交会落在游离头指针上
!仓库里还有没做完的操作，提交前先确认
!不清楚本地记的远端信息有多旧，推送前先确认

七 · 文件行上的零件

字母徽章、正负行数、分段小标题
状态字母徽章（方形 · 按类型着色）
vc.change.added / deleted / modified / renamed / typechange / untracked · vc.row.conflict
A新增 M修改 D删除 R重命名 T类型改变 ?未跟踪 !冲突
徽章是给扫一眼用的，中文词照旧在行里（可读文本不能只剩字母）；判不出类型时给 这笔提交只回了路径与增删行数，判不出变化类型。
正负行数（右对齐 · 表格数字）

+45 −2 +8 −8 −120 untracked
悬停说明：行数是相对上一次提交的总数（vc.row.countsDual）；二进制文件没有逐行增删的数字（vc.row.binaryTip）。
分段小标题
vc.group.staged · vc.group.unstaged · vc.group.conflict

十 · 空态

三处「没有东西」，语气要不一样
没有未提交的改动
vc.changes.none
没有未提交的改动
没有别的工作树
vc.other.empty
没有别的工作树
还没有任何提交
vc.noCommits · vc.noCommitsTip
这个仓库还没有任何提交刚建好的仓库就是这样；做出第一次提交之后，这里就有历史了。

十一 · 加载中

三处读取，各有自己的说法
骨架行
vc.diff.loading · vc.commits.loading · vc.commit.loading
旁配一句人话：正在读改动… / 正在读更早的提交… / 正在读这笔提交改了什么…。骨架不假装有内容。

十二 · 读不到（14 种说法）

这一族只在「某一项读不到」时出现，每种都要说清是谁的问题、人该怎么办
不是 git 仓库
vc.fail.notRepo
×这个目录不在任何 git 仓库里。
没装 git
vc.fail.noGit
×找不到 git 程序：请确认装好了 git、并且它在 PATH 里，然后重启 DSH 再打开这个页签。
git 版本太旧
vc.fail.oldGit
×这台机器上的 git 版本太旧，这个页签需要新一点的版本。
宿主文件服务没结论
vc.fail.envFs
×读不到仓库的运行状态（宿主的文件服务没给出结论），这一步读不到就不给数；稍后再试。
git 没正常结束
vc.fail.exit
×git 没有正常结束：多半是别的程序正占着这个仓库，或者权限不够。等它结束再重试。
超时
vc.fail.timeout
×读这个仓库超时了：git 一直没有回音，等它忙完再重试。
输出形状不认识
vc.fail.parse
×读到的内容看不懂：这台 git 的输出形状和预期不一样。
起不了进程 / 中途断了 / 超过上限 / 没按约定回话 / 界面发错 / 说不出原因
vc.fail.spawn · vc.fail.throw · vc.fail.truncated · vc.fail.shape · vc.fail.args · vc.fail.unknown
起不了 git 进程，这一步读不到。
读这一步时断了，内容没拿到。
读到的内容超过了上限，读不全就不给半份数据。
这条路没有按约定回话，读不到内容。
界面这一侧把请求发错了，这一步读不到。
读不到这一项。
这个会话还没有工作区
vc.noCwd
这个会话还没有工作区，读不到版本信息
