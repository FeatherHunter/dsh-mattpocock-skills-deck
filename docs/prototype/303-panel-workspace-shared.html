面板数据能否「按工作区共享一份、新会话秒显不转圈」？—— A 现状 vs B 目标 可交互对比原型

本原型要回答的问题：同一工作区（文件夹）的多个会话，共享同一份面板数据、新开会话秒显缓存并随下次定时静默更新——这个状态模型与交互边界（何时秒显、何时静默、何时必须显示遮罩），是否比现状更合理、可直接拍板？
怎么用：先在上方选 A 现状 或 B 目标，再到「演练场景」选一条动线点「开始」，按步骤点击；每一步后看右侧状态面板与下方事件日志的变化。也可直接点自由操作按钮任意乱按。
声明：本原型不含任何真实网络请求，只示意状态流转与视觉差异；A 模式行为按研究报告 #300 的行号事实建模，个别偶发场景为脚本化示意（见「与现行差异 → 来源与假设」）。
① 面板视觉（当前活跃会话）
② 演练场景与自由操作
③ 自由操作按钮
④ 事件日志（含请求计数）
⑤ 状态面板：工作区共享抽屉 vs 会话状态盒
⑥ 请求计数对比（本模式累加，切模式清零）

📊 数据模型示意：会话状态盒 + 工作区级共享抽屉（B 目标）

🆚 与现行链路的差异说明（A 现状 → B 目标）

⚡ 秒显（有数据必秒显）
打开/切换/新开面板 = 首帧即渲染旧数据，零遮罩零转圈。状态栏徽标显示「最后更新 X 秒前」。
🔔 静默更新（有数据不打扰）
定时探针/后台刷新成功后数据无感替换，仅变化的行闪烁 2.6s 自动清除；无遮罩、无 toast。
🚫 可见加载态（唯一例外）
仅当该工作区完全无可展示数据（首开/缓存被挤掉）才出现全屏遮罩；用户显式刷新 = 按钮 spinner，永不遮罩。
