# 电影探案板 · 第四轮设计任务书（交给独立设计者的共用简报）

> 这份简报给每一位独立设计者看。目标：五个人各做**一个**自包含 HTML 原型，互不干扰。
> 你不需要读别的原型，只需要读完这份简报 + 参考文件，然后按你的概念把它做出来。
> **这一轮跟前三轮最大的不同：原型必须是一个"能用的地图详情页"，不只是好看。真机上有的功能，一个都不能丢。**

---

## 0. 这一轮的来历（维护者的原话）

维护者说：

> 「我喜欢那种侦探、警方或者悬疑片里面那种男主在一个板子上贴上一个个嫌疑人的照片、资料等信息，用磁吸那个点吸附在面板上，有关联的资料之间是红色的线连接着，**中间是最终的目标**的人物。」
>
> 「以此电影感为灵感，设计下我们的 MAP 详情页面的 HTML 原型设计，可以交给不同 subagent 多设计几个。过程中**需要考虑我们现在支持的功能**（执行、新会话、诊断等按钮、还可以看到 MAP 详情正文）。」

所以这一轮要的是两件事**同时成立**：

1. **电影里那块板子的感觉**（下面第 2 节把这种感觉讲细）；
2. **真机上现有的功能一个不少**（下面第 3 节逐条列了，包括按钮上的原词）。

前三轮的历史裁决（简版，别重走弯路）：
- 第一轮十个方向，只有「探案板」被留下，星空／战棋迷雾／等高线／连载手稿／任务控制台／地铁图／折页地图／蓝图／梯田花园全部否定。**要的是「手上的东西」——真实材质、可钉可撕的物件感。**
- 第二轮六份里只有「精修证据墙」得 70 分。**并且下了一条硬裁决：「原型不一定要有明确的层级关系，比如第一层第二层直到终点。这种不是我喜欢的想法。」**
- 第三轮六份（`474-C1`…`474-C6`）都通过了，其中「无限画布探案板」（C1）最接近维护者这次描述的东西。

**所以这一轮有三条不许破的红线：**
1. **不许把「层」当骨架**：不按层分行／分列／分抽屉／分章节，不把层当坐标轴，票上不许挂「第 N 层」的徽章。（数据里还算得出层，但那是给程序看的，不是给眼睛看的。）
2. **四状态语义不许改**（见第 4 节）。
3. **诚实**：未知不许伪装成待办，也不许伪装成不存在。

**这一轮新放开的一条**：维护者这次明说「**中间是最终的目标**」。所以**中心枢纽式**的布局是允许的、而且是他要的——中心是目的地，四周是票，红线连起来。这不违反第 1 条（那不是台阶，是辐射）。

## 1. 这是什么产品

`dsh-mattpocock-skills-deck` 是一个装在「DeepSeek Harness」桌面应用里的插件，在应用**右侧边栏**里画一块面板（宽 360–810 像素，用户可拖）。仓库里的 issue 被当成「票」展示。

**「地图」**是打了 `wayfinder:map` 标签的一类 issue：它有一个**目的地**（正文 `## Destination` 一节），下面挂着一批子票，子票之间有阻塞关系（`blockedBy`）：A 没关掉，B 就动不了。

**这一页要回答四个问题**：终点在哪 / 我现在能做什么 / 哪些路还没走过 / 走过的路留下了什么痕迹。

**硬约束**：点开面板到看见内容 **≤ 300 毫秒**。因此**不许引入任何第三方库、不许联网、不许用 CDN**；一个 HTML 文件，双击就能打开，全部代码自己写。

## 2. 电影里那块板子，具体长什么样（这是这一轮的核心灵感）

**板面与固定物**——两种气质，你选一种或做出你自己的：
- **金属板／白板 ＋ 圆形磁扣**：冷、现代、警方作战室、荧光灯下反光。维护者原话说的是「磁吸」，所以他脑子里更可能是这一种。
- **软木板 ＋ 彩色图钉**：暖、老派、地下室或深夜办公室，钉子上带塑料圆头（红蓝黄绿），颜色本身在分类。

**板上贴的是什么**（这一点决定了「密度」）：嫌疑人照片、打印的资料、笔录、通话记录单、银行流水、地图上圈出的地点、报纸剪报、机票车票、收据、便利贴、手写纸条。**资料上还有人的痕迹**：马克笔画的圈、打的叉、写的编号、贴的箭头贴纸、折角、咖啡渍、胶带。

**线**：红色毛线或棉线，绷紧、有自然垂度、会交叉。有的片子用多色（红是主线、黄是支线、蓝是还没查的）。**线不是装饰，线是结论的可见化**：拔掉一根线就等于推翻一个假设。

**中心那张**：最大、最正、位置在视线高度，比别的东西亮一点。**四周的线都朝它汇。**有时它被单独圈起来、被划掉、被烟头烫出一个洞。

**边上的零碎**：放大镜、马克笔、胶带、便签本、咖啡杯、烟灰缸、一把椅子。这些东西让板子看起来是「人在用」的。

**镜头怎么拍**（这类片子反复用的几套；换成界面就是「动效与交互怎么设计」）：
1. **拉远揭示**——先拍一张资料的特写，镜头往后拉，露出整面墙的连线网。最经典的一下。
2. **推近**——缓缓靠近板子，视线被一根线牵着，从这张走到那张。
3. **沿着线走**——镜头贴着线移动，像跟着线索往前摸。
4. **从板子后面拍**——穿过板和线去看人，人被线切成几块，剪影在光里。
5. **手部特写**——把磁扣按下去、把资料按在板上、把一根线拽紧、把一条划掉。
6. **人从线丛里穿过／拨开线**——身体动作穿过这张网，意思是「他钻进这个案子了」。
7. **打光**——房间暗，只有一盏台灯或百叶窗缝的光，线在光里发亮。

**为什么这东西有力量**（这一段请认真读，它决定了什么该做、什么不该做）：
- 它把**想不清楚**变成**看得见**：侦探脑子里那张网被外化到墙上。
- **观众和侦探站同一个位置**——我们看到的和他看到的一样多，所以推理是一起做的。
- 板子同时给出两样东西：**中心是「要到哪去」**，周围是「有哪些路、哪些还没查」。
- 它天生的诚实：**没查的地方就是空的、就是还没钉上去的**。迷雾本身就是信息。
- 它**永远是半成品**：永远有空位、有还没钉上去的、有被划掉的。它从来不「完成」。

**一句实话（帮你把握分寸）**：现实里的警察很少真的这么拉红线，这是**影视化的发明**。所以这一轮要的是「**看起来对**」的电影语法，不是「流程上真」的工作流复刻。但第 3 节那批真机功能是硬要求，一个都不能因为「电影里没有按钮」而省掉——**你的本事就在于怎么让这些按钮长在这块板子上还不出戏**。

## 3. 必须保留的真机功能（硬要求，逐条核对）

下面这些是**今天真机上的功能**（抄自 `src/client/views/MapDetail.js` 与语言表）。原词照用，**不许改叫别的名字**（把「执行」改叫「出警」这种造新词的做法违反仓库纪律）。你可以改它们的**长相和位置**，但必须认得出来、点得到、有反馈。

**A. 顶部一条常驻操作行**（滚动时也看得见）：
- `← 返回`（返回上一级／列表）
- 面包屑：`列表 / #604`（从上一级进来时是 `#上一级 / #604`）
- `wayfinder:map` 标签
- 主按钮（三选一，取决于这张图的状态）：**没有子票时是 `检查`**、**子票全部关闭时是 `完成`**、**其余情况是 `执行`**
- `新会话`（在新会话里打开、推进这张图）
- **`诊断`**（诊断入口）

**B. 地图抬头**：`#604` + 标题 `MattSkillsDeck 全量性能调查与优化落地（面板 · 状态栏 · 宿主取数链）`，以及「本图 N 张子票（已关闭 M 张）」。

**C. 进度**：今天是「分层分段进度条 ＋ `当前：层 3` ＋ `2/4 层已通过`」。
**注意：这个进度环按「层数 + 1」算，单层地图永远显示满环，是个已知的错。你可以换一种诚实的进度呈现**（比如「已经办结 4 张 / 一共 20 张」、「正在办 1 张」、「现在能动手 4 张」、「还没探明 11 张」）——但**不许让任何一处进度显示撒谎**。

**D. 目的地（Destination）**：一段 236 字的正文，今天显示在抬头下面（绿色小旗图标 + 文字）。**这是整页的中心，任何方案里它都必须完整可见、且永远比周围亮。**

**E. 正文详情（Notes）**：今天是一个默认折叠的 `<details>`，标题就叫 `正文详情`，里面是 markdown 正文。真实地图 #604 的正文很长（见第 4 节），**原型要有一条路径能看到它**（钉在板上、挂在板边、抽出来的一张纸……随你）。

**F. 每一张票**：`#编号` ＋ 类型标签（研究／讨论／原型／修复／任务／地图）＋ 标题 ＋ 一行副信息（已关闭／经办人是谁／被谁挡着）＋ 进度 ＋ 状态。
票上的动作（**只在「开着且没有被挡住」的票上出现**）：一个技能按钮（研究票是 `研究`、讨论票是 `讨论`、原型票是 `原型`、其余是 `修复`）、`新会话`、以及一个「打开原票」的链接图标。

**G. 底部三个可折叠区块**（原词照用）：
- `Decisions so far（2）`——已经定下来的结论，每条形如「结论标题 — 一句话摘要」
- `Not yet specified（战雾 5）`——还没定的
- `Out of scope（5）`——明确不做的

**H. 底部那颗主按钮**：跟顶部同语义（`执行`／`完成`／`检查`），旁边一个 `档案` 链接（打开原票）。

**这八条是验收项。任何一条在原型里找不到，这份原型就不合格。**

## 4. 票的四个状态（全项目统一，不许改语义）

| 状态 | 判定 | 含义 |
|---|---|---|
| **走亮** | `state === 'CLOSED'` | 已经走完的路（今天页面上的词是「已关闭」） |
| **照亮中** | 开着，且有 `claimedBy` | 正在推进的那一张 |
| **现在能做** | 开着，没人认领，且它的阻塞者全都关了 | 现在就能开工的下一站 |
| **雾里** | 开着，且它至少有一个阻塞者还开着 | 路画出来了，但通不通不知道 |

四条全是**只看自己家前后**就能判出来的，没有一条要问「我在第几层」。

**不许只靠颜色区分状态**（色弱用户）：形状、纹理、文字、印章、图标至少再占一样。

### 5.2 正文（这是真的，一字不改）

**正文详情（Notes）**——真实地图的正文有 16 条，原型里放下面这 6 条，其余用一条折叠行带过（写「正文还有 10 条」）：

- 本图**携带执行**，不是纯规划图。票按「查清 → 方案 → 落地 → 真机复测」四步走；地图关闭条件 = 清单上每一条要么已落地并复测达标，要么明确裁决「不改」并写明理由。允许「裁决不改」作为合法终点，但不允许「没量就跳过」。
- 领域：宿主取数链（`src/host/`）、客户端渲染（`src/client/`）、日志体系（`src/host/logPkg/`、`research/489-appendix.md`）、平台层（`src/host/platform/`）、三层解耦（`src/seam/`）。
- **先量后改**：每条结论都必须能指到实测数字。本地对照实验的绝对毫秒数不能当真机数字用，只能搬「改前 / 改后的倍数」与「结果等价性」两个结论。

- 以目标准为闸门：超过目标准的一律治；已经达标的不动，登记一行「已达标」。
- 提问方式：需要人拿主意时写在对话正文里，不用弹窗式提问工具。

**Not yet specified（战雾 5 条）**：
- 按体检清单毕业出来的「方案 + 落地 + 真机复测」票：每一条毛病单独成票，数量与内容要等体检结果才知道，现在切不出来。

- 真机取证的常备手法细节（怎么一键复测、结果放哪）：等测点常备化那票落地后再定。

## 7. 五个人的任务（都在电影板这个世界里，五种不同做法）

### M1 · 作战室金属板（冷 · 磁扣 · 现代警方）

一整块**金属板**，圆形**磁扣**把资料吸在板上。冷白荧光灯，板面有轻微反光与网格。**中心是目的地那张**（最大、最亮、被磁扣四角吸住），红线从四面朝它汇。
- 票＝吸在板上的资料（照片格 + 编号 + 类型 + 标题 + 状态），四状态各有一件**实物**：已关闭＝盖了黑章／照亮中＝压着一枚蓝色的在办磁扣／现在能做＝贴着一张绿色小旗／雾里＝一张还没写字的空白资料（只钉了一个空磁扣位）。
- 顶部操作行做成**作战室的命令条**（金属质感的一条，上面是 `执行` / `新会话` / `诊断`），滚动时常驻。
- `正文详情`＝板子右上角钉着的一份「案情摘要」，点开像抽出一张纸。
- **入场**：先给一张资料的特写，镜头**拉远**露出整面墙的网（这一下正好也解决「首屏要看得清」）。
- 必须做出来的交互：**拖动一块磁扣／一张资料**它能挪位并记住；**鼠标移到一条红线上**，这条线亮起来并显示它连的是谁跟谁。

### M2 · 深夜软木板（暖 · 图钉 · 一个人的房间）

**软木板 + 彩色图钉**，一盏**台灯**，板子以外的房间是暗的。桌上有咖啡杯、便签本、一支笔。
- 台灯的光圈**跟着鼠标走**，光没照到的地方沉在暗里（这是物理上成立的雾）。**但目的地那张永远是最亮的，跟灯在哪无关**。
- 票＝钉在板上的资料，用**图钉颜色**区分类型（研究／讨论／原型／修复／任务）。
- `正文详情`＝用图钉钉在板子下沿的一张**对折的纸**，点开摊平。
- 功能按钮＝板子下沿一条**木质横档**上镶的黄铜牌（`执行` / `新会话` / `诊断`）。
- 必须做出来的交互：**拖动资料**、**拖动台灯**（或用方向键），并且**暗处的东西点得到**（#474 要求「雾不挡点按」）。

### M3 · 一块玻璃（从板子后面拍）

资料吸在**半透明玻璃**上，玻璃后面有房间的光。马克笔直接画在玻璃上的圈和箭头，红线在玻璃上穿来穿去。
- 这个方案的命脉是**光**：背景光从玻璃后面透过来，资料是半透的，线在光里发亮。鼠标移动时，背后的光跟着动一点（像有人从玻璃后面走过）。
- 中心那张目的地最大，被马克笔圈了一圈，旁边写着「目标」。
- 票＝贴在玻璃上的资料；雾里的票＝**背光被关掉**的那一块（暗斑），点一下背光亮起，内容才浮出来。
- `正文详情`＝玻璃上用马克笔写在右下角的一段摘要，点开时**拉出一张半透明的叠层**。
- 功能按钮＝吸在玻璃边缘的金属标签。
- 必须做出来的交互：**背光跟随指针**、**拖一张资料**、**点一块暗斑把它点亮**。

### M4 · 一整面墙（多块板拼起来 · 专案组会议室）

不是一块板，是**一整面墙**：正中一块板是**目标**（目的地＋进度＋主按钮），左右各挂几块分区板（正在办 / 现在能动手 / 已经办结 / 还没探明），边上还摆着卷宗、白板上写着时间线。
- 这个方案**最适合装下全部功能**：正文详情＝桌角摊开的卷宗；`Decisions so far` / `Not yet specified` / `Out of scope`＝墙上三块小标签板（或者白板上写着的三栏）；`执行`/`新会话`/`诊断`＝门口那块开关板／对讲机。
- 票＝分区板上吸着的资料，红线在板与板之间穿。
- 必须做出来的交互：**在墙上平移**（墙比一屏大一点），**拖一块资料换板**，**点一块分区板把它放大到正中**（像人往前走一步凑近看）。

### M5 · 运镜即交互（把「镜头」做成界面）

以**镜头**为核心：进页面先是一张资料的特写，然后**拉远**露出整块板；鼠标滚轮像推轨，拖动像摇镜；点一条红线，镜头**沿着这条线走到另一头**那张资料上。
- 板子本身用金属板 + 磁扣（或你自己定），中心是目的地。
- 功能按钮做成一条**常驻的「字幕条」**式操作行，固定在面板底部，永远在（`执行` / `新会话` / `诊断` 都在这条上）。
- `正文详情`＝一块可以**推进来看**的展板（点了它，镜头推近到它正面）。
- 必须做出来的交互：**进场拉远**（一次就好，不要循环）、**滚轮缩放**、**点线走位**（镜头平移到另一端）。
- 分寸：**不要为了运镜牺牲内容**。20 张票时要能看全、要能读字。

## 8. 技术菜单（挑着用，每条都必须让「电影感」更强）

1. **无限画布相机**：pointer 拖动平移 + 滚轮以光标为锚点缩放，rAF 惯性。
2. **拖拽物理**：`setPointerCapture` + 速度采样 + 弹簧阻尼，松手自然收住。
3. **红绳布线**：正交或曲线绕行，**不许穿过资料卡片**；SVG `<path>` 或 canvas 都行；箭头指向被阻挡的一方。
4. **内联 SVG 滤镜做真材质**：`feTurbulence` 生成软木／金属拉丝／玻璃磨砂，`feColorMatrix` 上色，`feDropShadow` 做纸的抬起——零图片、零网络。
5. **`mask-image` 跟随指针**：台灯光圈／背光，rAF 做阻尼跟随，别硬跟手。
6. **`mix-blend-mode`**：`multiply` 做墨迹与章，`screen`／`soft-light` 做灯光。
7. **`@property` 动画**：注册自定义属性做「盖章」「线被绷紧」「灯亮起来」这类可插值的东西。
8. **Web Animations API**：`element.animate()` 做可打断的镜头移动与抽卡。
9. **`content-visibility` + `contain-intrinsic-size`**：20 张以上卡片时保性能。
10. **`ResizeObserver` / `@container`**：面板被拖到 400 时换布局（真响应容器，不是响应窗口）。
11. **指针压力**：`pointerType === 'pen'` 时用 `event.pressure` 改笔迹粗细。
12. **程序化生成**：条形码、印章、指纹、齿孔、磁扣，全用 CSS/SVG 现算，不许贴图。

**性能红线**：首屏 ≤ 300 毫秒；rAF 里不许反复读 `offsetWidth` 造成强制同步布局；20 张卡时拖动要跟得上手。

## 9. 交付契约

1. **一个文件**：`docs/prototype/474-<编号>-<英文短名>.html`（编号 `M1`…`M5`）。单文件自包含：不许 `<script src>`、不许 `<link href>`、不许联网、不装任何包、不用轮询定时器。
2. **双击即开**：Chrome / Edge 打开就完整可用；所有数据内联。
3. **自适应**：`?w=400` 与 `?w=810` 都要正确渲染，不许横向滚动。
4. **URL 参数**：至少支持 `?w=`（宽度）、`?s=active|empty|big`（状态）、`?bar=0`（隐藏控制条，用于截图）。
5. **键盘可达**：Tab 走遍所有可交互元素，Enter/Space 等同点击；`←` `→` 不被拦截。
6. **诚实渲染**：数据缺字段按空渲染，不许抛错。
7. **每个票的根节点带 `data-ticket="编号"` 与 `data-state="closed|lit|ready|fog"`**；承载目的地的节点带 `data-role="destination"`。第 3 节那八条功能各给一个稳定的可查询标记（例如 `data-cap="execute|newSession|diagnose|notes|decisions|fog|outOfScope|back"`）——**这是验收用的，不是给你加负担**。
8. **自检**（必做，必须动手验证）：node + playwright 已装好，仓库根目录 `require('playwright')` 可用（写法参考 `.tmp-474-live/shot10.cjs`）。至少验：
   - 三份样本 × 两种宽度，每份**等满 2.5 秒**再收 `pageerror` 与 `console.error`（打字机／入场动画这类延后启动的链路，等 500 毫秒是抓不到的）；
   - `document.body` 与 `documentElement` 无横向滚动；
   - 四状态票都在 DOM 里且分布对：active `2/1/0/1`，big `4/1/4/11`；
   - **第 3 节 A–H 八条功能每一条都能在 DOM 里找到、且目的地在视野里**；
   - 用真指针跑一遍你承诺的核心交互（拖资料 / 拖灯 / 点线走位 / 背光跟随），贴原始输出。
9. **产出截图**：810 与 400 各一张、大样本 810 一张，放 `docs/prototype/474-shots/`，命名 `m1-<短名>-810.png` / `-400.png` / `-big810.png`。

## 10. 不要做的事

- 不要改别人的文件、不要动 `src/`、`host.js`、`package/`（那是插件本体，本次只做原型）。
- 不要 `git add` / `git commit`；不要装 npm 包；临时脚本放 `.tmp-474-live/` 下。
- 写文件只用文件工具；**绝不要用 PowerShell 的 `-replace` + `Set-Content` 写中文文件**（会变乱码）。
- **不许用层当骨架**（第 0 节红线 1）；**不许改票上的原词**（执行／新会话／诊断／正文详情／Decisions so far／Not yet specified／Out of scope）。
- **不许为了电影感把功能藏起来**：第 3 节 A–H 八条必须一屏之内能找到，不能要点三次才出现。
- 不要写只有自己看得懂的简称；页面上的中文要让人第一眼读懂。
