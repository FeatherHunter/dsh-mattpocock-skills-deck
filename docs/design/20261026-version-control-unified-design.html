01顶部信息：把「我在哪、和远端什么关系、几时读的」缩成一条可核的状态轨

现状把仓库名、分支、同步、路径、两个时间、刷新按钮挤在两行里，同步与时间的含义全靠用户自己猜；拉取、推送又只在「改动」页出现，切到提交历史或工作树就找不到。

  1. 1
    「超前 2 · 落后 0」是裸文本：没有基准远端、没有颜色优先级，也没有解释「超前」到底相对谁。同一个词在别处还叫「领先」（854 原型、工作树列表的过滤词），两种叫法并存。
  2. 2
    两个时间没有说明书：用户看到「读取于 刚刚」「远端信息更新于 12 分钟前」，但页面不解释前者不联网、后者依赖上一次取回远端信息；也不知道「更新」这颗按钮到底联网不联网。
  3. 3
    三个页签的数字是三种单位：11 是文件数、50 是已加载的提交条数、13 是工作树棵数，却都裸着；50 还会让人以为是总数。
  4. 4
    「更新」是含糊动词：它其实是「取回远端信息」（fetch），和「重新读取」（本地重读）不是一类动作，却都长得很像按钮；而提示语又说「请先提交再拉取」，把 fetch 和 pull 混成一句。
  5. 5
    同步动作待在「改动」页的视图条里：拉取、推送是仓库级动作，切到提交历史或工作树就找不到；身份块里的 sync 只读不动作。

「超前 2 · 落后 0」裸文本，相对谁、哪个更急都要猜
同步是五个状态：一致 / 领先 / 落后 / 分叉 / 没有远端依据；每种状态有自己的颜色和一句完整的话。
+

+

−

+

−

+
页签是一组真正的 tab：role="tablist"、左右方向键切换、aria-controls 指向各自面板；切换保留每个页签自己的滚动位置与选中项。

关键决定：读类动作留在状态轨（重新读取 / 取回远端信息），会改远端关系的动作（拉取 / 推送）也归状态轨，因为它们改变的是「与远端的差」；暂存、提交、丢弃仍然只在「改动」里。这条分界和 ADR 20261004 的写路径一致：能看到关系的地方才能改关系。

验收切到任意页签，同步状态、两个时间解释、重新读取与推送入口都在同一处；任何数字与时间都能点开或悬停拿到口径；520 以上一行放下，300px 收成两行且动作进「⋯」。

03提交历史：列表与详情是两层，不是上下堆

现状把「这一笔的详情」画在「提交列表」上方，两者共享一条很长的垂直滚动；返回按钮又写「返回未提交改动」并真的把人带回改动页。设计改成单列两层：列表与详情一次只显示一个（点行进详情、返回回列表），返回只回来源，列表给出筛选范围、日期分组与精确时间。

动作类型放在哪完成后结果回到哪

  10. ✓
    宽度档（460–520 / 380–459 / 300–379）逐屏核对：没有左右两栏，无横向滚动、无动作被裁掉。

D 明确不做

  1. ·
    不自动 fetch / 自动 pull：首屏不联网是 ADR 20261002 定的，保留。
  2. ·
    不做全库提交搜索：筛选只作用于已加载集合，范围写在输入框上，不假装有服务端搜索。
  3. ·
    不在页面里新建 / 切换 / 删除工作树、不 checkout：这些留在侧栏终端；页面只给入口与交接。
  4. ·
    不改写任何 git 生成的文字（提交说明、Merge 原文、报错原话）；中文只出现在界面词条与解释里。
  5. ·
    不新增主题与皮肤：沿用「工程台账」深色；文档页用浅色是为了读，不代表产品支持浅色主题。
