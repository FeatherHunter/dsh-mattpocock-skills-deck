# 原型行级按钮与提示词定版

## Problem Statement

用户在面板里看到带 `wayfinder:prototype` 标签的票时，只能看到通用的“执行”紫色按钮，点进去是 `/wayfinder {url}`。这让用户分不清这张票到底是要做研究还是要做一次抛弃式原型，也看不出它跟研究、讨论、修复有什么区别。按钮颜色写死，不跟着 GitHub 上这个标签的颜色走，改了标签色按钮也不变。

## Solution

给这类票一个专属入口：三处（列表里的一行、地图卡片、详情页顶部）都显示同一个“原型”按钮，文案中文“原型”英文“Prototype”，图标用 Apple 极简的双层卡（前实后虚），颜色跟着标签走——有标签色就用标签色，没有就回退到 `#f59e0b` 暖黄，字色按亮度自动选深或白。点一下，三处都往输入框里塞同一条提示词 `/prototype {url}`。这条提示词只做两件事：说清要回答的设计问题并选分支（逻辑是否顺畅就做单文件可分享的页面，界面长什么样就做同路由多变体加底部切换），然后按分支做出抛弃式原型并把状态外显。窄屏时按钮只剩图标，被阻塞时不显示主按钮。占位符只用 `{url}`，跟研究保持一致。

## User Stories

1. 作为看板用户，当一张未关闭的票带有 `wayfinder:prototype` 时，我想在列表那一行看到“原型”按钮，而不是“执行”，好让我一眼知道这是要做原型。
2. 作为看板用户，当我打开地图卡片看到同一张票时，我想看到跟列表一样的“原型”按钮和颜色，好让我不用猜两处是不是一回事。
3. 作为详情页用户，当我点进这张票的详情页时，我想在顶部看到跟列表一样的“原型”按钮，好让我在详情里也能直接开始。
4. 作为使用英文界面的用户，我想看到 “Prototype” 而不是“原型”，好让我按自己语言读懂。
5. 作为维护标签颜色的人，当我在 GitHub 上改了 `wayfinder:prototype` 的颜色后，我想面板里的“原型”按钮立刻跟着变，而不是写死不变。
6. 作为使用本地 Markdown 后端的人，当我在标签调色盘里改了 `wayfinder:prototype` 的颜色后，我想按钮也跟着变。
7. 作为在窄屏下使用的人，当窗口很窄时，我想按钮只剩图标不溢出，好让我还能点到。
8. 作为被阻塞票的查看者，当一张原型票被别的票阻塞时，我想主按钮先不显示，好让我知道现在不能开始。
9. 作为点按钮的人，我想点一下就能在当前会话的输入框里看到一条完整提示词，里面已经填好了这张票的链接 `{url}`，好让我直接回车开始。
10. 作为中文用户，我想那条提示词是中文的，包含原型目标、澄清、收尾、正文格式四段，好让我按清单做。
11. 作为英文用户，我想那条提示词是英文的，Goals、Clarify、Wrap-up、Body format 四段与中文一一对应。
12. 作为做逻辑原型的人，我想提示词让我先说清问题并选分支——逻辑顺畅就做单文件可分享的页面，好让我按对分支做。
13. 作为做界面原型的人，我想提示词让我选界面分支——同路由多变体加底部切换，好让我一次做出多个高保真差异。
14. 作为怕猜错的人，当提示词里有“我猜用户想要” 的地方，我想先被提醒去追问确认，而不是直接猜着做。
15. 作为收尾的人，我想做完后被提醒按进度约定去更新正文，95% 时必须写明待确认什么，没确认不能关，好让进度真实。
16. 作为写正文的人，我想被提醒用真实换行、每段 `## 章节` 独占一行、段落间空一行，不要写成 `\n` 两个字符，也不以不可见字符开头。
17. 作为配模板的人，我想在模板编辑器里看到“原型”这一项可编辑，必填的 `{url}` 删了就无法保存，并有提示。
18. 作为配过模板的人，当我删了必填的 `{url}` 后，我想保存时被拦住并告诉我缺了什么。
19. 作为没配过模板的人，我想留空就自动用默认的那条原型提示词，不用自己写。
20. 作为看优先级的人，当一张票同时有 `research` 和 `prototype` 时，我想只看到上游的“研究”按钮，而不是并列两个，好让优先级清晰。
21. 作为看优先级的人，我想完整顺序是 未分类/待诊断 > 缺陷 > 讨论 > 研究 > 原型 > 执行，这样最不惊讶。
22. 作为换皮肤的人，当标签色很浅时，我想按钮上的字自动变深色，好让我看得清。
23. 作为发布的人，我想改完后跑一次构建，两份产物（开发用与发布用）一致，好让线上和本地一致。

## Implementation Decisions

- 提示词只用一个占位符 `{url}`，跟研究一致，版本记为 1，用一句话说明“动作按钮‘原型’·清单式”。留出以后若需 `{title}` 或 `{number}` 再讨论加的余地。
- 中文提示词用 `/prototype {url}` 开头，后接四段：原型目标（先说清问题并选分支，只写两行）、澄清、收尾、正文格式。英文用 Goals、Clarify、Wrap-up、Body format 对译。不把原型技能里的六条共同规则复述进提示词，规则由技能本身承载。
- 词典里加“原型”与 “Prototype” 两个条目，分别对应按钮文案与模板名。
- 按钮颜色跟着标签走，取快照里所有标签色与票面标签色的并集里 `wayfinder:prototype` 的那一项，没有就用 `#f59e0b`。字色按亮度公式算，大于 160 用深字 `#140a1e`，否则白字，与研究、修复同逻辑。
- 图标用双层卡：后一张半透明，前一张实心，都是大圆角，极简，十像素下仍可辨前后深度。
- 三处（列表行、地图卡片、详情页）走同一套“谁该显示”的判断与同一套“点一下塞什么”的文本，不各写一份。
- 被阻塞的票不显示主按钮，窄屏时按钮只剩图标。
- 两份产物一致性：改一处源，跑一遍构建，两份产物一起更新。
- 本地 Markdown 的标签调色盘里已有 `wayfinder:prototype #f59e0b` 这一行，改这一行就能改按钮色。

## Testing Decisions

- 只测从外看到的行为，不测内部怎么写。看按钮上是不是“原型”、颜色对不对、点一下塞进去的是不是同一条提示词、窄屏与阻塞时显隐对不对。
- 测的地方就选面板里那一个整段：点带原型标签的票，看三处按钮。
- 再加一个小校验：模板里必须含 `{url}`，少了就拦。
- 参考之前给“研究”按钮做过的那套校验写法，保持一致。

## Out of Scope

- 不自动打标签，也不新建标签。
- 不改已有优先级与颜色。
- 不加新的后端能力或字段。
- 不在这次把占位符加到 `{title}` 或 `{number}`。
- 不处理标签改色后极浅色的二次特判，仍用同一套亮度阈值。
- 不为原型单独加新的验证维度，仍用现有门禁。

## Further Notes

- 本次图标定为 Apple 极简双层卡（U），前实后虚，近大感靠留白，十像素下仍可辨深度与三选一。前 13 版备选仍留档，若后续要更强“三选一”选中感可在顶层加勾或星芒的半档精致度迭代。
