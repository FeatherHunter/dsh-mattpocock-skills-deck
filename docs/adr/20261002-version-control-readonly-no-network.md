# ADR：版本管理页签第一版只读视图不联网（领先/落后只读本地缓存并永远标出依据时间）

> 日期：2026-10-02 定版（承接地图 #810 与来源票 #812；git 命令与输出解析口径见 #811 已关闭的调研，本文不重复）
> 地位：本文件是「版本管理页签第一版只读视图的数据从哪里来」这一件事的唯一依据。凡与本文冲突的旧写法以本文为准；未来任何讨论若改动本决策，以未来版本为准（CONTEXT.md 同款两条规则）。
> 关联：#810（地图）· #812（来源票）· #811（命令选型调研）· #704（刷新机制地图，决定「什么时候去取」，不决定「从哪里取」）· `docs/adr/20260913-builtin-ts-shape.md`（TypeScript 与 JavaScript 的分界线）· `CONTEXT.md` 的「版本管理词条」

## 1. 背景

版本管理页签要回答「我现在在哪个工作树的哪个分支上、我的改动安不安全、有没有漏提交」。其中「当前分支和远端的领先落后状态」是 #811 调研定下的第一版必备项。

问题在于：领先/落后要准，就得问远端；一问远端就是网络动作。DSH 调 git 走的是宿主 `subprocess` 服务起的子进程（`src/host/repoKeys.js:125-159` 的形状），**没有终端可以接交互提示**。`git fetch` 遇到需要凭据的远端时会弹交互式凭据提示，这个提示在无终端的子进程里会挂住直到超时。要做对必须给每次 git 调用钉死 `GIT_TERMINAL_PROMPT=0`，那属于宿主执行层的一张独立票，不是视图这一版能顺带解决的。

所以「第一版不联网」不是范围上的偷懒，是**能力上的前置条件没到位**。

## 2. 决策

1. **第一版只读视图不发起任何网络动作。** 不提供 fetch、不提供 pull、不提供 push。读到的全部数据来自本地。
2. **领先/落后只读本地缓存。** 读 `git status --porcelain=v2 --branch` 的 `# branch.ab`（#811 已定：这是唯一在「上游缺失」时不报错的路径）。这个数字相对的是**本地记录的远端状态**，不是此刻的真实远端。
3. **永远显示这个依据的时间，不设阈值。** 依据时间先取远端跟踪引用 reflog 的末条时间戳，即「这个远端信息最后一次被刷新」的时刻；刚克隆、还没 fetch 过、引用已被打包这类没有 reflog 的情形，退回**这个上游自己的松散引用文件**的落盘时间；两条都拿不到就如实说读不到，**绝不拿现在几点、也绝不拿全仓库共用的 `packed-refs` 的落盘时间顶替**（那个时间与这个上游无关，`git gc` 一次就会让它往后跳）。显示成一行安静的小灰字，**没有「新旧两套样式」，没有魔数阈值**。

   设阈值要凭空多出一个魔数、一条第二套样式、一次「到底定多少」的争论，而且判断本来就不精确——想知道依据是否够新，唯一准办法是去问远端，而这一版恰恰不问。永远显示，代价只是几个字符，换来的是一条代码路径和一份完整的诚实。
4. **依据时间读得到与读不到，必须画成两样东西。** 读得到：数字照常显示，旁边跟依据时间。读不到：那一项显示「读不到」加重试。混淆的后果是把「我不知道」画成「我知道了但是旧的」，或者反过来。

   **2026-10-04 补记（#819 对抗式审查）**：本节原先写的是「依据旧」，与第 3 条「不设阈值」自相矛盾——不设阈值就没有办法判「旧」，这一档按字面不可实现。所以它的真实含义是**依据未知**（判据 `basisMs === null`）。代码里旧名字 `tracked-stale` / `tracked-fresh` 现在叫 `tracked-known` / `tracked-unknown`：known 是「依据时间读得到」，unknown 是「读不到」——两个都不是在说「新 / 旧」。

## 3. 五种分支状态各有各的说法

「分支怎么样」不是一件事，是五件。合并成一句话就会对用户说错话：

| 状态 | 判据（#811 已定的命令口径） | 界面上 |
|---|---|---|
| 有推送目标，依据读得到 | `# branch.ab` 有值，且依据时间读得到 | `领先 3` + 一行灰字写依据时间 |
| 有推送目标，依据未知 | 同上，但依据时间读不到（刚克隆、引用已打包、上游是本地分支） | `领先 3` + 一行灰字写「读不到」 |
| 推送目标没了 | `for-each-ref` 的 `%(upstream:track)` 给字面量 `[gone]` | `推送目标 origin/main 已经不存在` |
| 还没设推送目标 | `# branch.upstream` 整行缺失（新分支最常见） | `还没有推送目标` |
| 游离头指针 | `# branch.head` 等于 `(detached)` | 身份行分支位置显示 `a1b2c3d 游离头指针` |

最后一条在措辞上要中性：`git checkout <某个提交>` 是合法且常见的操作，把它染成警告色是在指责用户。但它必须显眼——在这个状态下做的提交会挂在一个没人引用的提交上，是这个页签要消灭的那类事故。

## 5. 将来要放开联网时怎么办

放开的前置条件是宿主执行层能安全地跑会触发凭据提示的命令（钉死 `GIT_TERMINAL_PROMPT=0` 之类）。在那之前，界面上给「依据时间读不到、或那个数字可能已经过时」的用户的出路，是指一句话：在侧栏终端里运行 `git fetch` 之后回来刷新。**侧栏终端是这一版唯一被承诺的联网出口**，与地图 #810 已定的「有风险的操作走侧栏终端」一致。

## 6. 平台契约：宿主文件服务的调用形状（踩过一次，2026-10-04 记）

读首屏要用到宿主文件服务（读那四个「正在合并 / 变基 / 拣选 / 回退」的标记文件、读上游松散引用文件的落盘时间）。**这个服务的调用形状与 Node 的 `fs` 不同**，照 Node 的习惯写会整条读不出来：

- `stat(target, signal)`：收的是 `resolve()` 的产物（一个带 `targetKey` 的对象），**不是路径字符串**；缺失时回 `undefined`。
- `lstat(path, opts, signal)`：这个才是**路径式**的；缺失时回 `undefined`。
- **没有 `exists`**；缺失的 `code` 是 `FS_NOT_FOUND`（不是 Node 的 `ENOENT`），判「没有这个文件」要把 `ENOENT` / `ENOTDIR` / `FS_NOT_FOUND` 一起认（共享判据见 `src/host/fsAbsence.js`）。

两个由此而来的纪律：① 路径式的存在性检查走 `lstat`（或 `resolve` + `stat(target)`），别把路径喂给 `stat`；② **每个探测各自给结论，一条探测抛错不许否决别的探测的结论** —— 2026-10-04 的那次故障就是「先 `stat(路径)` 抛错记了一票，把后面本来正确的 `lstat` 结论一票否决」，于是首屏整条失败、界面还把它说成「找不到 git 程序」。
