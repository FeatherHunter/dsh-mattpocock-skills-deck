## 1. 背景：同一件事今天有三个决定者

「进程什么时候可以退出」在今天由三处各自决定，谁也不知道另外两处在想什么：

| 决定者 | 它现在的做法 | 出过的事 |
| --- | --- | --- |
| 产品壳里五处等待的定时器 | `src/deck/shell/call-shell.ts:93` 的 `realSleep` 等五处，装好后 `unref()`（#1114 有意为之：只为到点提醒的定时器不许决定进程活多久） | 一场竞速里只剩它一笔等待时，进程当场收摊：选后端那一笔从未结算，77 毫秒退出、退出码 0；`tests/verify-deck-repo-resolve.js` 拆掉绕行后 13 条断言只跑到 7 条 |
| 门禁用的时间压缩助手 | `tests/lib/time-compress.js:117` 的提前返回只在走到底时算一次「还有没有被引用的等待」，`:123` 又把泵 `unref` 掉 | 产品的 `unref()` 打在助手的虚拟句柄上（`:181`），泵停在没被引用的定时器上；`tests/verify-deck-no-hang.js` 拆掉原生把手后 21 条只跑到 12 条、无收尾行、退出码 0 |
| 两条门禁自己 | `tests/verify-deck-no-hang.js:25-33` 一支原生 `setInterval` 把手、`tests/verify-deck-repo-resolve.js` 注入同形状等候口 | 两处都是 #1138 的绕行；前者今天能跑满 21 条，靠的是助手缺陷的余荫（实测：把「两方向都重新评估」的助手配上去，只剩 0 条） |

三处各自都「有道理」：产品想让提醒不吊住进程，助手想只在自己被需要时留住进程，门禁想跑完。合在一起的结果是——**没有一处能对「这趟跑完了吗」负责**。

## 2. 裁决

1. **存活与到点提醒分开。** 到点提醒永远不拥有存活：`realSleep` 这类等待口令继续 `unref`。要用到「这段时间进程必须活着」的地方，显式拿一份**存活租约**——谁有活在跑谁拿，活干完就释放。
2. **租约是独立原语，不挂在定时器上。** 落点是 `src/deck/shell/in-flight-lease.ts` 的 `withInFlightLease(work)`：内部一个引用计数加一支懒创建的被引用长延时真实句柄，计数 0→1 时建、回到 0 时清。理由：Node 只认被引用的句柄，「有活在跑」在语言里没有对应类型，只能自己立一个；做成 O(1) 的计数加单一句柄，而不是每个租约各拿一支定时器（那会把句柄数变成 O(并发)）。
3. **虚拟时钟的引用状态必须是队列的纯函数。** 门禁助手的泵该不该被引用，只由「队列里还有没有被引用的等待」这一个事实决定，并且在每次会改变这个事实的变更点重算（排入、撤销、`ref`、`unref`、重排、到点触发），不许由「上一次走到底时的状态」残留决定。理由：#1146 的根因不是少写了一行，而是把不变量算成了历史状态。
4. **门禁的存活由门禁自己拥有。** 夹具可以持有自己的存活把手，而且它不是「等缺陷修好就拆」的临时物：一次检查跑得完，不该依赖被检查对象（助手或产品）的引用记账。`tests/verify-deck-no-hang.js` 的原生把手因此长期保留；`tests/verify-deck-repo-resolve.js` 注入的等候口在产品侧租约落地后可以拆（它模拟的正是产品行为，租约落地后产品自己会拿住进程）。
5. **判定契约要完成证据，不只看退出码。** 一次检查必须能自己证明「我从头跑到了尾」；链执行器对已开闸的门禁要求「退出码 0 + 完成记录存在 + 断言数与登记一致」（落在 #1158）。

## 3. 被否掉的路

| 方案 | 为什么不选 |
| --- | --- |
| 甲：把那五处 `unref` 删掉，让等待自己留住进程 | 退回 #1114 之前：一笔只为到点提醒的定时器就能决定进程活多久，正是那次要治的病 |
| 乙：助手内部两个方向都补（有被引用就 `ref`、没有就 `unref`） | 实测会把门禁打得更差：拆掉把手的 `tests/verify-deck-no-hang.js` 只剩 **0 条**断言（今天的助手 12 条、只补 `ref` 21 条）。对称不是「更正确」，是主动把泵 `unref` 给产品的那一手 |
| 丙：把 no-hang 的把手当临时物，修完就拆 | 门禁的完成就押在助手的记账上——这次事故正是记账出错，等于把测试的生死交给被测对象 |
| 丁：用轮询或心跳定时器保活 | 白烧 CPU；存活是「有没有停在跑的活」这个事实，不需要周期性确认 |
| 戊：顺手重构助手队列的数据结构（换成最小堆） | n 是几十，实测无瓶颈。教科书上更优的结构不等于今天该做的改动，等有实测数字再单独立票 |

## 4. 代价与已知限制

- 多了一个公共原语（一个文件，约三十行）：以后「让进程活着」有了固定写法，但要求调用方记得套——漏套就是老毛病复发。缓解：五处竞速一次改齐，并留一条门禁盯住这次因果（拆掉注入的等候口之后 `tests/verify-deck-repo-resolve.js` 仍然 13 条）。
- 租约靠一支被引用的长延时 `setInterval` 句柄实现（Node 没有「引用事件循环」的公开 API），这是机制性代价，写在文件头注释里。
- 助手侧的不变量只能靠一条子进程回归测试顶住：「提前收摊」这种失败跨进程才观测得到，进程内看不出来。
