# ADR：悬停提示锚定在触发控件上方，方位收回控件内部（规格 #1651，#1653）

> 日期：2026-10-29 定版（规格 #1651 第二张实施票 #1653）
> 地位：悬停提示几何归属的定版结论。凡与本文冲突的旧悬浮实现、定位参数、翻转阈值，以本文（更新日期者）为准；未来任何讨论若改动本契约，以未来版本为准。
> 关联：#1651（规格）· #1652（地基票：方位纯函数 tipPlace 落盘）· #1653（本票：锚定上方、删调用方定位参数、时间改 400）· #1660（宽度口径修正：上限改按渲染外框宽）· 地基产物 src/client/views/primitives/tipPlace.ts · 门禁 tests/verify-hovertip.ts

---

## 1. 背景

HoverTip 从 G2（2026-09-01）起同时承载两档跟随：anchor 读触发控件矩形，mouse 跟鼠标坐标。调用方还要逐个传 mode、placement、offset、flip、caret 五组定位参数，翻转阈值按字数估宽（estW = maxWidth + 16 + 2 = 238），小三角随翻转同步变向。三年实践下来三处痛：

- 鼠标跟随的提示会盖住鼠标正指着的那一格，在办表这类信息密集的行里，想看的原文正好被提示挡住；
- offset 按 anchor、mouse 分档手写（{8,0} 与 {14,12}），每新增一处调用就要抄一遍分档，改一处易漏另一处；
- 字数估宽在中文与混合内容下量不准，量错了翻转阈值跟着错，窄屏与屏幕边缘要靠 caret 翻转去救，越救越复杂。

地基票 #1652 已经把「落在触发控件哪一边」抽成独立纯函数 tipPlace：只吃数字、只出数字，不读 DOM，不读 window，屏幕宽高由调用方传进来，五步按上方、下方、右侧、左侧、保底的顺序试，两条不变式对任何输入都成立（提示不越出屏幕，提示不盖住触发控件）。本票把调用侧收尾。

---

## 2. 决策

### 2.1 方位从调用方收回控件内部

- 调用方只给内容与触发节点：content、children、maxWidth、visible 与受控回调、appearance（padding、style、className、background、border）、targetRef。mode、placement、offset、flip、caret 五组定位参数从 Tip 与 HoverTip 的收参里整组删除，调用处逐个清掉，只删参数，不改内容与布局。
- 提示一律先锚定在触发控件上方，屏幕边缘与窄屏由方位纯函数让位。调用方不再决定提示落在上下左右，也不再决定翻不翻转。
- 自定义触发节点（状态栏胶囊、状态栏分段、在办表徽标、子工作区标记）不改文件：HoverTip 取鼠标进入事件的真实元素（currentTarget 或 target）量矩形，引用只做兜底。克隆引用拿不到真实 DOM 的位置，事件元素才拿得到。

### 2.2 几何独立纯函数，控件先量后算

- tipPlace 住在 views 叶子，不进内核：它是提示控件自己的零件，不是全仓共用的基础设施。几何算得对不对脱离浏览器就能证明，门禁 tests/verify-tip-place.ts 用合成数字穷举边界（#1660 起覆盖带小数外框宽、带小数外框高、200 像素窄屏与居中偏差等边界，断言数见门禁运行输出）。
- HoverTip 按固定顺序调纯函数：触发控件矩形、量出的提示尺寸、屏幕尺寸、宽度上限，四位少一位、多一位、换一位，门禁按正则判红。
- 先量后算：提示先按宽度上限渲染，再读 getBoundingClientRect() 的外框宽（带小数）与外框高得到真实尺寸，拿真实尺寸算落点，挂上屏后下一帧重算。字数估宽（length 乘 7）与 estW 中间变量整段删除，量不到时按上限宽与一行高占位，不抛异常。#1660 起不再读整数化的偏移宽高：排位、限宽与量尺寸必须共用「渲染外框宽」这一个口径，两个口径并存会让算出来的位置与画出来的盒子对不上。
- 返回的坐标一律是提示左上角，渲染处不再加中心位移（translateY(-50%) 删除）；返回的生效宽度上限必须拿去限宽，否则量出来的尺寸和定位用的尺寸对不上。

### 2.3 宽度与时间

- 默认渲染外框宽上限 320（原来 220），调用方可覆盖；在办表那一行保留 520（默认装不下完整标题与会话名）。这里的「宽度上限」指渲染外框宽，含左右内边距与边框：提示按 box-sizing: border-box 渲染，所以正文宽 = 上限 − 内边距 − 边框（320 时约 294 像素，520 时约 494 像素）。生效宽度取调用方上限与屏幕可用宽度的较小值，窄屏自动收窄，夹取逻辑只住在纯函数里，调用方不许重复写。夹取时先把目标坐标取整、右边界向下取整，带小数的外框宽才不会把右缘顶出屏幕。
- 显示延时 400 毫秒（原来 500），隐藏延时 160 毫秒不变。时间真源住在 config/intervals.yaml，Tip 顶部经 values.js 真引用，构建剥行首拼闭包；改时间只改 YAML。本票确认 tests/verify-time-config.ts 按键锁引用关系，没有字面量锁，不用改那份门禁。

### 2.4 门禁跟着契约走

- tests/verify-hovertip.ts 按 #1653 重写：删掉 estW、maxWidth 220、flip 默认、offset 分档、caret、mode=mouse 迁移检查六组旧断言；换成锚定上方、纯函数四参顺序、先量后算、不越屏、不盖控件、107 处调用点无定位参数五组新断言。不能只删不加。
- 产物不断言 estW、caret、clientX 的有无：配额、弹窗三角、标签页自画提示另有主人，真源干净即可，产物只断言同一份行为（portalTop、zIndex、computeTipPlace、量度、真实元素、320）。

## 4. 后果

- 正向：新增提示只包一层 Tip，不再有人抄定位参数；窄屏与边缘行为由纯函数断言锁死（断言数见门禁运行输出），不依赖真机走查；时间只改 YAML 一处。
- 代价：tests/verify-1082-work-route-table.ts 里三条旧断言（placement 透传、HoverTip 含 placement、Tip 透传 placement）与新契约冲突，本票按分工不改那份门禁，留给收口处理。
- 风险与缓解：调用点扫描用 props 对象提取（花括号配平，tipProps 经变量顺藤），declare 行与类型引用取不到对象自然落选；产物里 estW、caret、clientX 另有主人，门禁只看真源，避免误伤。
