## 1. 背景：顶栏有身份，为什么页内还要再要一次

2026-10-23 维护者拍板把地图详情页做紧凑：不再展示正文详情，标题成为进入 issue 详情页的入口；同时删掉页内「地图 / 规格 + 编号」身份行，理由是顶栏的面包屑与身份小签已经写着同一个编号（提交 a3014b1d9）。那次改动让方法论自洽——编号在页面里只出现一次。

2026-11-01 报告人（维护者本人）在真实使用里报出 #1803：规格 MAP 详情页的档案区标题只有标题文字，看不出这是「规格」这种容器、也看不出编号；他要求在标题前补「地图标志 + 规格文字 + 编号」，随后拍板半包围版式（Q1=A、Q2=与标题同一行在左、折行从标记下方走过、Q3=顶栏保留）。

分诊复核发现了比「个人偏好」更强的依据，三方证据指向同一结论：

- **设计验收**：`docs/design/1286-implementation-map-visual.md` §6 原文写着「点进规格：结构与探索地图详情页一致；……编号徽章蓝」；:137 也写明「编号徽章蓝」。2026-10-23 删身份行时只改了代码，没有同步这份验收。
- **共享徽标契约**：#1564 的 `src/client/views/shared/ticketBadge.ts` 文件头把「地图 / 规格详情页头」列为 badge 显示点（与列表行、票详情页头同级），并记着 #1301 那次「地图详情页头画的是裸号 #00，跟别处对不上」的教训。但 V2 详情页活页上根本没有徽标——契约点的名与真实页面不一致。
- **入口与落地页不一致**：点进档案后看到的 issue 详情页头有「徽标 + 标题」，而档案入口卡片没有。

所以这次不是「换个口味再试一次」，而是把 2026-10-23 那次顺手删掉、却与设计验收和徽标契约都对不上的那一格补回来；同时用可复用的共享画法，避免再造第五份徽标。

## 2. 裁决

**决定一 · 在档案区标题前放身份标记，与标题同一行、在左侧。**

- 标记内容固定三样：地图图标（`Ic({ n: 'map' })`）+ 容器词（`list.mapChip`「地图」/ `list.specChip`「规格」，按容器种类从 kernel 中央表 `CONTAINER_CHIP_LABEL_KEY` 取，不在别处再留一份词表）+ 编号徽标。
- 版式是半包围：标记向左浮动（`float:left`），标题文字沿它右侧排，折行时从标记下方走过；标记只占第一行的左侧一小块，不额外占一行。标题末尾的「档案 ›」小签保留。
- 为什么不放独立一行（分诊 Q2 的 A1 方案）：那会在紧凑档案区里多占一行高度，且标记与标题的阅读路径被拉开；维护者拍板要「标题第二行出现在这个标记下面」的半包围感。
- 为什么不并进 h1 行内前置（A2 方案）：行内前置在折行时会把标记留在第一行行首、标题从标记右侧余下的窄列往下排，文字被挤成很窄的一条；浮动方案让标题第二行起用满整行宽度。

**决定二 · 编号走 #1564 共享徽标契约，身份色走 CONTAINER_ACCENT 唯一真源。**

- 编号徽标不自己拼「#编号」：调用 `ticketBadgeOf(h, { surface: 'badge', key, effortId })`，目录与编号的拼法（`#目录/编号`）、悬停完整串、宽度上限全部由 `src/client/kernel/ticket-label.ts` + `ticketBadge.ts` 负责，与列表行、票详情页头、在办表首列、状态栏胶囊同一画法。
- 容器身份色运行时取 `CONTAINER_ACCENT[kind]`（规格蓝 / 探索紫），由档案头放进 `--m2v2-id-accent` 交给样式；不在这一层写颜色字面量（`tests/verify-container-colors.ts` 也零容忍任何源码里的身份色字面量）。
- 容器词用 caption 令牌、中性色，不抢编号的视觉重量。

**决定三 · 两种主题都要读得清：身份色往「看得清」的方向混一档。**

- 规格蓝当 11px 小字在深色面板上只有约 2.6:1（#1286 §3.3 记过这笔账），探索紫在浅色暖纸上同样不够。所以徽标色用 `color-mix` 做一档调整：深色主题往白里提（55% 身份色 + 45% 白），浅色主题往黑里压（68% 身份色 + 32% 黑）。
- 浅色判断沿用页面已有的 `body:not([data-ds-dark-theme])` 选择器，与同一文件里 `.m2v2-page` 的浅色覆盖同一套判据。
- 这是本票范围内的读法修正；顶栏容器小签在浅色主题下的对比度问题是既有隐患，另开票处理，不在 #1803 里顺手改（改动面与回归面都不同）。

**决定四 · 模型带两格，页面把目录短名传进来。**

- `MapProfile` 增加 `badgeKey`、`badgeEffortId` 两格；`mapProfileOf` 增加第四个可选参数 `effortId`，由页面的 `effortOf(m)` 传入，页面在 `mapDetailPageModelOf` 的 inputs 里带上 `effortId`。
- 容器词不进模型：它由档案头按容器种类从 kernel 中央表 `CONTAINER_CHIP_LABEL_KEY` 取。模型不 import 运行时中央表（它同时要被门禁直接 require、又要当构建叶子拼进闭包，只能 import 类型），但再抄一份词表就成了同一个值的两处定义（见 `docs/adr/20261021-config-ownership.md` §2.1）。
- `badgeKey` 优先取快照行的 `key`，没有就退回 `number`；两格都空时是 `null`，页面不画空徽标。

**决定五 · 门禁与注释、文档同步改成新行为。**

- `tests/verify-map-detail-v2.ts` 第 14 条从「页内不重复身份行」改为「标题前有身份标记，与标题同一行在左，标记浮动、标题折行从它下方走过」，并新增模型两格、header 源码（容器词取中央表）、样式（float / color-mix / 浅色覆盖）断言。
- `tests/verify-map-first-frame-freshness.ts` 加 5 条真实渲染断言：图标、容器词（地图 / 规格两种）、徽标契约的编号文本（编号尾巴 `/100`、`/700`）、身份标记排在标题文字前。
- 四处写死「页内不再重复身份行」的注释（档案头、模型、样式、契约类型）与设计文档 §6 同步更新，并指向本文。

## 3. 影响与迁移

- 改动的源码：`MapProfileHeader.ts`（身份标记 + titleNode 版式）、`MapDetailV2Styles.ts`（标题与身份标记样式）、`mapProfile.ts`、`mapDetailTypes.d.ts`、`mapDetailPageModel.ts`、`MapDetailV2Page.ts`（传 effortId）。
- 门禁：`tests/verify-map-detail-v2.ts`、`tests/verify-map-first-frame-freshness.ts`；归属表 `scripts/gate-map.mts` 的期望条数随之更新。
- 文档：本文 + `docs/design/1286-implementation-map-visual.md` §6 补遗。
- 不改顶栏：面包屑「列表 / #编号」与「地图 / 规格」小签保留（分诊 Q3）。它不是重复——顶栏回答「我在导航树的哪里」，页内身份标记回答「我正在读的是哪张图」，两者服务不同的阅读动作。
- 已知边界（不在本票范围）：①窄窗时顶栏折叠机仍会先裁面包屑编号（`issueDetailFold.ts` 的阶梯顺序），是否把编号留在最后另开票；②浅色主题下顶栏容器小签与探索紫徽标的对比度另开票；③不恢复 2026-10-23 删掉的正文抽屉。

## 4. 被否掉的路

| 方案 | 为什么不选 |
| --- | --- |
| 维持现状关票（Q1=C） | 设计验收（#1286 §6 的「编号徽章蓝」）与共享徽标契约（#1564 把详情页头列为显示点）都要求这一格存在；报告人在真实使用里也确实认不出容器与编号。现状不是「文档已同意」的状态，而是文档与代码互相矛盾 |
| 只强化顶栏、页内不动（Q1=B） | 顶栏是 sticky 的滚动上下文，但它的编号是 11px 灰字，和标题隔着一段距离；读标题时需要就地认出「这是什么容器、第几号」，改顶栏字重解决不了视距问题，且要动顶栏折叠机与两处共用组件，回归面更大 |
| 独立一行放在 h1 上方（Q2=A1） | 紧凑档案区里多占一行高度，且标题与标记被拆成两段阅读路径；维护者拍板半包围 |
| 并进 h1 行内前置（Q2=A2） | 折行时标记留在第一行行首，标题从右侧余下的窄列往下排，行宽被挤得很窄；浮动让第二行起用满整行 |
| 自造号码样式（自己拼 `'#' + key`、自己写 maxWidth） | 正是 #1564 点名禁止的反例；会造成与其它显示点不一致（#1301 画成裸号 `#00` 的教训） |
| 在样式里直接写身份色或另定一套颜色 | 违反 #1296 / `tests/verify-container-colors.ts`：身份色的唯一真源是 `CONTAINER_ACCENT`，源码不许写字面量 |
| 顺手把顶栏身份小签也去掉，只留页内一份 | 顶栏同时承担面包屑导航与「新会话 / 复制 / 外链」等动作的定位上下文；删掉身份小签会让顶栏无法一眼区分地图与规格，且改动面扩到共用组件 |
