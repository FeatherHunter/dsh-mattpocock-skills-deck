# ADR：UI 遵守「布局零抖动」，测量与变更分相（2026-09-11 定版）

> 日期：2026-09-11 定版
> 地位：本决策给面板渲染定下一条可验收的纪律，来源是 #602「布局零抖动」（证据、实测数字与全仓排查见该票）；承接 `docs/reviews/601-panel-first-open-latency.html` 与 `docs/reviews/603-panel-first-open-5s-handoff.html` 的调查过程。
> 版本与效力：本文件落盘后，凡与本决策冲突的旧写法/讨论，**以本文件（更新日期者）为准**；未来任何讨论若改动本决策，**以未来版本为准**（CONTEXT.md 同款两条规则）。

## 1. 背景（第一性原理）

浏览器的硬规矩：**布局一旦被改脏，任何一次读取尺寸都会当场把布局重算一遍**才能给出数值（`offsetWidth`、`clientWidth`、`scrollWidth`、`getBoundingClientRect` 都是这类读取）。

于是「写一次样式 → 读一次尺寸 → 再写 → 再读」这种交替写法，会把一次渲染变成几千次强制重排。现场就是这么发生的：标签折叠要按面板实际宽度决定每行显示几个标签，原写法在同一个循环里读一次 `offsetWidth`、紧接着写一次 `style.display`，循环次数 = 行数 × 每行标签数。

真机实测（右侧面板**强制刷新后第一次**点开）：

| 量的是什么 | 修复前 | 修复后 |
| --- | --- | --- |
| 渲染起点 → 提交结束 | 4948 ms | 117 ms |
| 其中标签折叠用掉的 | 4911 ms | 81 ms |
| 浏览器「长动画帧」账本记到的强制布局 | 4824 ms | 76 ms |
| 点击 → 内容可见 | 5075 ms | 193 ms |
| 对照：建 9047 个 DOM 节点 | 13 ms | 14 ms |

对照行说明了问题不在建节点：**慢的全是强制重排**。同一次打开里的第二次渲染只要 13 毫秒（折叠结果按内容指纹缓存跳过），这也解释了为什么「关掉再点开」一直很快——只有刷新后第一次才会重跑折叠。

## 2. 决策

1. **UI 代码遵守「布局零抖动」**：同一次同步执行里，布局只允许被重算一次。
2. **把写样式与读尺寸分成两个相位**：**测量相**只读尺寸、不写任何样式；**变更相**只写样式、不再回头读。需要先把元素摆成「可量状态」的写操作单独成一段，放在测量相之前，不与测量混在同一段里。跨相就是违规，违规名叫**量改交替**（表现是**重排风暴**）。
3. **要不要动手，看循环次数会不会随数据量放大**：会随数据量放大（行数 × 每行元素数）的必须改；次数固定的（标签栏约 6 个、状态栏胶囊个位数）**不动**——不为守纪律制造无谓改动。
4. **改动必须证明结果等价**，不能只有「看起来没问题」：把旧实现冻结、新旧同场对跑，逐行比对**结果状态**（显示还是隐藏、文案、由版式反算出的尺寸），全部一致才可合。
5. **等价的前提要写进代码注释**，让后来的人知道为什么可以这么改。本次两条依据：单个标签宽度只由自己内容决定（`.dsws-tags .dsws-chip{flex:none}`）；行宽由外层容器决定，与行内编号是横排还是竖排无关。

## 3. 备选与取舍

| 备选 | 否决理由 |
| --- | --- |
| 只做「先出空壳、内容随后」就收工 | 只把等待挪到点击之后，总工作量没变（黑壳子挂 6 秒）；它用于止血，不能替代本条 |
| 列表分片渲染（先画一屏、其余分批补） | 能改善观感，但把成本摊开而不是删掉，还要引入批次状态、筛选后批次复位、新批次重新测量三处新坑；定位到根因后不再需要 |
| 改用虚拟滚动 | 改动面与回归风险远大于本条；本案不需要（建 9047 个节点只要 13 毫秒） |
| 只加 CSS 布局隔离 | 隔离不改变「读一次就必须重算一次」这条规矩，治不了量改交替 |

## 4. 后果与边界

- 面板首次打开从 5.1 秒降到 0.19 秒（真机实测）。
- 本纪律适用于本仓库所有插件 UI；对其他 DSH 插件同样成立——这是浏览器规则，不是插件规则。DSH 插件还有一个放大器：插件把成百上千个节点放进与外壳共享的同一份文档，强制重排按整棵文档收钱（同一段代码真机比本地小页面贵约 20 倍）。
- 本仓库同类毛病只找到两处（`src/client/views/shared/tagsFit.js`、`src/client/views/ListTab.js` 的地图行适配）；其余 47 处读取点循环次数固定、或一次只测一个元素，按第 3 条**不动**。
- **不覆盖另一类问题**：宿主侧同步阻塞（`gh` 子进程占住宿主事件循环，导致所有宿主调用被推迟）。那是另一类毛病，另行处理。

## 5. 验证

- **真机判据**：必须**强制刷新**后第一次点开（内存里的内容指纹被清空才会重跑折叠，只关掉再打开是量不到的）；看测点 `commit` 与 `fit` 的毫秒数，以及浏览器「长动画帧」账本里的强制布局时长。
- **等价判据**：新旧实现同场对跑、逐行比对结果状态。本次两组对照实验脚本在本机 `.scratch/tagsfit-bench/`（未入库，脚本依赖本机路径）；复现时按同一做法搭即可，做法与逐行比对的口径写在 #602 正文里。
- **门禁**：`npm run test` exit 0。
