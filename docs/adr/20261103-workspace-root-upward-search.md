# ADR：工作区根只认一份工作区文件、逐层往上找（#1806 纠正）

## 1. 背景（为什么把上一版决定撤掉）

- 2026-11-02 的上一版决定（`docs/adr/20261102-workspace-identity-records.md`）为了把「是不是工作区根」变成可验证的事实，新增了两份插件记录：身份记录 `docs/agents/workspace-root.yaml` 与从属记录 `docs/agents/workspace-member.yaml`，并让「工作区已初始化」这条检查改看身份记录。
- 落地后暴露出三个问题：
  1. **多出了用户没要求过的文件。** 一个工作区本来只需要一份 `docs/agents/workspace.yaml`（记录「这个工作区用哪个后端」），上一版又加了第二份、第三份；对用户来说这是同一件事被拆成三份文件，难以理解，也没必要。
  2. **「已初始化」被错挂到新记录上。** 新记录只有初始化流程与「标为独立工作区」两个写入点；老工作区从没写过它，升级后一律显示「该工作区尚未初始化」，而它们的 `docs/agents/workspace.yaml` 明明在、初始化也早就做完了。这条提示对老工作区是误报。
  3. **判定需要额外的人工动作。** 新机制把「标为独立工作区」「并入上级」做成设置页按钮，又要求子目录写入或删除记录才能改变归属；这等于让用户去维护插件内部的身份状态，而正确的关系应该从磁盘上已有的文件直接推出来。
- 维护者的判断（2026-11-03）：不需要第二、第三份记录，也不需要存「父工作区」这种字段——没有人能在创建根工作区时预知未来会在哪个子目录打开工作区。正确的逻辑是：打开一个目录时，**往上逐层找那份已经存在的工作区文件**，找到就说明自己是它的子工作区；找不到，自己就是这一层的工作区。

## 2. 决策（定版机制）

1. **工作区根**：从会话所选目录开始，逐层往上（先看自己这一层，再看父目录、祖父目录……），第一个自带 `docs/agents/workspace.yaml` 的目录就是工作区根。一路到盘符根、文件系统根或 UNC 共享根都没有 → 工作区根就是所选目录本身。
2. **子工作区**：命中的那一层在所选目录之上 → 所选目录处在一个子工作区里。界面显示「属于 X 工作区」，**不提示初始化，也不写任何文件**。
3. **只有一份文件参与认根**：`docs/agents/workspace.yaml`。它回答两件事——「这一层是工作区」与「这个工作区用哪个后端」。认根只看它在不在，不读内容：空文件、内容写坏了、那个位置是个目录，都照样算。
4. **`.git` 不参与认根。** 理由见第 3 节。
5. **`docs/agents/issue-tracker.md` 不参与认根。** 它是人按模板写下的「这一层用哪个后端」的说明，可以由用户随手写、随手改；把它当身份凭据正是 #1806 要修的错。它继续被读来回答「用哪个后端」。
6. **「工作区已初始化」检查的判据**：工作区根上有 `docs/agents/issue-tracker.md`。不拿 `workspace.yaml` 当初始化凭据——它在「选定后端」这一步就会写下，早于初始化完成。初始化流程本身不写任何新文件。
7. **删除**：身份记录 `docs/agents/workspace-root.yaml`、从属记录 `docs/agents/workspace-member.yaml`、它们的读写代码与电话（`wf.ensureWorkspaceRecord` / `wf.markWorkspaceRoot` / `wf.workspaceFacts` / `wf.joinParentWorkspace`）、设置页的「标为独立工作区」「并入上级」按钮、面板里「根部判定依据 / 历史归位」那几行，全部删除。旧版 `docs/agents/workspace.json` 不算标记，只保留一次兼容读。
8. **不新增任何字段**：不存父工作区、不存 scope、不存角色。父与子的关系在每次打开目录时由磁盘上的文件现算，不落盘。
9. **随包脚本**（`scripts/wire-subissues.mts`、`scripts/fix-issue-body.mts`）与宿主同一规则：只往上找 `docs/agents/workspace.yaml`，不认 `.git`、不认从属记录。
10. **边界**：到盘符根／POSIX 根／UNC 共享根停止；经过 junction 或软链按真实路径去重，防止绕圈；路径写法先归一（大小写、斜杠、尾斜杠）；读目录权限失败按「这一层没有」处理，继续往上；普通目录里误放一份 `docs/agents/workspace.yaml` 会被当成一个独立工作区（「文件在哪，工作区就在哪」的直接代价，可接受）。
11. **缓存**：根判定结果按所选目录缓存 30 秒；`workspace.yaml` 被写下之后立刻清掉这份缓存，否则子目录最多 30 秒仍会显示旧的归属。

## 3. 为什么这样做

- **事实在磁盘上，不靠人维护。** 一份 `workspace.yaml` 已经说明了「这一层是插件的工作区」；往上找就能推出归属，不需要第二份记录、按钮或迁移。
- **父与子是打开时算出来的，不是存下来的。** 存 parent 字段会在目录移动、复制、改名后过期；往上找每次都对。
- **子目录只读不写。** 打开子目录不会在磁盘上留下任何新文件，也不会因为「忘了加记录」而让归属漂移。
- **一份文件承载所有需要的信息。** `workspace.yaml` 同时回答「是不是工作区」与「用哪个后端」，两个问题的答案天然同源；拆成三份文件只会增加不一致的机会。
- **`.git` 不参与认根，对三种后端一视同仁。** GitHub／GitLab／本地 Markdown 都可能有 `workspace.yaml`，而 `.git` 只属于前两种；本地 Markdown 的工作区可以没有 git。GitLab 的同一个项目可以在本地有多份克隆与 worktree，`.git` 会让它们各自成根；子目录里任何一份 `.git`（嵌套仓库、子模块、worktree 文件）还会截断上溯。因此 `.git` 既不是工作区的必要条件，也不能当标记。
- **`workspace.yaml` 不能当「已初始化」的凭据。** 面板为工作区选后端时就会写下它，这一步是初始化的前置门，早于初始化本身；拿它当凭据会把「选了后端但还没初始化」误报成已初始化。初始化产物是 `docs/agents/issue-tracker.md`（以及后续的标签、领域文档），检查看它。
- **升级后的老工作区不会再误报。** 只要该工作区曾经选过后端，`workspace.yaml` 就在，往上找立刻得到正确的根与归属；「工作区已初始化」看回说明文件，老工作区只要初始化过就是绿的。上一版决定的「升级后老工作区会重新看到一次初始化提示」这个代价随之取消。
- **删除的两份记录不迁移也不改名。** 机器上若残留 `workspace-root.yaml` / `workspace-member.yaml`，它们不参与任何判定，可以随时手动删除；不静默迁移，也不伪装成新格式。

## 4. 后果

- 工作区根只由 `docs/agents/workspace.yaml` 决定；同一层同时有 `.git` 与 `workspace.yaml`，判定回报 `record`（依据仍是那份文件，`.git` 不参与）。
- 老工作区里残留的 `workspace-root.yaml` / `workspace-member.yaml` 变成普通文件，判定忽略；面板不再显示「标为独立工作区」「并入上级」两个按钮，也不再显示「判定依据」那几行。
- 一个从没初始化过的 git 仓库，在它的子目录里打开会话并初始化时，工作区会落在那个子目录（因为往上没有 `workspace.yaml`）。等那一层写下 `workspace.yaml` 之后，它的子目录自然归它。这是「不猜上级」的代价，与本次定版一致。
- 子目录会话与根会话仍然共享同一份工作区级数据（面板、后端选择、检查链快照、仓库引用），这一条与 #649 的结论一致、不变。
- 日志：`workspaceRoot.resolve` 事件名、级别、字段名、采样口径不变；`source` 取值只剩 `record` / `self` / `fail` / `no-fs` / `no-probe` / `empty` / `relative`（`git`、`anchor` 删除）。四条工作区电话删除后，`research/489-appendix.md` 第 1 章对应补记同步更新。
