# ADR: 会话命名分档契约与存量回填否决

日期：2026-08-27 生效（效力规则见 CONTEXT.md「版本与效力」，后续冲突以更新日期者为准）

状态：已采纳

关联：#257 会话命名治理二期（map）、#258/#259 研究结论、#260 分级命名契约定版、#261 范围裁决、#263 一期落地

## 背景

#211 双通道改名机制中的 host watcher 三 handler 在 e98f636 重构中被静默删除且无替身，前端兜底轮询亦不扫描会话文本，导致凡由 AI 在会话内自行 gh issue create 的主流程零事件、必然超时，会话列表成片滞留 [New] 占位名。研究进一步证实：宿主无会话枚举/改名 API、无 LLM 通道，且任何半区都读不到历史对话文本。

## 决策

- D1 分档命名：P0 占位（不变）→ P1 [草稿] <语义段> → P2 [#n] <issue 标题>（承接 #204/#205 契约，前缀永不破坏）→ P3 精修（契约预留位，限 1 次，实现分期至二期）。
- D2 分工：host 常驻任务持跟踪状态（落盘 .dsh-mattskillsdeck-cache，重启可续、面板未开不丢账）；Web 渲染钩子发现待办并代执行 face.rename。
- D3 手改锁定：值比对真检测（当前标题 ≠ 机器最后写入值 ⇒ 判手改 ⇒ 永久免机器改名），替换 #211 遗留的 userRenamed 死代码。
- D4 存量不回填（#261 裁决）：已滞留的占位会话保持现状，由用户自行处置，不立项一次性回填；本图治理只面向此后新建会话。
- D5 回填重访既定口径（若未来推翻 D4 直接沿用）：判定仅精确匹配四占位串、不加时间窗；目标名取面包屑语义线索分级拼 [草稿] <线索>，无线索裸档；无状态天然幂等，拒绝记账清单；执行并入当期落地票作首次启动自动迁移。

## 后果

+ 新会话不再向列表倾倒无法辨识的占位名；编号档恢复可点击定位 issue 的价值。
- 存量占位名将长期留存于列表（D4 既知代价，用户知情接受）。
- 会话文本不可读使 P1 语义段降级依赖面包屑线索，无线索会话呈裸档——P3 精修二期为既定的质量补完位。
+ 恢复建号感知附带强制防回归测试，杜绝 e98f636 式静默能力删除再次发生。
