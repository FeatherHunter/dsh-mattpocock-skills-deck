## 1. 背景

版本管理页的能力范围已经从 2026-10-02 / 2026-10-04 的第一版最小集，扩到 #1586 的 162 条能力（119 条操作、36 条只读、7 条只读说明，有操作或只读落点 155 条）。三处能力与旧 ADR 的绝对口径直接冲突：

- docs/adr/20261002-version-control-readonly-no-network.md 的 §2 决策第 1 条写「第一版只读视图不发起任何网络动作」，§5 写「侧栏终端是这一版唯一被承诺的联网出口」。能力 8.4 要看远端分支与标签，强推前的租约基准也要读一次远端；照旧口径做，这两件事都做不了。
- docs/adr/20261004-version-control-write-path.md 的 §6 写「不保存凭据、不改用户 git 配置」，§1 与 §8 还把写路径的最小集和「一律不做」清单写死。能力 12.2 / 12.3 / 12.4 要改提交身份两个键，能力 11.8 要用 maintenance start / stop / register 写维护配置与调度器；照旧口径做，配置页和维护页只能永远只读。

直接改两篇旧 ADR 会把历史决策和今天的边界混在一起，也不符合仓里「旧 ADR 加取代声明、不改正文」的惯例。所以另写这一篇，把三处例外逐条钉死。

第一性原理只有一句：版本管理页只是帮人操作一个 git 仓库的界面，它不替人保管凭据，不替人执行任意命令，不在人没点的时候动仓库或网络。每一个写动作都必须同时满足四件事：人明确发起；执行前能看到将要改什么；执行后能核对真实结果；失败不假装成功。本文的三处例外，是在这四件事不动的条件下，把旧 ADR 的绝对口径收窄成「只开这一处、只按这个形状」。

|---|---|---|---|---|

## 3. 三处例外共同遵守的边界

### 3.1 只做 git 原语

只用 git 自己的子命令完成这三件事，不执行任意命令，不调用外部窗口，不输入或保存任何凭据。#1586 的三类永久例外继续有效：任意命令执行不做；秘密不输入、不保存、不落盘、不进日志；外部窗口与平台 API 不做。本文不开放第四类例外；将来要再开一处，必须先另写 ADR，不能在这份文件里临时加一句。

### 3.2 只有用户明确发起才执行

默认行为仍是本地、只读、不联网。三处例外都只在用户点击并确认后发生：没有定时器，没有后台预取，没有自动重试，没有「刷新一次就顺手联网」。8.4 的界面必须把联网动作标成「需要联网」；12.2 / 12.3 / 12.4 与 11.8 的确认卡必须写清这次改的是哪个作用域、会影响谁。

### 3.3 写动作先过票据，读动作也要有明确请求

12.2 / 12.3 / 12.4 与 11.8 是写动作，一律沿用现有的一次性票据：预检生成票据，票据有效期 120 秒，只代表预检时的状态；执行前重新读取票据绑定的状态，不一致就拒绝并让人重看。票据不落盘，结果表只存进程内存，requestId 用于重放去重。票据失效时一个进程都不许起。

8.4 是只读动作，不签发写票据，但也必须是显式请求：同一远端同一时刻只允许一个请求在飞；用户连续点击时复用进行中的请求，不排队、不设定时器、不自动补一次。强推前的 ls-remote 属于写动作的预检，结果绑进写票据（见 6.3），没有票据就不推送。

### 3.4 执行层沿用现有安全边界

argv 直传，不经过 shell；固定前缀与清理环境（GIT_TERMINAL_PROMPT=0、GCM_INTERACTIVE=never、清掉 GIT_ASKPASS / SSH_ASKPASS / DISPLAY、ssh BatchMode 等）按 docs/adr/20261004-version-control-write-path.md 的 §6 执行；stdout 有上限，超过就截断并显式标记；超时由执行层的 timer 杀整棵进程树；新增写命令仍要同步七个登记点，漏掉判定分支就会永远落到 unknown-operation。

### 3.5 审计只记能定位故障的信号

同一用户动作一个 requestId，把预检、执行、结果串起来。日志沿用 git.exec / git.exec.fail 与电话层事件，不新开含义不稳的事件名；字段只记动作名、作用域、键名或远端名、旧状态是否存在、退出码、耗时、输出长度、截断标记、错误类。不记配置值原文，不记凭据或带凭据的远端地址，不记 crontab / timer / plist 文件全文，不记 ls-remote 的完整引用清单。仓库根、配置文件路径这类长值在需要串联时用短指纹，不把整条路径抄进每条日志。

### 3.6 失败必须落到已知分类，不能假装成功

所有失败必须落到现有错误分类；归类不了就显示 git 的退出码与脱敏后的第一行错误，不能把 unknown 当结论。执行后能安全重读的（配置、维护状态、远端引用）必须重读，用读到的真实状态说话；读不到才说结果未知。绝不自动重试、不自动回滚、不把半成功说成成功，也不把「我没读到」说成「没有」。

## 4. 例外一：配置身份两键（12.2 / 12.3 / 12.4）

### 4.1 允许什么

- 只允许写 user.name 与 user.email 两个键，只允许 set 与 unset 两个动作。读用 git config --show-origin --get-all，显示当前值、作用域和旧值；没有值时显示「未设置」，不猜默认值。
- 默认作用域是 --local，只改当前仓库的 .git/config。--global 是另一个动作：单独入口、单独确认，确认卡写明「会影响这台机器上的所有仓库」。系统级（--system）不提供。--local 与 --global 是两个按钮，不是同一个按钮里的下拉项。
- 写入命令按最低版本 git 2.11 可用的形状执行：git config --local user.name <值>、git config --local --unset user.name，user.email 同理；--global 时把 --local 换成 --global。能力矩阵里的 git config set / git config unset 只是动作名，不强制实现只用新版子命令。
- 一个键有多个值时，先把全部值列出来让人选要改或要删的那一条；选不出精确的一条就拒绝执行，让人去命令行处理。不替用户合并、不静默改全部、不猜测「最新一条」。
- 值只接受单行文本；包含换行、回车或 NUL 的值直接拒绝，不写半截。空串与删除是两个动作：空串是一个合法的值，删除必须走 unset。
- 确认卡必须写清：改的是哪个键、哪个作用域、旧值是什么、改后是什么；git 改写配置文件时可能丢掉注释和原有排版，这一点要在卡上明说。--global 时还要写清会影响其他仓库。
- 执行前重新读取该键的旧值与配置文件路径；与票据绑定的状态不一致就拒绝，让人重看。票据绑定仓库根、作用域、键名、旧值摘要、配置文件路径；票据只记录核对所需的状态，不保存值的原文。

### 4.2 禁止什么

- 禁止写 user.name / user.email 之外的任何键；禁止使用 --system、--file、--config-file、--edit、--add，也禁止任何批量写入和通用键值编辑器。
- 禁止直接读写 .git/config、全局配置文件或 include 文件；禁止通过环境变量或命令行别名改道到别的配置文件。
- 禁止改 alias.*、core.*、credential.*、include.*、core.hooksPath 等能执行代码或改变凭据来源的键；这些键仍然只读展示。
- 禁止把 --global 做成默认动作，也禁止在执行时偷偷把 --local 失败降级成 --global；本地写不了就如实失败并说明原因。
- 禁止在日志里记值原文；身份值是个人信息，日志只需要知道「改的是哪个键、作用域是什么、旧值是否存在、结果如何」。

### 4.3 怎么审计

每个动作记一条起点与一条终点：动作是 set 还是 unset，键名是 user.name 还是 user.email，作用域是 local 还是 global，旧值是否存在、是否多值，退出码、耗时、输出长度、错误类。requestId 与票据 id 串起预检和执行；配置文件路径用短指纹记，不记值原文。成功时也记一条「已完成」，让人能从日志看出改的是哪一个键，而不是只知道「有一次写配置」。

### 4.4 失败与取消怎么处理

- 确认前取消：零进程，票据过期即可，没有残留。
- 确认后执行：这是短命令，不提供假的「中途取消」按钮；执行层预算到点会杀进程树。被杀或超时后必须重新读取该键的实际值，按读到的结果说话；读不到才说结果未知。
- 失败分类至少分开：没有权限、配置文件被锁、键或值非法、git 版本不支持、其他。不能把权限失败说成「配置不存在」，也不能把锁冲突说成「已保存」。
- 多值键、非法值、系统级配置这些情况在预检阶段就拒绝，不等到执行时才报错；预检阶段拒绝时一个进程都不起。

## 5. 例外二：自动维护的 start / stop / register（11.8）

### 5.1 允许什么

只允许三个子命令，三者不是同一件事，界面必须分开说清：

- register：把当前仓库加入当前用户的全局维护列表（maintenance.repo），并写入 git 自己推荐的维护配置（包括 maintenance.strategy = incremental（如果之前没设）、当前仓库的 maintenance.auto = false，以及各维护任务的推荐 schedule）。它不安装后台调度器。这个动作只影响当前仓库是否被列入维护列表，不改变调度器是否在跑。
- start：做 register 的全部配置更新，再安装或更新当前用户的平台调度器，让它按小时运行 git maintenance run --scheduled。调度器是当前用户级的、跨仓库的：开启后，维护列表里的所有仓库都会被这个调度器带上。
- stop：停止并清理 git 安装的后台调度器；它不把当前仓库移出维护列表，所以以后再次 start 时这个仓库还在名单里。stop 影响的也是整台机器上的调度器，不只是当前仓库。

命令形状固定为 git maintenance <子命令>，不带 --scheduler，也不带 --config-file；调度器由 git 按平台自动选择（POSIX 的 crontab 或 systemd timer、macOS 的 launchctl、Windows 的计划任务）。git 自己维护的那段调度器配置（POSIX crontab 里的 Git 注释区、systemd timer 文件、launchctl plist、Windows 计划任务）不要让人手工改；start 可能覆盖它，stop 可能删除它，确认卡要写清这一点。

确认卡必须写清四件事：当前仓库是哪一个；这个动作只改当前仓库的维护列表，还是改整台机器的调度器；调度器现在是开还是关；如果失败，哪些部分可能已经生效、怎么恢复。stop 的确认卡尤其要写清：仓库不会被移出维护列表，unregister 不在本面板能力范围内，需要移出名单只能去命令行。

maintenance run（立即运行一次）、11.5 垃圾回收、11.6 清除不可达对象仍走长任务通道，不属于本例外；11.7 重新打包仍是只读。它们不因为本文获得配置写入权限。

### 5.2 禁止什么

- 禁止传 --scheduler 让用户选调度器，禁止传 --config-file 把配置写到别的文件，禁止 --force 或任何绕过 register 检查的开关。
- 禁止 unregister：它不在 #1586 的能力矩阵里，面板不暴露；要移出维护列表只能去命令行。
- 禁止直接编辑 crontab、systemd timer、launchctl plist 或 Windows 计划任务；禁止在 git 自己的调度器区域里加自定义内容。
- 禁止用管理员权限或提权执行；当前用户权限不够就如实失败，指引去终端，不弹系统授权窗口。
- 禁止把 maintenance run / gc / prune 塞进这个例外，也禁止把这三个子命令说成「清理仓库」或「优化所有仓库」这类笼统说法；确认卡要分别写清 register、start、stop 的实际效果。

### 5.3 怎么审计

- 票据绑定仓库根、用户全局配置文件路径与摘要、仓库本地配置文件路径与摘要、maintenance.repo 的当前内容摘要、maintenance.strategy 与 maintenance.auto 是否存在、当前调度器是否存在。执行前重读这些状态，任一不一致就拒绝并让人重看。
- 日志记：子命令是 start / stop / register 中的哪一个，仓库短指纹，maintenance.repo 前后的条数变化，strategy / auto 是否由未设置变成设置，调度器类型与执行前是否存在，退出码、耗时、输出长度、错误类。不记 crontab / timer / plist 全文，也不记整个 maintenance.repo 列表原文。
- 一次用户动作是一个 requestId；如果 git 在一条命令里同时改了配置和调度器，仍按同一条 git.exec 记录，结果里的「部分成功」由读取后的状态说明，不伪造多个成功事件。

### 5.4 失败与取消怎么处理

- 这是组合动作，可能只成功一半：register 成功但 start 的调度器安装失败；start 的配置写了但调度器没装上；stop 停了调度器但清理某一段失败。执行后必须分别读取配置与调度器状态，把「哪些已经生效、哪些没有」逐项说清，不能用一个「失败」盖住全部，也不能用一个「成功」盖住半截。
- 没有自动回滚，也不声称能回滚。git maintenance 没有事务；面板能做的是重读状态、把实际结果说清、把恢复路径（再点一次、去命令行）写出来。
- 没有权限、平台没有对应调度器、crontab / systemd / schtasks 不可用、配置被锁、git 版本不支持：这些在预检或执行失败时分别归类，不合并成「维护失败」。权限不足不提权，平台不支持不伪造降级。
- 确认前取消：零进程，没有残留。确认后执行：短命令不提供中途取消按钮；执行层预算到点杀进程树。被杀或超时后重新读取配置与调度器状态；读不到才说结果未知。

## 6. 例外三：8.4 的只读联网（git ls-remote）

### 6.1 允许什么

8.4 有两条路径，默认路径和联网路径必须分开：

- 本地路径：git branch -r 读本地已有的远端跟踪引用，不联网。界面显示读取时刻与「这是本地记录」的说明，不把它说成远端此刻的真实状态。
- 联网路径：用户显式点击「联网查看」后，执行 git ls-remote 读取远端的分支与标签。按钮或说明必须标「需要联网」；打开页面、切换页签、定时刷新都不自动走这条路径。

命令形状固定为 git ls-remote <远端名> [<引用名>...]，远端名只能从 git remote 的输出白名单里选，引用名由界面上的分支/标签选择器给出，所有参数都是独立的 argv 元素。用户不能自己拼选项；面板自己也不传 --upload-pack、--exec、--server-option 这类能把命令或参数送到远端的选项。

联网结果只用于当前这一屏的查看，以及强推前的租约基准；不写入本地远端跟踪引用，不落盘缓存，不自动转成 fetch / pull / push。成功时标出读取时刻；失败时明说失败，不拿上一次的结果冒充这一次。

强推（8.12）的租约基准走这条只读联网路径：预检先 ls-remote 读远端分支当前提交，票据绑定远端名、分支名和基准提交号，确认卡点名这个基准；执行时用 --force-with-lease=<分支>:<基准提交号>（git 2.30 以上再加 --force-if-includes），永不裸 --force。基准读不到、输出被截断、或者 ls-remote 失败时，不签发强推票据，不推送。

凭据不输入、不保存、不读取助手输出；用用户已经配置好的凭据助手，在非交互环境里跑。需要输入凭据时明确失败并指引去终端登录一次，不弹凭据输入框，也不把凭据写进 URL。

### 6.2 禁止什么

- 禁止把这条例外扩展到 fetch、pull、push 或其他网络命令；它们的联网授权与长任务通道是另外的能力，不在这里。
- 禁止自动刷新、后台预取、定时轮询、自动重试；同一远端同一时刻最多一个请求在飞，用户重复点击时复用进行中的请求，不排队、不补发。
- 禁止把 ls-remote 的结果写成远端跟踪引用或持久缓存；禁止在 ls-remote 失败时用本地旧数据冒充远端真实状态。
- 禁止 --upload-pack、--exec、--server-option、--depth 等能把额外命令或参数送到远端的选项；禁止用户直接输入带凭据的 URL，也禁止把远端地址原文写进日志。
- 禁止把 ls-remote 说成「本地查看」；界面必须区分「本地记录」与「刚联网读到」。

### 6.3 怎么审计

每次联网记一条 git.exec：远端名、引用数量、退出码、耗时、输出长度、是否截断、错误类（没有网络、需要凭据、远端不存在或无权访问、超时、输出被截断、其他）。不记完整引用清单，不记带凭据的 URL，不记凭据助手的输出。强推预检时把票据 id 一并串起来，能看出这次 ls-remote 是为哪一次强推读的基准。

### 6.4 失败与取消怎么处理

- 失败分类至少分开：没有网络、需要凭据、远端不存在或无权访问、超时、输出被截断、其他。没有「部分结果」：输出被截断或读取失败时不显示半份列表，也不签发强推票据。
- 用户关掉面板、切换远端或点取消：杀掉这条请求的进程树，不保留结果；下次打开重新发起，不复用未完成的请求。
- 超时不自动重试，不自动降级到本地旧数据；显示失败原因与「需要联网」的说明，让用户自己决定要不要再点一次。
- 强推预检失败时明确说「没有读到远端基准，不能强推」，不签发票据；这也是失败，不是「稍后会自动再试」。

## 8. 后果、风险与验收

| 风险 | 后果 | 本 ADR 的处理 |
|---|---|---|
| 改全局身份会影响其他仓库 | 用户以为只改当前仓库，结果所有仓库的提交身份都变了 | --global 单独入口、单独确认，确认卡点名影响范围；默认 --local |
| git 改写配置文件可能丢注释与排版 | 用户手写的注释或分组被清掉 | 确认卡明说；只开两个键，不提供通用编辑器；给去命令行编辑的出路 |
| 调度器写入需要平台权限 | start / stop 只成功一半，或直接失败 | 组合动作分开报；重读配置与调度器状态；不提权；给终端出路 |
| stop 影响整台机器且不 unregister | 用户以为只停了当前仓库，或以为仓库被移出维护列表 | 确认卡写清这两点；不提供 unregister；给出命令行恢复路径 |
| 联网读取需要凭据或网络不通 | 用户以为远端没有分支或权限不足 | 失败分类分开；不拿本地旧数据冒充；指引去终端登录一次；强推不发票 |
| ls-remote 输出被截断 | 强推基准不完整，可能租约判断错误 | 截断即失败，不显示半份；不签发强推票据，不推送 |
| 票据过期或执行前状态被别人改了 | 用户确认的状态与实际执行时不一致 | 沿用 120 秒票据与执行前重读；不一致就拒绝，不自动重试 |
| 有人把三处例外读成「面板可以写配置、可以联网」 | 后续实现悄悄扩大范围 | 一次写清允许与禁止；新增例外必须另写 ADR；两篇旧 ADR 顶部有指向本文的声明 |

验收落在这些票上，不靠本文口头保证：

- T24 #1760（配置与钩子）：只允许两个身份键；--local 默认、--global 单独确认；多值要人选；旧值展示；注释可能丢的提示；除这两个键外没有任何写入路径；日志不记值原文。
- T22 #1758（维护、维护任务与危险区）：start / stop / register 的效果分别可见；组合动作部分失败能如实说；权限与平台不支持分别归类；unregister 不暴露；run / gc / prune 仍走长任务通道。
- T18 #1754（远端管理与凭据诊断）：8.4 的本地路径与联网路径分开；联网按钮标「需要联网」；没有自动刷新；强推基准来自 ls-remote；截断或失败时不签发强推票据；不输入、不保存、不记录凭据。
- T05 #1740（长任务通道）与 T06 #1741（执行层补齐与写登记门禁）：三处例外仍走同一套执行层、票据与日志白名单；新增写命令同步七个登记点。
