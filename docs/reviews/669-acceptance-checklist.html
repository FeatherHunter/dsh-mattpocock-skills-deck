对应：#669 第 6 件 · 决策记录 docs/adr/20260921-tracker-choice-precedence.md · 发版 1.7.24

先做这一步：重启 DSH 桌面应用。这次改动里有宿主那一侧（判定顺序），必须重启才会加载新的一份；面板本身刷新页面即可，但宿主不重启就还是旧逻辑。
这次改了哪三件事（都不需要额外设置）：
  • 谁说了算：用户自己在面板上选的后端 > 仓库里那份 docs/agents/issue-tracker.md（AI 写下的声明）> 自动识别。
  • 切完之后做什么：已经初始化过的仓库 → 给 AI 一段「把记录后端的地方对齐到新后端」的指令；还没初始化 → 和黄色横幅那条路完全一样（先问域文档布局，答完注入初始化全文）；仓库还没就绪 → 什么都不注入，只提示下一步。
  • 按不动的按钮不再假装能按：「清除后端选择」删掉了；「迁移」「清空」和 GitLab 变灰、按不动（鼠标停上去有理由）。

场景一 · 已初始化的仓库，从 GitHub 切到本地 Markdown（就是原来那次失败的现场）

  • 前置：该工作区已经初始化过（docs/agents/issue-tracker.md 里写着 GitHub），面板顶部后端标显示 GitHub。

场景二 · 还没初始化的仓库（仓库已就绪），切到 Markdown

场景三 · 还没初始化、而且仓库还没就绪（例如切到 GitHub，但远端仓库还没建）

场景三之二 · 布局那一问：点黄条每次都问，答案按工作区记住（1.7.25）

场景三之三 · 切换后端那条路：也每次都问布局（1.7.28 / #698）

限制为什么怎么办
切换后如果没有让 AI 跑那段对齐指令，仓库里 docs/agents/issue-tracker.md 仍是旧后端 插件不写用户的仓库文件（一直如此）；真正持久的「真相」是文件，靠 AI 去改 把那段话发给 AI 执行一次
用户手动改 docs/agents/issue-tracker.md，面板不会跟着变 「用户的手动选择」优先级最高，而这份选择没有到期时间（决策记录第 4 节攻击 8） 在面板上再切一次；或清掉这台浏览器的缓存（切回「锚文件说了算」）
换一台机器 / 清了浏览器缓存后，面板回到锚文件写的那个后端 用户的选择按工作区存在浏览器本地；跨机器没有同步机制（决策记录第 4 节攻击 2） 在新机器上再选一次，或让 AI 把锚文件改好
点黄条时那张布局小卡每次都会出现，要按一下「确认并继续」 1.7.25 起维护者定的：这样答案永远看得见、随时能改（此前答过就不再问，也就没法改） 不想改就直接确认（预选着上次那一项）
布局这个答案只记在这台机器的浏览器里 换机器、换浏览器、清缓存都会重新问一遍 重新答一次即可；仓库里那份真相是 AI 按注入的话写下的 docs/agents/domain.md
手动改仓库里 docs/agents/domain.md 的布局结论，面板不会跟着变 插件只认那张卡上的选择（它记的是「你答过什么」） 要改就在卡上改一次
本地 Markdown 后端看不见 GitHub 上的旧 issue 「保留」只换指向，不搬数据；切回 GitHub 就又能看见 需要搬数据的话，「迁移」今天没有实现（已置灰）
