# 未来展望（Roadmap）

> 这里写的是方向，不是承诺。计划会随实际情况调整，完成一项勾一项。

## 当前支持

- **GitHub：完全支持**。面板的行级 triage / 修复 / 讨论 / 执行、wayfinder 地图、跨会话 handoff，都围绕它打磨，是现在的主力。
- **Markdown 本地文件：半成品（预览版）**。能用，已知有较多问题，欢迎反馈。
- **GitLab：计划中**。当前版本暂不在支持范围，未来会做。

## 未来展望

### 1. 支持所有项目版本管理后端

今天只完整支持 GitHub。未来的目标是：市面上主流的项目版本管理后端（GitLab、Jira、Linear、自建等）都能接进来，同一个面板、同一套操作。

### 2. 地图详情页面重构

当前的地图详情页是最小可使用的产品：信息全，但布局和节奏还没打磨。重构的方向已经定死，核心理念是“**清晰而模糊的目的地**”：

- **终点清晰、路模糊**：用户永远看得见终点，但通往它的路诚实地盖着未知——就像去泰国旅游，“到泰国”明确，“怎么去”全是待探索。
- **战争迷雾三态**：没画图时全黑；wayfinder 画图后转半黑（地形大概清晰、细节盖雾）；子票推进、关闭，对应区域走亮，连成一条直达终点的亮痕——回头看，亮痕就是认真探索过的领域。
- **存雾**：想过但没走通的分支继续盖雾，不为全亮去走没意义的路——迷雾本身也是信息。
- **视野**：正在推进的票周围一片是亮的，表示正在照亮这一片。

一句话：让看地图像看故事（有终点、有探索、有痕迹），而不是看报表。

完整 spec（含 15 条用户故事与实现 seam）见理念存档 #474，暂不实施，重构时照此取用。

### 3. 技能列表按钮改走“建议的工作流”

状态栏右侧的技能列表按钮，今天点开是直达入口。未来点开会是一套建议的工作流呈现：先做什么、再做什么，一步一步带着走，严格按照 mattpocock 的思想开发，方便用户在使用中思考和学习，而不只是点按钮。

### 4. 小 tips：底部偶尔浮现的经验总结

开发过程中，面板底部会偶尔冒出一句 mattpocock 的经验总结，比如“甜品区”的概念、handoff 适合用在什么场景。不打扰，看到就是学到。
