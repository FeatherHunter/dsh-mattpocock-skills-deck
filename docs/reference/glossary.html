Reference · Glossary

词汇表 — 在本工作区，这些词只有一种意思

来源：codebase-design / domain-modeling / aihero.dev/skills。

工程过程

Skill：一小段锋利的指令，交给 Agent 让它按资深工程师的方式工作；可组合，前一个的输出是后一个的输入。避免：prompt / template

Wayfinder / Map：为“超大、跨多会话、终点在迷雾中”的任务建的共享地图；map 是一张 wayfinder:map 票，决策票是它的子票，跑通后在 Decisions so far 留一句话 gist + 链接。

Grilling / Grill：以拷问式访谈把模糊想法磨锋利的动作；grill-with-docs 会同步锐化领域语言（写 CONTEXT.md + ADR）。

Spec：不访谈、只综合的产物；含 Problem / Solution / User Stories / Implementation Decisions / Testing Decisions / Out of Scope，写入 issue tracker 并打 ready-for-agent。

Tracer-bullet ticket / 垂直切片：切“窄但穿透全层”（schema→API→UI→test）的可演示切片；每票声明 Blocked by 边。

Frontier：blocking 全关、未被认领的开放子票集合；永远只做 frontier 上的事。

模块设计

Module：有 interface 与 implementation 的任何东西。避免：component / service

Interface：调用者必须知道的一切（签名 + 不变量 + 顺序约束 + 错误模式 + 性能）。避免：API / signature

Seam：能“不改此处而改行为”的位置；interface 所在之处。

Depth / 深模块：小 interface 背后藏大量行为；反之为浅模块。

Adapter：在 seam 上满足 interface 的具体实现（按角色命名）。

Leverage / Locality：深模块给调用者的杠杆、给维护者的局部性（改一处、处处生效）。

Deletion test：假想删掉该 module——复杂度消失则是透传，复杂度在 N 个调用方重现则是真深。

领域建模

CONTEXT.md：项目的通用语言词汇表，只含定义不含实现。

ADR：难逆、意外、有权衡的决策记录（docs/adr/0001-*.md）。

Ubiquitous Language：团队与代码中共用的那套词。

协作与质量

TDD / red→green：先写会红的测试，再写刚好变绿的实现，一次只做一个 seam、一个切片。

Code Review 双轴：Standards vs Spec，并行子 agent 互不污染。

Tight feedback loop： diagnosing-bugs 的第一性原理——一条能对“这个 bug”稳定变红、数秒内、Agent 可无人值守跑的命令。
