上下文卫生：grill→spec→tickets 在同一个上下文窗口内连续做完；每个 implement 起一个新上下文。

步骤输入输出何时分叉
/grill-with-docs模糊想法锐化问题 + 更新的 CONTEXT.md/ADR遇到“跑一下才知道” → /handoff → /prototype
/to-spec已拷问过的对话含 seams 的 spec issue先让用户确认 seams 再写正文
/to-ticketsspec多张 vertical slice 票宽重构走 expand→migrate→contract
/implement单张票绿测试后的 commit内部固定跑 /tdd，收尾 /code-review
三条铁律：① grill-with-docs 解决“做对的事”，tdd 解决“把事做对”；② 永远只做 frontier 上的票；③ wayfinder 只产决策，交付仍走主流程。
