更新能力委托地图（873）待定三问

下面三个问题是这张地图里还没拍板的事。名词先说清：按钮指配置页上的检查更新按钮；面板指点开后的更新弹窗；档案卷指包里自带的纸面案卷外观（浅色纸面加印章样式）。已经定下的三件事：只留包的基本用法、更新包跟最新、做完以门禁全绿为准、发版由人手动做。

【已定案 2026-10-06】Q3-1、Q3-2 本不该是问题：包提供了现成的按钮与弹窗，直接用默认，不自写；Q4-1 只用档案卷。下面的问答与架构版附加项（语言接入、尺寸对齐、重启探测）一并作废，以本条为准，不再需要人回答。

Q3-1 按钮摆成什么样

背景

包里的按钮有三种摆法：正常按钮、只显示一个状态圆点、整块面板直接嵌在页面里。进页面时可以静默查一次（只读本地，不联网），也可以等用户点击再查。点击后可以有新版才开弹窗，也可以每次都开。我们现在的按钮是正常按钮，进页面先读一次，有新版才弹窗。

推荐答案

正常按钮，进页面静默查一次，有新版才开弹窗。没新版时在原地留一句小字（已是最新加版本号），让用户确认查过。

每个选项的优点和缺点

选项优点缺点
正常按钮按得着，文案能写清当前状态占标题行一点位置
状态圆点省地方点不准，看不出是什么状态，还得另写说明
整块内嵌不用点开长期占地方，配置页变长
进页面静默查用户不用点就知道有没有事，且只读本地每次进页面多一次本地读取（成本很低）
点击时才查不做多余动作用户不点就永远不知道有新版
有新版才开弹窗没事不打扰用户可能怀疑到底查没查，用原地小字解决
每次都开弹窗所见即所得没新版也弹一次，打扰

对抗式审查

先攻击推荐：静默查会不会偷偷联网浪费流量？不会，静默只读本地，联网只在用户点了之后发生。有新版才开弹窗，用户怎么确认查过？原地小字写清版本号。按钮文案会不会中英文混排？包按界面语言只渲染一种。攻击完结论不变：推荐成立，附带原地小字。

从第一性原理出发

用户的核心需要是“不用点开就知道有没有事”；检查必须是只读的，安装必须由人明确点一下。正常按钮加静默只读查加有事才开，正好一一对应。推荐成立。

Q3-2 弹窗关闭和重启接不接自己的流程

背景

弹窗有关闭按钮，点关闭后轮询会停，但已经提交的安装在宿主那边继续跑。待重启横幅上有个重启入口，但宿主没有提供重启自己的方法，默认只能提示手动重启。我们也可以自己接一个重启流程。

推荐答案

关闭用包自带的，重启只提示手动重启，不接自己的流程。面板里保留一行说明：关掉面板不会中断安装。

每个选项的优点和缺点

选项优点缺点
用包自带的关闭关得干净，先撤界面再停轮询，安装不受影响行为固定，加不了自己的动作（本来也不需要）
自己写关闭能加自己的动作容易漏停轮询造成后台空转，状态显示还可能断档
只提示手动重启说的是实话多一步手动操作
接自己的重启流程一键到底宿主没给重启方法，自己拼的流程一旦失败，用户会以为重启了其实没有，这是最坏的结果

对抗式审查

先攻击推荐：如果用户在安装中途关弹窗，安装会不会停？不会，宿主侧继续跑，重开面板一秒内恢复显示，但必须在面板里写明“关掉不会中断”，否则用户不敢关。只提示手动重启会不会显得简陋？待重启横幅本身显眼（版本号对照加重启后生效说明），而手动是宿主唯一的诚实做法。攻击完结论不变：推荐成立，面板保留“关掉不中断”说明。

从第一性原理出发

界面绝不能宣称自己没做到的事。关弹窗做不到停安装，就必须明说；点重启做不到真重启，就只能提示手动。推荐成立。

Q4-1 档案卷之外还加自己的颜色吗

背景

包里按钮和面板有两套外观：默认深色最小可用，和档案卷（纸面浅色案卷风）。传一个参数就换，不改变行为。还可以传自定义颜色，但传了之后那部分颜色就固定了，不再跟随深浅切换，写错会直接报错。

推荐答案

两处都传档案卷，不自定义颜色。验收时深浅各看一遍。

每个选项的优点和缺点

选项优点缺点
档案卷正是你要的外观，一套参数两处生效样式比默认重一点，但结构顺序不变
默认外观最轻不是你要的样子
自定义颜色能调自己的品牌色自己要保证深浅两套都可读，固定值不再跟随系统，维护成本高，写错直接报错

对抗式审查

先攻击推荐：档案卷在深色模式下会不会看不清？包说明浅深两套跟随系统，验收时深浅各看一遍。印章和横幅会不会挡住操作按钮？结构顺序与默认一致，复制诊断一直在，验收时点一遍。攻击完结论不变：推荐成立，验收加深浅各看一遍。

从第一性原理出发

外观只是皮肤，不能改变行为和结构。一次传参换肤，不动结构、不加变量，是成本最低且可回退的做法（随时可切回默认）。推荐成立。

第二部分：架构师视角（最高质量，不计成本，但合理）

总体立场：面向未来，更新面板是唯一可信的版本事实源。能委托给包的全部委托；本仓只保留三样：取值（标识、前缀、目标包名）、挂载点（放在哪）、验收（门禁）。下面每题先给架构版推荐，再写多花的成本，然后对抗审查，最后第一性原理复核。

Q3-1 架构版：按钮摆法

推荐答案（架构版）

正常按钮加进页面静默查加有新版才开加原地小字（与第一部分一致），外加三样：按钮尺寸对齐标题行其他控件（用参数传实测值，取值来自共享的标题行 token，不写手写像素）；语言接到宿主语言服务（切换即时重绘，关页面自动停订；若本插件不支持运行时切换语言就回落默认）；打开动作保持默认进包的弹窗，不桥接自己的页面。

多花的成本在哪

双语验收矩阵（中英乘各状态）、标题行改版时顺手核对尺寸、语言服务接口变更时跟随。三项都是验收与跟随成本，不增加运行时复杂度。

对抗式审查

攻击1：语言订阅会不会漏停？包在卸载时停订，面板票验收加开关页面用例。攻击2：尺寸对齐是不是脆弱耦合？取值来自共享 token 而非手写像素，标题行改版门禁会连带发现。攻击3：语言接入是不是过度设计？推荐里带了回落条件，不满足条件就不接。攻击4：为什么不桥接自己的页面？那会制造第二个事实源，面板与自有页面迟早不一致，这是确定的未来维护债。攻击完结论不变：推荐成立，带回落条件。

第一性原理复核

按钮的可信度等于状态准确加语言是用户的语言加尺寸不跳变。三个附加项各保一条，无多余。成立。

与第一部分推荐的差异：第一部分只到默认三件套；架构版加了尺寸对齐与语言接入（有回落），并明确不桥接自有页面。

Q3-2 架构版：关闭和重启

推荐答案（架构版）

关闭用包自带的真关闭（撤界面再停轮询），安装中关闭后由按钮继续显示进度；重启先探测宿主能力，有则接、无则诚实提示手动；横幅写清两个版本号；待重启期间不给安装按钮（包内已强制）。

多花的成本在哪

面板票里加一个只读探测步骤（限时，不阻塞主线）；重启成功与失败两条验收用例。

对抗式审查

攻击1：探测不到能力，白花时间？探测只读且限时，找不到就回落默认提示，主线不受影响。攻击2：探测到一个不稳定的重启方法？验收要求成功与失败回执两条都过，不过就不用，最差回落到手动提示，不会比现在更差。攻击3：用户安装中途关弹窗后忘记？按钮持续显示正在安装，信号不断。攻击4：按 Esc 关闭走不走同一条路？走同一回调，验收覆盖 Esc 用例。攻击完结论不变：推荐成立。

第一性原理复核

关闭语义等于撤界面不等于停安装，必须明说；重启语义等于有能力才给按钮，无能力只给指引。探测就是先问有没有，再决定给不给。成立。

与第一部分推荐的差异：第一部分直接定手动重启；架构版加了先探测、有则接，并明确按钮接力显示进度。

Q4-1 架构版：皮肤

推荐答案（架构版）

两处传档案卷，零自定义颜色；留一个唯一的换肤缝（挂载点一处注释：以后调色只改这里，且每次改必须深浅各验一遍）；不给用户提供皮肤开关，跟随系统；验收查全局样式不泄漏进面板。

多花的成本在哪

深浅两套截图对比各一遍，样式隔离检查一次。一处注释的发现成本极低。

对抗式审查

攻击1：留而不用缝会腐烂？缝只有一处注释加验收清单一行；相对地，现在传两三个品牌色会冻结深色跟随，风险更高。攻击2：以后真要品牌色怎么办？走换肤缝加深浅验收，有路可走。攻击3：用户想手动切皮肤？仓库既有惯例是不给用户开关（版本页同样跟随系统），一致性优先。攻击4：印章会不会遮挡操作按钮？结构顺序与默认一致，验收点一遍操作按钮。攻击完结论不变：推荐成立。

第一性原理复核

皮肤三约束：不改事实（同结构）、任何模式可读（跟随系统）、可回退（一参切换）。零自定义是唯一同时满足三条且成本最低的做法。成立。

与第一部分推荐的差异：第一部分只说传档案卷；架构版加了换肤缝（留而不用）、无用户开关、样式隔离验收。
