# 前端技法调研：六个库能教我们什么（以及哪些不该装进插件）

> 起因：#474 要重做地图详情页，维护者点名了 Leaflet / Chart.js / PixiJS / Paper.js / Chroma.js / Anime.js 六个库，要求先学。
> 结论先行：**六个库一个都不装**，但每个都偷一个技法。理由是体积——本插件的客户端产物 `package/lib/client.js` 已经是 **1.23 MB**，
> 而真机首屏目标（地图 #604 自己定的验收标准）是「点开面板到看见内容 ≤ 300 毫秒」。装重库等于拿这张图上最硬的一条指标去换画面。

## 1. 六个库的硬数字（2026-09-21 实测）

星标数与体积用 `gh api repos/<repo>` 与 bundlephobia 现查，不是记忆里的数字：

| 库 | 星标 | 许可 | 最新发布（min / gzip） | 装进本插件 = client.js 增重 | 结论 |
|---|---:|---|---:|---:|---|
| Leaflet | 45,639 | BSD-2 | 148.5 KB / 42.7 KB | +12% | 不装 |
| Chart.js | 67,702 | MIT | 200.8 KB / 68.4 KB | +16% | 不装 |
| PixiJS | 48,197 | MIT | 913.1 KB / 261.0 KB | **+74%** | 不装 |
| Paper.js | 15,078 | 见仓库（NOASSERTION） | 237.9 KB / 84.2 KB | +19% | 不装（且 2024-07 后未再更新） |
| Chroma.js | 10,582 | 见仓库（NOASSERTION） | 41.2 KB / 16.2 KB | +3.3% | 可装，但用不上（见下） |
| Anime.js | 72,978 | MIT | 116.8 KB / 40.3 KB | +9.5% | 不装 |

`package/package.json` 目前的 dependencies 只有一项 `dsh-plugin-update`，插件一直是「产物自带、不拉第三方运行时」的路子；
上面任何一个库都会破这个局面。**六个库的画像都记在本文，代码里一个 `import` 都没有。**

## 2. 每个库偷什么（这是本篇真正的产出）

### Leaflet — 偷「雾 = 整张遮罩挖洞」和「控件永远待在角落」
它自己的定位是「小核心 + 插件生态」，值钱的是两件事：
- **战争迷雾的正确画法**：不是往未知的地方刷一层半透明色，而是**盖一张覆盖全图的遮罩，把走过的地方挖成洞**。
  社区里成型的做法就是往多边形里塞「洞」（[Leaflet fog of war](http://www.agalera.eu/leaflet-fog-of-war/) 用的就是 `L.Polygon` 的第二个参数当洞），
  SVG 对应 `fill-rule="evenodd"`，Canvas 对应 `destination-out` 合成。挖洞与「刷一层」的观感差别很大：
  挖洞得到的是**一整张连续的雾**，洞边是柔的；刷一层得到的是「一堆雾团」，雾团之间会露出地形，看着像脏点。
- **控件设计**：缩放、图例、比例尺都在边角，位置固定、不随滚动跑，且**可折叠**。地图页最难的就是「不给画面加东西但让人知道怎么用」，Leaflet 用一列小方块解决了。
- 另有一条产品级教训：它的插件里最受欢迎的永远是「数据层」（打点、聚合、热力），不是「画法层」。我们该沉淀的是**地图数据的推导**（哪张票在哪个状态），不是画法。

### Chart.js — 偷「环要分段、环心要说话」
Chart.js 的甜甜圈图有两个现成约定，本插件那个 72px 的环两样都没做到：
- **分段而不是一整圈**：数据有几项就画几段，段间留缝（`borderWidth` + `cutout`），一眼能数出「几段走了几段没走」；
- **环心写字**：社区标准做法是在 `afterDraw` 钩子里往圆心画文字（总数/百分比），而不是让环空着。
本插件现在的环按「已通过层数 + 1 / 总层数」算，单层地图永远满环——那是环的口径错了，不是画法错了。画法可以照 Chart.js 抄，20 行 canvas/SVG 就够，不需要 200 KB。

### PixiJS — 偷「软边视野」的思路，但不用 WebGL
PixiJS 处理迷雾的经典配方是：雾画进一张离屏纹理（RenderTexture），再用 `destination-out` 混合模式在单位周围**擦掉**圆形区域；
「探索过」与「当前可见」分成两层纹理（永久点亮 vs 只照亮当下）——这正是 #474 里「走亮」与「视野」两条语义的实现方式。
一屏最多几十个节点，用 WebGL 是杀鸡用牛刀；Canvas 2D 的径向渐变 + `destination-out` 就是同一套算法，代价 0 KB。
（思路来源：[Efficient fog of war](https://www.html5gamedevs.com/topic/1323-efficient-fog-of-war/)、[Raycasting and inverse masking](https://www.html5gamedevs.com/topic/46621-raycasting-and-inverse-masking)，社区多年沉淀的通行做法。）

### Paper.js — 偷「等高线是偏移曲线」，不用它的渲染器
等高线不是手画的波浪，是**同一条基线按等距向外偏移**（`Path.offset(delta)`）叠出来的，所以层与层之间永远平行、宽度成比例。
Paper.js 的布尔运算与偏移是它的看家本领，但等高线这种规则曲线用 Canvas 的 `quadraticCurveTo` 手写也够；它 2024 年后已不再更新，风险比收益大。

### Chroma.js — 偷「感知均匀」与「色觉」的判据，不用它的代码
两件事值得抄进纪律：
- **色阶在感知空间里取**（LCh / OKLab），而不是在 HSL 里等距取。HSL 里等距的一串颜色，人眼看过去明暗是乱的。
- **可访问性要能被量化**：#474 只要求「三态不能只靠颜色区分」，Chroma 的方法论给了可判定的判据——
  把颜色按**明度阶梯**排开（相邻两态的 L\* 至少差 10），再套一层色觉模拟矩阵（Viénot 1999 那套线性 RGB 矩阵）看阶梯还在不在。
  在的话，红绿色盲看到的仍然是「亮→暗」的有序阶梯；不在的话，那三种颜色对色弱用户就是同一个色。
  这两件事各约 30 行数学，自己写即可，不必为 41 KB 引一个包。

### Anime.js — 偷「状态迁移要动」，不用它的运行时
Anime.js v4 有两个模块正中本页面的痒处：
- `stagger()` + SVG 描边动画：让「亮痕」像被点亮一样一段段扫过去，而不是整条线突然出现；
- `layout` 模块：DOM 顺序/父节点变化时自动做 FLIP 补间——票从「雾里」被推进到「走亮」时，卡片**平滑地移动并变色**，而不是原地重排。
这两件事用 CSS 关键帧 + Web Animations API 可以覆盖（本插件客户端已经有 React，再加一个动画运行时只会让包更大、和 React 的渲染时机打架）。

## 3. 顺带看的设计仓库（学到的是纪律，不是代码）

| 仓库 | 星标 | 拿走的那一条 |
|---|---:|---|
| [shadcn-ui/ui](https://github.com/shadcn-ui/ui) | 124,262 | 组件是**复制进你自己的仓库**的源码，不是依赖。设计系统的价值在「可改的源码」，不在「引用一个包」 |
| [tailwindlabs/tailwindcss](https://github.com/tailwindlabs/tailwindcss) | 97,635 | 把设计决定收成**极少的一组刻度**（间距/字号/色阶），界面不许出现第 8 种灰 |
| [radix-ui/primitives](https://github.com/radix-ui/primitives) | 19,309 | 交互态（hover/focus/disabled/expanded）要穷举，不是用到哪个补哪个 |
| [IBM/carbon](https://github.com/carbon-design-system/carbon) | — | 数据可视化有独立于品牌色的**语义色板**；状态色必须配图标/形状 |
| [d3/d3](https://github.com/d3/d3) | 113,748 | 比例尺（scale）是独立概念：数据 → 视觉通道的映射要单独写、单独测 |
| [FormKit/auto-animate](https://github.com/formkit/auto-animate) | 13,925 | 列表增删的动效可以「一个函数搞定」，前提是布局稳定（呼应本仓 #602 的布局零抖动纪律） |

## 4. 落回到地图详情页：五条具体改动

1. **雾改成挖洞遮罩**（学 Leaflet 的画法）：一整张雾盖住全图，走亮与照亮的地方挖出柔边洞；雾里有噪点纹理，全亮模式下整张雾淡出而不是消失。
2. **状态色改成明度阶梯 + 色觉模拟开关**（学 Chroma 的判据）：四态的 L\* 拉开到 ≥10，界面上给一个「色觉模拟」开关（红/绿/蓝三型），随时可验。
3. **亮痕加扫亮动画**（学 Anime.js 的 stagger）：进入页面时亮痕从起点扫到当前点；点「重播」可重看。
4. **边角控件栈**（学 Leaflet 的控件）：右下角一列小方块——聚焦当前 / 一键全亮 / 图例开关；底部一条数据条（走亮 n/总 m · 雾 n）。
5. **进度环按票算、分段、环心写字**（学 Chart.js）：删掉「按层 +1」的口径，改成按票分段的甜甜圈，环心写「2/4 走亮」。

这五条都不需要新依赖，全部可在现有的 `src/client/views/MapDetail.js` + `kernel/styles.js` 里落地。
原型见 `docs/prototype/474-map-detail-craft.html`（每一条都能在页面上开关对照）。
