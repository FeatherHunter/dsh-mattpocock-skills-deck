## 0. 拍照前一次性准备（8 张图共用）

- 电脑与窗口：用 DSH Desktop 桌面应用，把窗口最大化。操作系统显示缩放调到 100%，DSH 界面缩放也保持 100%。下面所有图都在这个缩放下截，截完不压缩、不转格式。
- 主题与配色：DSH Desktop 切换到深色主题，装上自制配色插件 dsh-opencode-palette 并选中自制配色。截图里看到深底加彩色文字就是对的。
- 工作区：准备一个有远端的 GitHub 仓库目录，用它打开 DSH 会话，后端选 GitHub 并完成初始化。除了第 7 张多后端切换，其余 7 张都在这个工作区拍，保证列表有数据、状态栏数字不是空的。
- 隐私检查：截图前看一眼画面里没有登录令牌、私钥、个人邮箱、公司内网地址。有就换一条公开任务再拍。
- 新建图片目录：在仓库根目录执行一次新建目录，后面 8 张图都放进去，不放别处：

```powershell
mkdir assets/readme
```

- 通用拍图约定（来自 #483，拍图的人负责）：同一组里的小图必须在同一缩放下截，统一用 100% 缩放。深色截图要保证在深色网页背景上看得见边界，做法是在 README 引用时加 1 像素边框，拍图的人只管把内容拍清楚。README 里引用小图时用宽度百分比按原图像素比分配，图与图之间留 12 像素间距，每张图包一层超链接，点小图能打开原图文件。这些引用写法由结构重排时统一写，拍图的人不用管，只管交原图。

## 2. 第 1 张：安装（assets/readme/01-install-board-ready.png）

- 对应标题：安装。
- 文件在仓库里的完整路径：assets/readme/01-install-board-ready.png。
- 准备：在终端里确认 DSH Desktop 对应的 profile 是 desktop，后面所有安装命令都用 desktop。
- 操作步骤：
  - 第一步：在终端执行安装命令，把插件装进 desktop 这个 profile：dsh plugin --profile desktop add dsh-mattpocock-skills-deck@1.7.14 --registry https://registry.npmjs.org。看到命令行回显安装成功，没有报错，算这一步成功。
  - 第二步：完全退出 DSH Desktop 再重新打开，不是只关窗口。重开后刷新一次页面。
  - 第三步：用准备好的 GitHub 仓库目录打开一个会话，看 DSH 侧边栏出现面板入口，点开面板。
  - 第四步：看面板顶部出现三个页签，文字分别是列表、技能、环境检查，右侧出现两个描边按钮，文字分别是 + 需求、+ bug，外加一个文字是刷新的按钮，旁边还有一串版本号，点版本号能打开插件仓库主页。
- 成功标准：面板能打开，列表里出现自己仓库的任务，顶部关键数字可接有数字，版本号点得开。
- 截图时机与范围：拍整个面板，上面四个角都要进画面，重点是顶部三个页签加右侧两个新建按钮加版本号，下面带出列表前三行。不截终端，不截全屏。
- 存图：把截到的图原样存成 assets/readme/01-install-board-ready.png，不改名，不压缩。

## 3. 第 2 张：任务板列表（assets/readme/02-task-board-list.png）

- 对应标题：任务板列表。
- 文件在仓库里的完整路径：assets/readme/02-task-board-list.png。
- 准备：留在第 1 张的工作区，保证有开放任务、阻塞任务、已关闭任务各至少一条，这样筛选与折叠才有东西可拍。
- 操作步骤：
  - 第一步：在面板顶部点文字是列表的页签，看到任务列表页。
  - 第二步：看列表顶部有一行关键数字，文字是可接几个、阻塞几个，数字和下面列表里的开放任务对得上。
  - 第三步：看筛选行，状态筛有全部、开放、阻塞、已关闭，旁边有标签筛，点一下能筛出来，地图类型的行永远在最上面。
  - 第四步：看每一行任务的动作按钮，文字按标签自动换，分别是诊断、修复、讨论、执行中的一个。点一下不是直接开干，而是把写好的指令填进输入框。再看每行还有复制链接、在远端打开、新会话中打开三个小动作。被阻塞的行动作按钮会换成红色被阻塞标签，点标签能跳到所属地图。
  - 第五步：把页面拉到最下面，看已关闭的任务收成一行，文字是已关闭加数量，点开才看得到。
- 成功标准：上面五步看到的东西都在画面里，行动作按钮至少出现一种，地图置顶行看得到，已关闭折叠行看得到。
- 截图时机与范围：拍列表页首屏，含顶部关键数字、筛选行、前四行任务、底部已关闭折叠行。不点开任何下拉菜单，保持干净列表。
- 存图：存成 assets/readme/02-task-board-list.png。

## 4. 第 3 张：底部任务栏（assets/readme/03-statusbar-capsule.png）

- 对应标题：底部任务栏。
- 文件在仓库里的完整路径：assets/readme/03-statusbar-capsule.png。
- 准备：打开任意一个有仓库的会话，看输入框下面那一条胶囊状态栏。把窗口拉到正常宽度，不要窄到胶囊自动折叠，保证每个分段的文字都看得见。
- 操作步骤：
  - 第一步：看胶囊最左边是插件图标加 MattSkills 字样，点一下能打开或收起面板。
  - 第二步：从左往右认每个分段，文字依次是可接、BUG、诊断、沉淀、交接、环境、更新加相对时间。把鼠标悬停在 BUG 上，看浮出一层小菜单，里面有一项文字是新增。
  - 第三步：看交接是一对左右拼在一起的按钮，左边点一下生成交接文档，右边只有交接文档就绪时才变亮。看环境分段显示类似 3/9 的数字，意思是检查链过了几项、共几项。看最右侧有技能悬浮入口，再往右有一个下箭头，点一下能把整条功能区收起。
  - 第四步：每个分段点一下试手感，确认点可接跳列表可接筛选，点环境跳环境检查页，然后回到原位，不停在跳转页。
- 成功标准：一条完整胶囊从左到右每个字都清晰，输入框下边缘作为参照一起进画面，证明它长在输入框下面。
- 截图时机与范围：横向截完整一条胶囊，上下各多带 8 像素的输入框与会话背景，不要只截半条。悬停菜单那一下不用截，保持胶囊常态。
- 存图：存成 assets/readme/03-statusbar-capsule.png。

## 5. 第 4 张：ISSUE 详情与评论（assets/readme/04-issue-detail-comment.png）

- 对应标题：ISSUE 详情与评论。
- 文件在仓库里的完整路径：assets/readme/04-issue-detail-comment.png。
- 准备：在任务板列表里挑一条有描述、有评论、有作者的开放任务，标题不要含隐私。
- 操作步骤：
  - 第一步：在列表里点这条任务的行，看到详情页。
  - 第二步：看详情页顶部固定一行，从左到右是返回列表按钮、列表与编号、快照或加载中提示、新会话主按钮、复制链接、打开原票按钮。如果网络失败，会出现红色横幅加重试按钮，换一条能打开的任务重拍。
  - 第三步：看票头信息，含编号、标题、开放或已关闭状态、标签、认领人、更新日期、创建日期、有作者就显示作者。如果这条任务属于某张地图，会有一条紫色小横条写属于加地图编号标题，点一下能跳到地图详情。
  - 第四步：往下滚，看描述正文是排好版的 Markdown，看评论区能翻页，底部有评论输入框，输入框上面有底部动作行，文字同样是诊断、修复、讨论、执行中的一个。
- 成功标准：顶部按钮行、票头信息、描述开头、评论区入口同在一屏，输入框看得到，证明不用跳终端就能回话。
- 截图时机与范围：拍详情页首屏，从顶部按钮行拍到描述前十行加评论区第一条。不把长评论全文拍完，保持首屏信息密度。
- 存图：存成 assets/readme/04-issue-detail-comment.png。

## 8. 第 7 张：多后端切换（assets/readme/07-backend-switch.png）

- 对应标题：多后端切换。

- 准备：进面板设置页，找到后端选择器。保证当前选中 GitHub，这样来源小胶囊有东西可拍。
- 操作步骤：
  - 第一步：看选择器里有四行，分别是 GitHub、本地 Markdown、GitLab、外加 Other（无后端）逃生舱。每一行有圆点颜色、英文编号、中文名，当前选中的一行多一个来源小胶囊，文字是显式绑定、自动匹配、回退中的一个。
  - 第二步：点一下另一个后端，看到弹出来确认框，标题是切换 Tracker 后端，里面写现有数据保留在原后端、切换后不可见、切回来又可见，默认选中保留并可编辑提示语。看到这个框就点取消，不要真的确认，避免切走数据看不见吓到自己。
- 成功标准：四行选择器加来源小胶囊清晰，证明换跑道不断数据。确认框细节不拍，知道会弹什么、点取消就行。
