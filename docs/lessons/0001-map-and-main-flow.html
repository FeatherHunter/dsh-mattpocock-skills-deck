What is a skill?

Skill 是一小段锋利的指令，你交给 Agent，让它按资深工程师的方式工作。

不是让 Agent 去猜。猜，就会写出“看似合理、悄悄腐化”的代码。
一个好 skill 只编码一个好习惯，每次都走同一套可信任的过程。

为什么会复利： skills 连成链，前一个的输出是后一个的输入。调优单步，整条链变好。

The 4 failures they fix
  1. Agent 没做你要的 → 拷问对齐 /grill-with-docs
  2. Agent 太啰嗦 → 共用语言 CONTEXT.md + ADR
  3. 代码跑不起来 → 反馈环 /tdd · tight loop
  4. 越写越成泥球 → 深模块 /improve-codebase-architecture

练一练：6 个情境，你会伸手拿哪个 skill？

每题选一个最贴合的。目标：6/6。

Quick check — 6 scenarios0 / 6
1/6 · 你有个模糊想法：“想给 Tracker Deck 加个沉淀快照功能”，但还没想清楚
/grill-with-docs — 先拷问，把想法磨锋利并留下 CONTEXT/ADR
/to-spec — 直接综合成 spec
/to-tickets — 拆成多张可并行票
✓ /grill-with-docs 是起点：对齐“做对的事”。
2/6 · 经过拷问已对齐，spec 也写好了，现在要拆成 Agent 可并行的小票
/implement — 直接开建
/to-tickets — 产 tracer-bullet 垂直切片 + Blocked by 边
/wayfinder — 建迷雾地图
✓ /to-tickets：每票窄但穿透全层、可独立演示。
3/6 · 已拆好票，拿其中一张去落地
/tdd — 只在已定 seams 上写测试
/implement — 驱动 /tdd 单步推进，收尾跑 /code-review 再 commit
/code-review — 只审 diff
✓ /implement 是编排层：内部固定用 /tdd，结尾固定 /code-review。
4/6 · 线上“收藏”偶发丢数据，本地难以复现
/research — 后台读一手文档
/diagnosing-bugs — 先造 tight feedback loop
/improve-codebase-architecture — 扫架构体检
✓ 硬 bug 的纪律：无 loop 不假说。
5/6 · 要做“单仓拆多上下文 + 迁移历史数据”，大到一会话装不下
/to-spec — 直接写全量 spec
/prototype — 建抛弃式原型
/wayfinder — 建 map，逐个清 decision tickets
✓ /wayfinder 只产决策不直接开建。
6/6 · 最近改得最多的模块越来越难测，想挑一个“深模块”机会体检
/diagnosing-bugs — 先造 loop
/triage — 分拣需求堆积
/improve-codebase-architecture — 扫热点 → HTML 报告 → 挑一个再 grill
✓ 体检产候选、挑一个再 /grilling。
🎉 完成！ 现在你已能在主流程与四大入口间做一秒选型。记忆钩子：配 → 磨 → 写 → 拆 → 建 → 审。
