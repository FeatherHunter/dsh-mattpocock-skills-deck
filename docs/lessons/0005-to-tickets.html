拆票：/to-tickets
垂直切片 + blocking 边，让多 Agent 可并行

spec 是“一整块”。/to-tickets 把它切成窄但穿透全层的 tracer-bullet 票。

垂直 vs 水平： 垂直 = 一刀穿透 schema→API→UI→test（可演示）；水平 = 只改一层（不可演示）。永远选垂直。

切多细？以“可装进一个上下文窗口”为度

  • 每票刚好能被一个新鲜上下文一口气做完
  • 先做 预重构 票：让后续改动变容易
  • 给每票写 Blocked by：必须先完成的票
# .scratch/snapshot/issues/01-expand-snapshot-store.md
# 01: 扩展快照存储（IndexedDB 并存 localStorage）
What to build: 扩展存储使后续迁移可在不破旧读的前提下分批进行
Blocked by: None (can start immediately)
Status: ready-for-agent

宽重构的例外：expand → migrate×N → contract

当改动是“机械地横扫全仓”（改列名），垂直切片无法保持 CI 绿，则：

  1. expand：新旧并存
  2. migrate：按目录分批迁，每批一票
  3. contract：删旧
