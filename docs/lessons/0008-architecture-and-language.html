体检与语言
improve-codebase-architecture + domain-modeling / codebase-design

交付会加速腐化。体检让你定期挑出“值得变深”的模块；语言让你用 1 个词代替 20 个词。

improve-codebase-architecture：怎么做体检

  1. 定范围（YAGNI）：优先看最近频繁改动的热点（git log --oneline）
  2. 扫：体会摩擦——要理解一个概念是否要跳多处、是否存在浅模块
  3. 产报告：一份自包含 HTML（Tailwind + Mermaid + 手绘 SVG），每候选一张卡：Files / Problem / Solution / Benefits / Before-After 图 / 推荐强度
  4. 挑一个再 grill：问用户“想探索哪一个？”，随后用 /grilling 走决策树

若候选与既有 ADR 冲突，仅当摩擦足够大才提示。

深模块的词汇（codebase-design）

Deep — 深
小 Interface
大 Implementation
一处改，处处生效
Shallow — 浅（避免）
大 Interface
薄 Implementation
只是透传
  • Deletion test：删掉它——复杂度消失则是透传，复杂度在 N 个调用方重现则是真深。
  • Interface is the test surface：调用方与测试跨同一条 seam
  • One adapter = 假想，Two adapters = 真实

领域语言（domain-modeling）

目标：Agent 与人共用同一套词。

  • 有人用词与 CONTEXT.md 冲突 → 立刻指出
  • 有人用模糊词（“账号”）→ 追问到精确并落新词
  • 用具体场景锐化边界
  • 改词当场写 CONTEXT.md；难逆选择再立 ADR

CONTEXT.md 只放定义，不放实现。
