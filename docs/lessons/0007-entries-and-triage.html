双入口：diagnosing-bugs 与 wayfinder

主流程解决“从 0 到 1 的交付”。这两个入口解决“已经在跑的世界里，最难的两类事”：偶发的硬 bug 与 大到看不清路的规划。

diagnosing-bugs：先造 tight feedback loop

第一性原理： 没有“能对这个 bug 变红”的 loop，就不许进入假说。

  1. 造 loop：失败测试 / curl / CLI fixture / Playwright … 选一个能“秒级、稳定变红、Agent 可无人跑”的。
  2. 紧一紧：更快、更尖、更确定。
  3. 复现 + 极小化：删到“每剩一项，去掉就变绿”。
  4. 假说 3–5 个可证伪：写成“若 X 是原因，则改 Y 会使 bug 消失”。
  5. 埋点：一次只改一变量，打 [DEBUG-xxxx] 前缀。
  6. 修 + 回归测试：让原 loop 变绿，并留下防止再犯的测试。

非确定 bug 的目标是把复现率从 1% 提至 50%+。

wayfinder：为迷雾建地图

大到一会话装不下的事，不直接开建——先画地图。

  • Map：一张 wayfinder:map 票，含 Destination / Notes / Decisions so far / Fog
  • Decision tickets：每张一个待决问题，类型 research / prototype / grilling / task
  • Frontier：所有 blockers 全关 + 未认领的开放子票；永远只做 frontier
  • 只产决策不交付：雾清后回到 /to-spec→/to-tickets→/implement
