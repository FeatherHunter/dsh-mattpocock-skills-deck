磨锋利：/grill-with-docs
拷问你的想法，同时留下能复用的词与决策

这是 Matt 最受欢迎的 skill。同一场访谈做两件事：把想法磨锋利 + 把通用语言写进 CONTEXT.md、把难逆选择写进 ADR。

一句话区分： /grill-me 只拷问；/grill-with-docs = 拷问 + 边问边沉淀文档（有仓时永远选后者）。

拷问在问什么（设计树）

Grill 不是“随便问问”，是沿 设计树 把每个分支都判成 已定 / 待定 / 不做

  • 目标与非目标：到底解决谁的什么痛、什么明确不做
  • 用户与场景：谁会用、关键路径是哪 2–3 条
  • 约束与权衡：时间/性能/安全/兼容，哪个可牺牲
  • 依赖与风险：是否需要一条 /prototype 或 /research 来闭环
  • 术语：你说的“沉淀”是否与 CONTEXT.md 一致？

每定一个词 → 立刻写 CONTEXT.md；每定一个难逆选择 → 当场立 docs/adr/0001-*.md。

产出长什么样

CONTEXT.md 的一条
## 沉淀 Snapshot
一次把当前地图+任务+阻塞的可视状态
原地落盘为可恢复的快照
_Avoid_: save, dump

只放定义，不放实现。

ADR 的一条
# ADR-0007: 快照存于 IndexedDB
Date: 2026-08-26
Decision: 用 IndexedDB，键为 mapId
Consequences: 需迁移旧 localStorage

三问都中才立 ADR：难逆 × 意外 × 真有备选。

对话示范

Agent：你说“沉淀”，是指把整张地图的状态落盘，还是只存当前焦点任务？

你：整张地图，含过滤器与滚动位置。

Agent：好，我把“沉淀 = 地图全量快照”写入 CONTEXT.md。追问：快照多大？会超 5MB 吗？

节奏感：一问一答一落盘。

何时该分叉去 prototype / research

  • “这个交互跑起来才知道” → /handoff → 新目录 /prototype → 带结论回来
  • “这个 API 到底支不支持 X” → /research → 回来把事实写入 ADR
