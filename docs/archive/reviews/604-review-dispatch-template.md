# 派给审查子代理的固定要求（模板）

这张票关掉之后，总工程师会派两路互不通气、也看不到对方结论的审查子代理，各自独立给出 0–10 分并列出「不成立的地方」与「必须整改才能放行的地方」。两路看的是同一把尺子——就是本文件里「对抗式审查的尺子」那一节——但任务与材料不同，防止两路互相抄。

## 甲路：查「规矩与证据」

给它看的材料：本说明书、那张票的正文与全部评论、`AGENTS.md`、`docs/agents/commit-convention.md`、`docs/design/335-logging-contract.md`、`research/489-appendix.md`，以及本次改动的提交与差异（`git show`/`git diff`）。

要它回答：

1. 票里每一条结论**能不能重跑**：要求它自己挑至少两条关键结论，按票里写的复现方式跑一遍，报告实际跑出来的数字与票里写的差多少。跑不出来、或票里根本没写复现方式，直接算不成立。
2. 有没有**把本地对照实验的绝对毫秒数当真机数字用**（本图只允许搬「改前改后的倍数」与「结果等价性」）。
3. 有没有**该写「没量到」却用推断填空**的地方。
4. 改动是否守住日志纪律：新增事件是常驻还是按需、判定依据是合同第 3 章哪一条、字段是否越出白名单、调试开关关闭时是否真的不组装字段、门禁与对照表是否同步。要求它**自己跑一遍三项日志门禁**并贴结果，不接受「代理说绿了」。
5. 有没有碰不该碰的东西：别的仓库、DSH 本体、地图 #604 的正文、同一卷里别人的改动、不属于本票的暂存文件。
6. 进度节写的百分比与票的实际状态是否对得上；被关闭的票其验收条件是否逐条有证据。

## 乙路：查「目标与等价」

给它看的材料：本说明书、那张票的正文（**但不给评论**，防止顺着结论走）、地图 #604 的正文（目标准 与 Notes）、以及本次改动的差异。

要它回答：

1. 这票**声称解决的问题真的被解决了吗**，还是只改了一处写法、把症状挪到了别处。要求它指出具体是哪一段逻辑证明「根因被消除」，而不是「补了一个测点」。
2. 改写渲染或取数逻辑的地方**有没有逐行等价对照**：改前改后拿同一份输入产出同一份结果？用户可见行为有没有变化（多一行少一行、状态名、顺序、时序）？「看起来没问题」不算证据。
3. 改动的**尺度**是否守住本图的约定：宿主取数走结构性收敛、客户端渲染走保守单点改法。超尺度的改动有没有单独说明理由。
4. 这张票的产出**能不能让下一张票照着开工**：下一张票需要的关键事实（调用次数、耗时分布、触发链归属、复现方式、测量手法）有没有给出来；没给出来就算没做完。
5. 验收命令是否在**同一棵工作树**上真跑过、变绿是不是因为被放宽过的检查标准或改过的阈值。
6. 独立判断：如果**这票不做**，地图的目标会不会受影响？会不会只是「有产出但没价值」？

## 两路共同的要求

- 一律自己动手核验，不接受票里或代理回报里的说法作为证据。
- 报告用中文，结构固定：① 总分（0–10）；② 成立的结论（简列）；③ 不成立或证据不足的地方（逐条写清「哪一句、凭什么不成立、怎么才能成立」）；④ 必须整改才能放行的地方（按优先级排序）；⑤ 你自己跑过的命令与结果原文。
- 如果发现的是「细节不完美但不影响目标」的问题，明确标注为「建议，不阻塞放行」，不要与「必须整改」混在一起。
