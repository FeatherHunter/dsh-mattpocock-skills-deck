## Question

用户在子目录里打开会话时，界面上要用**一处简洁的标志**告诉他「当前目录属于工作区 X」。用原型把这个标志做出来给人看，把形态定下来。要定：

1. 标志放在哪：面板顶部（仓库芯片旁边）、环境检查链里多一行、状态栏胶囊、还是几处配合。
2. 标志长什么样：一句话、一个 chip、还是一个图标加悬浮说明（本项目已有的 `HoverTip` 是现成做法）。
3. 文案怎么写：中文与英文各一句，要让人一眼看懂「这是子工作区」以及「工作区根在哪」。
4. 要不要可点：点了把面板切到工作区根的数据、跳到根目录、还是只是说明不可点。
5. 出现与消失的时机：只在子工作区会话里出现，还是根会话也要反向标出「下面有 N 个子目录会话」；跟现有的「未识别仓库」琥珀色芯片、「未初始化」提示是什么关系（替代还是并存）。
6. 与本地 Markdown 后端的关系：那个后端没有仓库名，标志里显示什么。

产出：一个能直接打开看的原型（HTML 或写进仓库临时目录的页面都行）+ 一段结论（选了什么、为什么、边界情形），交给后续落地票照做。需要人一起看原型才能定，属于人要参与的那一类票。

## 原型已出（2026-09-18）

原型文件：`docs/prototype/650-subworkspace-indicator-variants.html`。双击就能打开，没有后端、没有依赖；四个变体按 `?variant=A|B|C|D` 分享，情形与开关也都写在 URL 里。

分支判定：这个问题是「界面应该长什么样」那一支 —— 同一处承载面上的多个变体 + 底部悬浮切换条。四个变体都长在真机已有的两个面上（面板顶部 `Dock.js` 头部、输入框下方的状态栏胶囊），页面把这两个面按真源码的配色与尺寸摆出来，免得在空页面上做判断。

四个变体：

- **A 仓库芯片旁的归属 chip** —— 面板头部、仓库芯片右侧一枚小 chip，悬浮给三行说明；
- **B 状态栏胶囊里的一段** —— 不碰面板，把归属放进胶囊，排在品牌字之后；
- **C 检查链一行 + 首次进入的一次性提示条** —— 进门提示一次，之后永久留在环境检查页里可查证；
- **D 面包屑路径行** —— 把归属做成一行可点的路径导航，工作区根那一节可点。

配八个并列开关，都能现场翻：反向标记（根会话要不要标出「下面有 N 个子目录会话」）、点击行为（打开根目录 / 复制根路径 / 不可点）、标志文字（三稿）、界面语言（中文 / English）、面板标题（图标+字样 / 只留图标 / 整个隐藏）。
六种情形模拟不同数据：GitHub 子目录、本地 Markdown 子目录、GitHub 根会话、嵌套仓库（子目录自带 `.git`）、仓库引用缺失、无仓库目录未初始化。
页面右下「当前状态」随每次切换重画，并按真实像素量出当前文案在各变体里放不放得下。

## 标志本身长什么样：四个做法（2026-09-19 补）

维护者看过第一版后给的意见是「这个胶囊样式和里面文字不好看」，所以要再定一层：**位置之外，这枚标志本身长什么样、上面写什么**。原型里加了「标志做法」开关，四个做法结构不同，并排画在页顶「四向对照」里（都摆在同一个位置对比，点一格就切过去）：

- **① 两段胶囊**：一颗淡底色胶囊，两段文字用一个小箭头连起来 —— skill-calorie ▸ ilife。信息最全、看得出层级，措辞里没有一句系统腔的话；代价是第一次看要猜箭头的意思（靠悬浮补全），实测占 108 像素。
- **② 一行路径**：没有底色也没有边框，等宽字体一行路径 D:\\ilife › packages › skill-calorie，工作区根那一段带紫色下划线。不写解释句，路径本身就是答案；代价是最长约 190 像素，窄面板会被裁，且与旁边的仓库芯片风格接近、容易连成一片。
- **③ 只一枚图标**：17 像素的小方块，里面一枚「嵌套方块」图标，一个字都不写，全部信息放悬浮浮层。几乎不占宽度、面板最干净；代价是不悬停就完全不知道它是什么意思 —— 可发现性最差。
- **④ 一行弱化小字**：没有边框、没有底色，一小段灰字 属于 D:\\ilife，悬停才出现细下划线。最轻、最不像控件；代价是容易被完全忽略，深浅主题下对比度要单独调，否则糊成一片。

原来那版「⊂ 当前目录属于工作区 D:\\ilife」的小胶囊已经退场：符号 ⊂ 在小字号下糊成一个点，整句话读起来像系统报错。另外原型里那圈紫色虚线框是我用来标「本变体新加的东西」的**标注**，不是设计本身 —— 已换成一个小箭头 ❯ 指认，不再挡住标志的样子。

## 看原型时能直接看到的几个结论

- 票面问题 4 里的选项「点了把面板切到工作区根的数据」**已经不成立**：按 #649 定版，子目录会话与根会话同桶，面板显示的一直就是工作区根的数据。还值得争的只剩三个：打开工作区根目录 / 复制根路径 / 不可点。
- 归属标志与「未识别仓库」琥珀色芯片、「该工作区尚未初始化」提示是**并存**关系，不替代：它们说的是两件事（你在谁的里面 / 这个仓库引用没解析出来），而且琥珀芯片那条更紧急，不能被归属标志挤掉。
- 定版原句「当前目录属于工作区 D:\ilife」在面板头部与胶囊里都**放不下**（原型实测：需要 172 像素、可用 148 像素；胶囊里 161 对 148），尾部会被截断 —— 最窄的两个面上得用短版。
- 本地 Markdown 后端的芯片显示的就是工作区根目录名（markdown 的 describe 取路径最后一段，例如 `xiaoshuai`），所以「只留目录名」那一稿在这一档会出现同一个词说两遍 —— 这一档要么显示完整路径，要么把话说成关系句。

## 结论（定稿 2026-09-19）

### 选了什么

- **位置**：A —— 面板头部、仓库芯片右侧。
- **做法**：③ 只一枚图标 —— 不占位、不写字，全部信息放在悬浮浮层里。
- **图标**：文件夹里放着一块（外层文件夹轮廓 + 里面一块小实心方块），SVG 见「落地规格」。
- **文案**：浮层三行固定（结论 → 证据 → 动作），工作区根还没初始化时补第四行；中英各一套，原文见「落地规格」。
- **点击**：点一下打开工作区根目录（复用宿主已有的打开文件夹能力）。
- **出现时机**：只在「所选目录 ≠ 工作区根」的会话里出现；根会话、嵌套仓库（子目录自带 `.git`）、无仓库目录都不出现。
- **没文字的兜底**：第一次出现自动展开一次浮层 + 图标带 `aria-label`。

### 为什么这样选

1. **位置选 A 而不是胶囊或检查链**：面板头部本来就是「这个面板在说谁的数据」的地方，仓库芯片就在那儿；胶囊在窄屏会被折叠优先级先收掉，检查链要用户主动跳过去看。
2. **做法选 ③（只一枚图标）**：面板头部在空间不足时会先隐藏标题文字（真机反正有这套收缩），所以一枚 18 像素的图标等于用最便宜的宽度，换到一条常驻提示。前面实测过：写成句子的小胶囊在原句下有 172 像素宽、可用只有 148 像素，会被截断 —— 写字反而更贵。
3. **不写字的代价用「首次自动展开 + 悬浮」补**，而不是把文案塞回头部；读屏用户由 `aria-label` 兜住（他们没有「悬停」这个动作）。
4. **文案只回答一个问题**「面板数据是谁的」：第一行给结论（数据来自哪个目录），第二行给关系（当前目录是它的子目录），第三行给动作。后端名与仓库芯片内容不放（芯片上已有），判定依据不放（哪一层有 `.git` 是环境检查页那一行的事）。
5. **第四行是给失败模式写的**：今天在子目录里会看到「该工作区尚未初始化」，人会就地重新初始化，于是在同一个仓库里长出第二套配置与票仓 —— 所以只有工作区根尚未初始化时才补一句「{工作区根}还未初始化」；根已初始化时不写「不用重新初始化」这类安慰话。

### 与既有提示的关系

与「未识别仓库」琥珀色芯片、「该工作区尚未初始化」提示**并存**，不替代：图标放在仓库芯片右侧，两条既有提示一个都不动。仓库引用缺失那一档，图标与琥珀芯片同屏。

### 边界情形

六种（GitHub 子目录 / 本地 Markdown 子目录 / 根会话 / 嵌套仓库 / 仓库引用缺失 / 无仓库目录）的图标出现与首行显示，逐条列在「落地规格」的对照表里，原型里都能点到。新增的第七种情形「子目录 · 工作区根还没初始化」专门用来把第四行看全。

### 本期不做

根会话反向标记「下面有 N 个子目录会话」：它要读会话清单（DSH 的 `sessions.list`），属新数据源，不在 #653 现有范围里。建议记进地图 #647 的 Not yet specified，需要时另开票。

## 维护者选定：③ 只一枚图标（2026-09-19）

维护者在四个做法里选了 **③ 只一枚图标** —— 头部只放一枚 18 像素的小图标，不写字，全部信息放到悬浮浮层里；位置仍取 A（面板头部、仓库芯片右侧）。选它之后要补齐两件事：图标本身画什么，以及浮层里到底放什么信息。

### 一、图标：12 像素下能不能一眼看懂「我在一个更大的目录里面」

原型里做了四枚候选，直接摆在「四向对照」③ 那张卡里挑（右上「图标」开关同样能换）：

- **文件夹里放着一块**（默认）：外层是文件夹轮廓，里面一块小实心方块 —— 文件管理器里最熟的语言，一眼就是「你所在的子目录在这个文件夹里」。
- **方块套方块**：最中性，不带「文件夹」的固有含义，纯讲「里面还有一层」；头部已经有仓库芯片时，它不会和「仓库」混淆。
- **从框里向上跳**：一个方框加一支向上跳出的箭头 —— 讲的是「上一层」，正好和点击动作（打开工作区根目录）一致，但它讲的是动作，不是「归属」这个事实。
- **树上的一个节点**：一条竖线加一个圆点（我在这一支上）—— 层级感最强，但小尺寸下容易被看成一条普通折线。

**已选定：文件夹里放着一块**（维护者 2026-09-19 看过四枚之后点的头）。备选留着：担心与仓库芯片抢意思时换「方块套方块」，想强调「上一层」这个动作时换「从框里向上跳」。四枚统一 16 视框、13 像素绘制、描边 1.3 像素、`currentColor`，深浅主题都跟着字色走。

### 二、浮层里放什么：从第一性原理倒推的那几行

顺序就是信息优先级：**结论 → 证据 → 动作 → 提醒**。

1. `面板数据来自工作区 D:\ilife` —— 用户此刻只有一个问题「我看到的这份数据是谁的？」，所以第一行直接回答它，先不讲关系。
2. `当前目录是它的子目录：packages › skill-calorie` —— 关系要靠两个目录并列才成立；只给一个路径，用户会以为那就是自己打开的目录。用相对尾巴省长度。
3. `点一下打开 D:\ilife` —— 可点就必须写清点了会发生什么。
4. `{工作区根}还未初始化` —— **只在工作区根还没初始化时才出现**。从失败模式反推：今天在子目录里会看到「该工作区尚未初始化」，人会去重新初始化，于是在同一个仓库里长出第二套配置与票仓。根已经初始化时不出这一行（维护者 2026-09-19 定：不要「不用重新初始化」这种安慰话）。

**不放什么**：后端名与仓库芯片的内容（芯片上已经有了）、判定依据（哪一层有 `.git`，那是环境检查页那一行的事）。浮层只回答一个问题，多放一句就多一分噪音。中文与英文各一套，切「界面语言」就能对照。

### 三、图标没有文字的兜底（要和图标一起落）

- **第一次出现自动展开一次**这个浮层（原型里做成开关，默认开）。否则第一次见到的人不会去悬停，一枚没字的图标等于白放。
- 图标必须带 `aria-label`，内容是上面三句话的合并 —— 读屏用户没有「悬停」这个动作。
- 极窄面板下它只有 18 像素宽，永远不会被挤掉，这正是选 ③ 的主要理由。

## 落地规格（#653 可以照做）

定下来的三件：**位置 A**（面板头部、仓库芯片右侧）、**做法 ③**（只一枚图标，不写字，信息全在浮层里）、**图标「文件夹里放着一块」**。

放在仓库芯片右侧，18×18 的点击区（圆角 5、边框 `rgba(192,132,252,.38)`、底色 `rgba(192,132,252,.07)`、悬停时边框加深），里面 13×13 画图：

`currentColor` 跟着字色走，深浅主题不用另配颜色；必须带 `role="img"` 与 `aria-label`（见下）。

### 浮层文案（中英各一套，顺序固定：结论 → 证据 → 动作 →（必要时）提醒）

1. 中文 `面板数据来自工作区 {工作区根}` / 英文 `Panel data comes from workspace {root}`
2. 中文 `当前目录是它的子目录：{相对路径}` / 英文 `The current folder is a subfolder of it: {relative path}`
3. 中文 `点一下打开 {工作区根}` / 英文 `Click to open {root}`
4. **只在工作区根还没初始化时出现**：中文 `{工作区根}还未初始化`；英文 `{root} is not initialized yet`。根已经初始化时**不出这一行** —— 不写「不用重新初始化」这种安慰话（维护者 2026-09-19 定）。

第 2 行的相对路径 = 所选目录去掉工作区根前缀的那一段，用 `›` 连接（例：`packages › skill-calorie`）；分隔符统一成 `›`，不要把反斜杠原样吐给用户。

### aria-label（读屏用户没有「悬停」这个动作）

`面板数据来自工作区 {工作区根}；当前目录是它的子目录：{相对路径}；点一下打开 {工作区根}`（根还没初始化时把第 4 行也接上）

### 出现与收起的时机

- 只在「所选目录 ≠ 工作区根」时出现；根会话不出现；子目录自带 `.git`（嵌套仓库）不出现 —— 那时工作区根就是它自己。
- 第一次在某个工作区的子目录会话里出现时，**自动展开一次**这个浮层；用户收起之后同一个工作区不再自动展开（「已读过」按工作区记一份状态，与 C 那条一次性提示条共用同一份记录）。
- 悬浮延迟照 `Tip` 的锁定预设：500 毫秒显示、160 毫秒隐藏。
- 与「未识别仓库」琥珀芯片、「该工作区尚未初始化」提示**并存**：图标放在仓库芯片右侧，不替代任何一条既有提示。

### 边界情形（原型里都能点到）

| 情形 | 图标 | 浮层第一条显示 |
| --- | --- | --- |
| GitHub 子目录 | 出现 | `面板数据来自工作区 D:\ilife` |
| 本地 Markdown 子目录 | 出现 | 工作区根的**目录路径**（不是仓库名） |
| GitHub 根会话 | 不出现 | — |
| 嵌套仓库（子目录自带 .git） | 不出现 | — |
| 仓库引用缺失（未显示仓库名） | 出现，与琥珀芯片同屏 | `面板数据来自工作区 D:\ilife` |
| 无仓库目录 / 未初始化 | 不出现 | — |
