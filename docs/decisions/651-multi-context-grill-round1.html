P1

这一问放在哪？

前因：今天点黄条一步就注入，面板里从没问过布局。后果：在面板里问要接回那张断线的卡（多一次点击）；不在面板里问，就只能让 AI 在聊天里问，答案与措辞都不由插件掌握。
甲 · 接回小卡：点黄条 → 出一张小卡（后端 ＋ 域文档布局 两组单选）→ 确认即注入（推荐）与开门链那张选后端的弹窗同一形态；一次交互答完两件事。
乙 · 保持一键注入，由注入文案让 AI 在会话里问零 UI 改动，但答案与措辞每次都可能不一样，面板上也不留痕。
丙 · 只在没绑定后端时弹卡，已绑定时默认单上下文点击最少，但多项目仓库会拿到错默认，还得靠用户自己发现。
➡️ 推荐甲。既然定「由用户决定」，就要放在一个保证问到的位置——聊天里问依赖 AI 记着问，面板里问则由插件保证。新增成本很低：那张卡已经在代码里，接回一行调用、加一组单选即可。
选甲利
  • 答案确定，注入文案里能直接写「已选定 X」
  • 用户当场看到布局是初始化的一部分
选甲弊
  • 主路径多一次点击（今天一键即注入）
  • 要加中英文案并同步几条门禁
P2

两个选项怎么写、默认选哪个？

前因：仓库有一条纪律——界面上的字一律说人话，不出现内部术语（「子工作区」「上下文」这类词只用在票名与文档里）。而「单上下文／多上下文」本身就是要翻成人话的词。
选项一：一个仓库共用一份词表（默认选中 · 推荐）领域词汇集中放在根目录 CONTEXT.md，架构决定放在 docs/adr/。绝大多数仓库选这个。
选项二：每个子项目各有一份词表子项目各自一份 CONTEXT.md（例如 packages/foo/CONTEXT.md），根目录放一份 CONTEXT-MAP.md 指向它们。
选项三：以后再定不推荐——初始化不写，后面补写要回头改 docs/agents/domain.md 与 AGENTS.md 两处。
➡️ 推荐：只留两选项、默认选「一个仓库共用一份」。理由：多数仓库就是一份；两个选项都能在选项下方各配一句人话解释，用户不必理解「上下文」这个词。
这样定利
  • 不出现内部术语，符合既有纪律
  • 默认合多数人，回车即可继续
这样定弊
  • 两个选项各要多一句解释，卡片会变高
P3

选了「每个子项目各有一份」之后，要不要当场列清单？

前因：初始化时仓库可能是空的——子项目目录还不存在，名字也可能还没想好。而地图里最有价值的一节是「这些子项目之间怎么关联」，这一节初始化时根本写不出来。
只记结论：这是多项目仓库，地图与各份词表等真正落到第一个词条时再建（推荐）初始化只在 docs/agents/domain.md 与 AGENTS.md 上标明布局。
当场让用户填各子项目的名字与目录，初始化就把空壳铺出来会留下一堆空文件；子项目改名或调整后还要回来改。
➡️ 推荐只记结论。空仓库场景下，多问一层只会拿到不准确的答案；这两份文件本来就是"第一个词条落定时才创建"的设计。
这样定利
  • 不在用户仓库里留空文件
  • 空仓库下也只问一个问题
这样定弊
  • 地图要等到第一次真正写词条才出现
P4

绕开弹窗的那两条入口怎么办？

前因（已修正）：设置页那条「复制提示词」的入口经查已经不存在。今天真正绕开弹窗、直接注入的是两条——状态栏黄条，和检查页那张红牌的「执行初始化」按钮（它连共用的注入入口都不走）。后果：这两条若不问，同一个仓库会因为用户从哪儿点进去而得到不同布局。
甲 · 单漏斗：注入前若还没选过布局，先弹那张卡，选完再注入（推荐）所有走共用注入入口的路（黄条、开门链、切换后端）自动获得这个行为；检查页那条红牌按钮改成也走同一个入口，一处实现处处生效。
乙 · 只给黄条按钮弹卡，其余入口由注入文案兜底问一句改动少，但同一次初始化会因为入口不同而问法不同。
丙 · 谁都不弹卡，全部由注入文案让 AI 在会话里问等于回到 P1 的乙，与已定的「在面板里问」不一致。
➡️ 推荐甲。插件里问得到的地方就由卡片问：问一次，答案跟着这一次注入一起走；只有一个入口要改接线，比「有的入口问、有的入口靠聊天」更可预期。
选甲利
  • 任何入口都不会漏问，答案是确定的
  • 一处实现覆盖四条路径
选甲弊
  • 检查页那条按钮要改接线
  • 已初始化的仓库重跑时也会再问一次（与 P5 一致）
P5

选错了能不能改？选择要不要记住？

前因：产物 docs/agents/domain.md 会写明本仓库是哪种布局，用户随时能改那个文件；面板上没有「改布局」的入口。要不要把选择存进工作区状态，影响的是下次初始化会不会再问一次。
不存状态、不加新入口：想改就改那个文件，或重跑一次初始化（推荐）与「插件不擅自改用户仓库里已有的东西」同款口径。
记住上次选择，下次初始化跳过提问省一次点击，但要新增一份持久状态与它的一致性口径（换目录、换后端、删了文件怎么办）。
➡️ 推荐不存状态。这个选择一辈子只做一次，省一次点击不值一份新状态；重跑初始化本来就会再问一次，天然就是"改"的入口。
这样定利
  • 不新增持久状态与一致性问题
  • 重跑初始化即可改，路径单一
这样定弊
  • 面板上找不到"改布局"的字样
补

「用户这个仓库是哪种布局」这句话写在哪儿（并入定稿草案，不再单独占一问）

前因：插件初始化时写进用户仓库的文件里有两处会提到布局——docs/agents/domain.md（技能种子模板里只有两张结构图，没有任何结论句）与用户仓库 AGENTS.md 的 ## Agent skills 块里那句布局摘要。后果：没有结论句时，读的人只看见两张图，不知道该按哪张做。
甲 · 两处都写同一句（推荐，随定稿草案一起确认）domain.md 里加一行「本仓库是单上下文／多上下文」；AGENTS.md 那一行按同一答案写。
乙 · 只写 domain.md少改一处，但 AGENTS.md 是 agent 每次开场先读的那份。
