1钩子：让测试跑起真源

Node 本来只认识 .js。转成 .ts 后，引用处还写 ./x.js，钩子负责领到同名 .ts。没有同名文件就放行，行为和今天一样。

看到 ./x.js
 → 同目录有 x.ts？有就加载它
 → 没有就交给 Node 原样走
 → 裸包名与 node_modules 一律不碰

为什么用同步的不用异步的：仓库还有旧 require('./x.js')，异步钩子管不到它，同步的才同时管 import 和 require。

记住一句：文件 scripts/ts-hook.mjs 共 79 行，挂在 4 个入口（测试、并行链、CI、全链冒烟）。Node 下限以根 package.json 为准。

2归属表：每条门禁在守哪

门禁就是 tests/verify-*.js 里判不变式的脚本，红了就挡发布。今天链上 228 步。

归属表 tests/gate-map.json 回答每一步在守哪块源码：能推出归属 200 步，28 步算不出（只指向文档脚本），20 步只跟构建产物有关。每步都写了理由，比如“载入模块 1 条”“读文件 2 条”。

漏了什么症状：临时目录没进排除表会被误报；某域扫到 0 文件构建直接失败；扫不到还判绿的三处已改成判红，下限 200 守着。

3金标准：证明没改坏的尺子

九个工具各跑一次代表性调用，去掉时间戳路径后逐字节存档，落在 tests/tracker-contract/fixtures/golden-receipts/01~09。之后每转完一个单元重跑，差一个键即红。

另一样叫活样板：真挑一个文件转成 .ts 留仓库，改一行三关都看见。它证明链存在，不能证明故意写错会红。

4搬家：最大的 diff 感

133 个文件一次搬完，引用改 138 处，只搬位置不改行为。记住 3 条例子就有感觉：

旧 → 新
deckIssueGet.js → src/deck/tools/issue-get.ts
shell.js → src/deck/shell/call-shell.ts
backends/github/*.js → src/tracker/rooms/github/*.ts

验收三条：改名提交、源码树下无生成物、包内份数不变且改坏必红。发布跟随是另一票：构建改 300 行，三棵新树转译进包，包内按源码镜像。
