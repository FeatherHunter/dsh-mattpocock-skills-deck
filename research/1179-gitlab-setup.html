地图10 · GitLab 房

给 GitLab 房接通真环境
—— 从零配置指南

用途：票 #1179（真实采样固件与生成脚本）的前置第 0 步
你的起点：有 GitLab 账号，但从来没用过 GitLab
目标：让这台机器上有一个真能对话的 GitLab，而不只是文档上写的 GitLab

一、为什么要做这一步

GitLab 房今天全部关于「远端会怎么回话」的判断，都是照着官方文档写的，一次真命令行都没跑过。九条新能力、887 条契约测试断言、能力登记表，全建立在纸面形状上。

这件事本身不丢人——本地没有 GitLab，只能这样。但它有一个后果：文档写错了、或者某一档账号根本用不了，今天没人知道。把「我以为它会这么回」换成「它真的这么回」，是这张票要解决的唯一问题。

而且还有一件更急的事压在它后面：票 #1176 记着一个会真删数据的缺陷（取消父子关系时可能把这张票全部关联链接一起删掉）。这个缺陷必须真跑一次才能定案——不真跑，改与不改都是猜。

二、这台机器现在缺什么（实测，不是推测）

东西状态说明
git已有C:\Program Files\Git\cmd\git.exe

三、六步做完

1装 glab

谁做：我可以替你做（下载 + 解压 + 放进工具目录）。你要自己做也行，命令都在下面。

winget 这类包管理器这台机器上没有，所以走官方发布页的压缩包。当前最新版是 1.123.0（2026-10-13 发布），Windows 64 位压缩包：

https://gitlab.com/gitlab-org/cli/-/releases/v1.123.0/downloads/glab_1.123.0_windows_amd64.zip

解压后里面有 bin\glab.exe。照 gh 的摆法，放到：

D:\0Tools\GitLabCLI\glab.exe

然后把这个目录加进用户级 PATH（不是临时 PATH）：

[Environment]::SetEnvironmentVariable('PATH',
  [Environment]::GetEnvironmentVariable('PATH','User') + ';D:\0Tools\GitLabCLI\', 'User')

为什么强调「用户级」：临时改当前窗口的 PATH，只对那一个窗口有效，程序下次启动就看不见了。写进用户级 PATH 才是持久的。

这一步有个坑，必须知道

DSH（也就是我运行在里面的这个程序）用的 PATH，是它启动那一刻从系统里读到的那一份。你在运行中改了 PATH，它自己看不见——这和 GitHub 那边的 DSH_GH_PATH 是同一个限制：那个变量也是只有宿主进程启动时就存在才有用。

两个办法，二选一：

  • 办法甲（干净）：按上面装好、加好 PATH，然后重启一次 DSH。以后长期都顺。
  • 办法乙（马上能用）：先把 glab.exe 放进 D:\0Tools\GitHubCLI\——这个目录已经在 PATH 上了，立刻就能找到。名字上难看一点，但不用重启。

另外，我的命令行调用不受这个限制：我可以用完整路径 D:\0Tools\GitLabCLI\glab.exe 跑它。受影响的是插件自己去解析 glab 那条路。

2建一个专门的沙箱项目

谁做：你，在浏览器里。这件事只有你能做（要登录你的账号）。

在 gitlab.com 上建一个私有项目，名字例如 dsh-gitlab-sandbox：

  • 右上角 + → New project → Create blank project
  • Project name 填 dsh-gitlab-sandbox
  • Visibility 选 Private
  • 下面那个「Initialize repository with a README」勾上，这样项目一建好就有内容可拉

为什么要专门建一个，不能拿现成的仓库

因为采样和验证是真的动手：建票、关票、改标签颜色、给两张票挂关联、再取消关联。这些动作会留下痕迹，甚至删掉东西。拿你在意的仓库做这件事，等于拿真账本做实验。

3造一个令牌

谁做：你，在浏览器里。令牌原文不要给任何人看，包括我。

令牌（Personal access token）就是给命令行用的一把钥匙。直达链接（已经把名字和要勾的作用域预填好了）：

https://gitlab.com/-/user_settings/personal_access_tokens?name=dsh-glab&scopes=api

手点的路径也一样：右上角头像 → Edit profile → 左侧 Access → Personal access tokens → 右上 Generate token 下拉里选 Legacy token。

要勾的东西：

项目填什么为什么
Token namedsh-glab以后好认
Expiration date默认 365 天即可到期会自动失效，到时再换
Scopes只勾 api 一个见下面

为什么只勾 api 就够

官方文档在作用域表下面有一条脚注写得很清楚：对个人令牌来说，api 这一个作用域同时覆盖「调 REST 接口」和「通过 HTTPS 推代码」两件事。所以不需要再勾 write_repository。

顺带一提：write_repository 那一行反过来还专门写着「不支持 API 认证」——所以就算勾了它，也替代不了 api。

两条红线

  • 令牌只在生成的那一刻显示一次，刷新页面就再也看不到。请当场存到一个临时文件里。
  • 不要把令牌原文贴进和我的对话。对话会被完整记进会话记录，贴一次就等于把它写进了日志。正确的做法是：存进文件，登录时用文件喂给 glab，登完把文件删掉。

4登录

谁做：你，在自己的终端里。这一步必须你来，因为只有你手里有那把钥匙。

先把这个令牌存成一个临时文件，比如 D:\tmp\token.txt（里面只放令牌那一行），然后在终端里跑：

glab auth login --hostname gitlab.com --stdin < D:\tmp\token.txt

然后立刻删掉那个文件：

Remove-Item D:\tmp\token.txt

为什么用 --stdin 而不是直接把令牌写在命令里：写在命令行参数里的东西会进命令历史；用文件喂进去不会。

凭据存到哪了：glab 默认把凭据存进 Windows 凭据管理器（系统的钥匙串），不是明文文件。只有加 --insecure-storage 才会落到 ~/.config/glab-cli/config.yml 明文里——我们不这么干。

5把项目拉到本地

谁做：你（一条命令），或者做完第 4 步之后叫我做也行。

git clone https://gitlab.com/<你的命名空间>/dsh-gitlab-sandbox.git

为什么必须本地有一份：有一条能力叫「从本地仓库认出它对应远端哪个项目」——它是读 git remote 认出来的。本地没有这份仓库，就没有可测的对象。

推到远端需要身份，而你的令牌已经被 glab 记下来了。如果 git push 提示要密码，密码填令牌原文即可（用户名随便填一个非空字符串）。

6三条验证命令

谁做：你跑一遍，或者告诉我「装好了」，我来跑。

# 1) 看登录状态
glab auth status

# 2) 看它认为「我是谁」——这条对应契约里的「当前用户」能力
glab api user

# 3) 看这个项目的权限——这条回的话里就有 permissions 那一格
glab api "projects/<命名空间>%2Fdsh-gitlab-sandbox?simple=true"

第 3 条要特别注意：地址里的斜杠必须写成 %2F，这是 GitLab 的规矩（它叫 URL 编码的路径）。这一格回话里的 permissions，正是「我能不能推、能不能整理票」那条能力要读的地方。

三条都通了，第 0 步就算完成。

四、做完之后会发生什么

  1. 我接着做 #1179：真跑一遍这些接口，把回话脱敏后落盘成固件，写一个能一键重采的生成脚本，再让机器离线比对形状。从此以后每一条 GitLab 改动都能离线复验。
  2. #1176 那个删关联的缺陷也就有了定案的条件——真跑一次「取消父子关系」，看链接到底有没有消失。
  3. 「哪些形状已经真采过、哪些还只是文档说的」会有一份清单，写在明面上，不再靠门禁全绿把它盖过去。

五、关于免费档：要有心理准备

你用的是免费账号，而 GitLab 有些能力是要付费档的。已知的两处：

  • 原生的父子层级（epics 那一支）是付费的。所以这一房从一开始就不走它，而是把父子关系落成平级链接——这是设计选择，不是缺陷。
  • 阻塞边在免费档常常拿不到原生支持，代码里备了一条降级写法（回落到正文里的「Blocked by:」那一行）。

反过来，这次九条新能力要用的接口，查过文档都是免费档就有的。举一条最容易踩的：数票数用的那个统计接口（GET /projects/:id/issues_statistics），官方文档标的是「Free, Premium, Ultimate」三档全有，回话形状是 {"statistics":{"counts":{"all":20,"closed":5,"opened":15}}}——和我们代码里写的一模一样。

但「文档说有」和「你的账号真的有」是两件事。这正是要真跑一遍的原因：跑完就知道哪些是真能用的，哪些只是文档上说能用。
