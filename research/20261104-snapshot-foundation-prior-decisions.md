# 面板快照「本地文件为权威副本」的前置决策盘点

日期 2026-11-04，只读调研，未改源码、未提交。目的：回答围绕「面板快照即工作区数据单一来源」已经定版了哪些决策、哪些与新要求冲突、哪些明确不做。

新要求（下称「文件为根」）：本地快照文件本身就是根基/权威副本；DSH 重启后直接加载它；后续一切增删改查都在它上面。

## 1. 已定版口径

1. **单一快照**：面板工具区的业务数据只有一份快照，客户端不再保留第二份业务缓存（issueCache 与地图子票桶退役为投影）。docs/adr/20261030-panel-snapshot-single-source.md:33；验收第 13 条（tests/fixtures/1700/closeout-matrix.json）
2. **权威归属（现行）**：权威副本在宿主（含落盘回放），面板渲染读它的投影。docs/adr/20261030-panel-snapshot-single-source.md:33；GLOSSARY.md:71 同款措辞
3. **物理分层、逻辑一份**：宿主存与合并、面板只读；面板临时取到的数必须先经宿主合并回快照再投影。同上 :35
4. **增量合并三态**：读结果与写回执按字段组增量合并；有值/明确为空/不知道三态由类型承载，未表达的字段保留上次已知，只有完整来源能清空。同上 :39–:42；docs/adr/20261030-github-room-channel-layering.md:45
5. **版本门**：入站结果带「取数开始时的快照版本」，早于当前快照的整份丢弃、不回填字段；版本号单调递增并随盘持久化，时间戳只用于显示。同上 :43
6. **TTL / 新鲜度**：TTL 只决定算不算新鲜、何时后台重取，不决定能不能显示；取数失败保留上次数据并标记，绝不清空。同上 :48–:49
7. **落盘回放**：磁盘回放带 schema 版本与来源；旧格式缺来源按未知、不删字段；回放完整度降为「上次已知（时间）」。同上 :50–:51
8. **按需细节上限**：详情有条数与字节上限、LRU 淘汰；淘汰只清内容、留「曾取过/时间」标记；行、父子边、依赖边、子票计数永不淘汰。同上 :62–:63
9. **首屏口径**：全部开放票（工单＋PR）＋开放容器全部子票（含已关闭）＋已关闭地图容器薄行；已关闭历史行不预装，按需翻页。docs/design/677-issue-pool-completeness-spec.md:155–:163；ADR 同 :34
10. **视野模型**：正在看的工作区之外没有长期定时器；活跃集合上限 2；离开最多留 30 秒；90 秒无信号全部收摊；用量与工作区数量无关。docs/adr/20260924-refresh-budget-architecture.md 判据 I2、I4；计划 :73
11. **请求预算**：常规增量每轮 ≤3、完整枚举 ≤16、单次详情 ≤5 类、并发 8；按插件读额度算（约 1225 次/小时）。ADR 同 :100；计划 :31；房间分层 :52；常量在 src/refresh/kernel/host-budget.ts
12. **单一入口**：所有后端操作走 Tracker 会话，闸与账本是操作管线里的拦截器，调用方绕不过；未知/离网/耗尽三者分开。docs/adr/20261023-tracker-single-entry.md

## 2. 冲突清单

### 2.1 必须改、且要动代码

**C1 权威归属句（字面冲突）** 现文 ADR:33「权威副本在宿主（含落盘回放）」。冲突：把文件降为宿主的回放素材。改成「权威副本是这个工作区的本地快照文件；宿主内存是它的读写工作副本，面板渲染读快照的投影。任何改变业务数据的写，先落文件再让界面看到」。文档 ADR:33 与 GLOSSARY:71 两处同款措辞一起改；代码上写失败不能再吞（src/refresh/rooms/host/git-execution.ts:382 现在写失败不影响主流程），否则「文件为根」不成立。

**C2 重启回放定位（字面冲突）** 现文 ADR:50「跨重启先画磁盘里的上次快照，再在后台校准」。冲突：「先画…再校准」把文件当临时首帧，新要求是文件直接就是答案。改成「重启时直接装载文件作为当前快照，再在后台按增量合并校准」。实现现在连「先画」都没做到：src/refresh/rooms/host/session-snapshot-cache.ts:350 先调 cacheSnapshotIsCurrent，后者发一次在线索引探测（src/refresh/rooms/host/issue-list-fetch.ts:239–:254）；探测回「变了」时整份回放被放弃、改走完整重建（p50 约 25 秒，#1436），首帧根本拿不到文件内容。要满足新要求，回放必须无条件先发生，探测退到后台。

**C3 回放降级句（字面冲突）** 现文 ADR:51「回放内容的完整度降为『上次已知（时间）』」。冲突：文件里的数据永远只能是「上次已知」，它就不可能是权威；写入时明明记下了来源。改成「回放沿用写入时的来源与完整度；只有被更晚的完整来源证明过期的字段，才降为上次已知」。文档 + 回放字段构造（diskReplayFields）；验收第 10 条把「回放完整度降为上次已知」写成判据（门禁 tests/verify-1692-disk-replay-eviction.ts），要一起改。

**C4 首屏范围 × 整份重建覆盖（语义冲突，本次最重要）** 现文 ADR:34 与 677 §6.3 规定快照只装开放工作集、开放容器子票、已关闭地图容器行。冲突：写回是整份的（src/refresh/rooms/host/session-snapshot-cache.ts:422），#1855 实测先前合并进来的已关闭行在完整重建后消失（缺陷 B′）。「一切增删改查都在文件上」不能容忍一次校准删掉已知行，§2.2 也要求只有完整来源能删。要定：重建结果按增量合并进文件、不得整份替换；删除只允许来自整仓完整枚举。若坚持只存工作集，就得另设一份「已知行台账」供重启兜底，否则文件答不出已关闭票，而 #1855 的胶囊正需要它。文档 ADR:34 补一句「文件内容是工作集，不是重建目标」；代码改重建写回路径。

**C5 文件身份与路径（语义冲突）** 现文：缓存目录 = 宿主进程 cwd/.dsh-mattskillsdeck-cache/，文件名 owner__name.json（src/refresh/rooms/host/git-execution.ts:335–:346）；无 owner/name 时读写直接返回（:351、:371）。冲突：三个「重启后直接加载」的前提都不成立——(a) 路径随宿主进程 cwd 变，同一工作区换个启动目录就看不到上次文件；(b) 按仓库名共用，两个工作区根同仓库会互相覆盖（docs/adr/20260918-subworkspace-identity-root.md:69 说缓存这样共用「这一条不动」，但升格为权威副本后必须按工作区根分文件）；(c) markdown 与非 git 镜像没有 owner/name，根本没有文件（#1850、#1838）。改成：路径由唯一工作区键出口（src/shared/workspaceKey，20260918 :54）派生，放稳定的应用数据目录（不要放仓库里，7MB 的 JSON 会被提交），与进程 cwd 无关，三个后端都有。认根规则（docs/adr/20261103-workspace-root-upward-search.md）不动。

**C6 两份持久快照（语义冲突，先定名）** 现文：宿主写 JSON 文件；客户端另把快照写进 IndexedDB（src/refresh/rooms/client/snapshot-cache-store.ts:162–:214，库 dsws-cache，键是工作区键，上限 24 条，落盘前剥掉 workRouteTable :128–:135）。冲突：两份都能在重启后画出界面，谁旧谁新没有单一答案，「文件」指哪一份必须先定。建议宿主文件为根，客户端 IndexedDB 降为一次性首帧提示（读到后仍以宿主文件为准），或直接退役。

**C7 写路径与静默失败（语义冲突）** 现文 ADR:55「写回执先合并…随后防抖触发整仓校准」；实现是先并内存、再写盘（src/refresh/rooms/host/patch-wiring.ts:43、detail-snapshot-merge.ts:98–:100），写盘失败被吞（git-execution.ts:382）。冲突：「一切增删改查都在它上面」要求文件写成功才算写成功；现在磁盘是事后副作用，写失败界面照旧显示成功，重启就丢（#1853 已证明只存内存的状态活不过重启）。改成「写回执先合并并落盘，随后防抖触发整仓校准」，合并内核（src/refresh/kernel/snapshot-merge.ts）不变；写失败进通知中心、不做乐观修改。

### 2.2 文档为主

**C8 可见的「上次快照」文字（措辞冲突）** 现文 ADR:50 第二句「界面要能分辨『这是上次的快照、什么时候的』」。冲突：#1855 维护者明确不要胶囊上出现这类文字（2026-11-03 19:50、2026-11-04 00:10 原话）；面板列表的来源时间仍要留。改成「面板列表保留来源与时间；胶囊等空间受限处不加可见文字，未知就按未知画」。现在的胶囊已经这么做，只改文档。

**C9 降级标记跨重启（措辞 + 小改）** 现文 ADR:68「当前是否降级仍从快照的降级标记与时刻派生」。冲突：文件为根后，重启第一眼会拿着上次会话的标记宣称「现在降级中」，其实还没探测。改成「装载后到第一次探测前，降级状态按上次已知显示，不宣称当前」。文档一句，状态派生处加「未探测」态。

**C10 坏文件与旧格式（口径缺口）** ADR:51「旧格式缺来源按未知、不删字段」兼容；但读文件任一步失败就返回 null（git-execution.ts:355–:359），格式版本不符整份丢弃（research/757-snapshot-size.md）。文件是根之后，「读不出来」不能等于「没有数据」，否则一次升级或半截写就把工作区清空。改成：读失败先把原文件改名备份、报通知，再允许重建；版本 3→4 原地迁移，不整份丢。

### 2.3 不是冲突，但要写进新 ADR 的边界

**C11 视野与预算的护栏**：文件为根不能变成「启动时把所有工作区文件都读一遍」或「监听文件变化」——I2 要求活跃集合上限 2、90 秒收摊、视野外无长期定时器；I4 要求用量与工作区数量无关（20260924；计划 :73）。装文件只在工作区被打开时发生；装完的后台校准仍走 ≤3/≤16 的预算（ADR:100、计划 :31）。重启装载本身应是 0 请求——现在先花一次探测，正是 C2 要拆的。

**C12 单一入口不破**：文件读写是本地操作，不进 Tracker 会话的闸与账本；但凡要问后端的（校准、写回执）仍必须走唯一入口（20261023）。新 ADR 补一句「本地文件不是第二个后端出口」。

## 3. 明确不做 / 已放弃

- **版本控制页、设置、技能、检查链不进快照**：它们各有读取与持久化路径，塞进来会把单一快照变成全局状态桶。docs/design/20261030-panel-snapshot-and-room-layering-plan.md:79；ADR:34
- **不做跨后端通用分层框架；GitLab 与 Markdown 不动**：这套分层只为解 GitHub 房间的重复取数。计划 :80
- **不做系统级/桌面通知**：宿主未暴露该能力，只做面板内通知中心。计划 :81
- **不追求 counts 与 GHES 的 REST 等价**：能力表标未知，界面按未知渲染。计划 :82；验收第 24 条只有夹具
- **会话私有状态不进快照**：当前打开哪张票、草稿、筛选都不进（ADR:61）；workRouteTable 落盘前剥掉（snapshot-cache-store.ts:128–:135，#1355），因为「本会话行」标记按请求会话算，跨会话共享会认错行
- **已关闭历史行不预装，按需翻页**（#690）：首屏体积与请求预算的取舍，677 §6.3 :158–:160
- **不新增后台定时器**：通知清理挂在既有读写刷新节拍上。ADR:70；20260924 I2
- **不做乐观写**：写失败不改本地、原因进通知中心。ADR:56
- **不做整行替换**：所有写入走字段组掩码。验收第 8 条
- **胶囊上不显示「这是上次快照/什么时候」**：#1855 维护者原话，已按此实现

## 4. 已知遗留边界现在是否仍成立

- **跨容器阻塞者首帧不显示**：仍成立。ADR §7 :117；规格 §13
- **已关闭容器首帧子票为空**：仍成立。同 :117；677 §6.3 :162 补记冷启动会丢已关闭规格容器行（薄行无正文、无 wayfinder:map 标签可认）
- **GHES 只有夹具、无真机**：仍成立。ADR §7 :118
- **真实演练只读，写回执用合并纯函数模拟**：仍成立。同 :121
- **依赖与子票端点在演练中按即时失败注入**：仍是演练手法。同 :122
- **markdown 与非 git 镜像没有快照文件**：成立（#1850、#1838；git-execution.ts:351、:371 无 owner/name 直接返回）。这条与「文件为根」正面冲突，是 C5
- **磁盘回放要先过一次在线索引探测，探测说变了就不回放**：成立（issue-list-fetch.ts:239–:254；session-snapshot-cache.ts:347–:352）。这是 #1850 的机制之一，对应 C2
- **整份重建覆盖文件、写失败静默**：成立（session-snapshot-cache.ts:422；git-execution.ts:382），对应 C4、C7
- **客户端 IndexedDB 是第二份持久快照**：成立（snapshot-cache-store.ts:162–:214），对应 C6
- **7MB 整份 JSON 读写、解析在宿主侧**：成立（research/757-snapshot-size.md）；文件升格为权威副本后，启动读取与写放大的代价要重新量

## 5. 一句话结论

单份快照、增量合并三态、版本门、按需细节上限、首屏口径都能原样保留；真正要改的是三处：权威归属的措辞与写入时序（C1、C7）、重启回放被在线探测挡住的顺序（C2）、文件的身份与路径（C5）。再加一条新规则：重建只能合并、不能整份覆盖（C4）。只改文档交付不了这个要求。
