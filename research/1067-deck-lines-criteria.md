### 1.3 deck 调到这些代码的真实调用链（静态引入加运行时接线，两条都要看）

只看静态 `import` 会漏掉一半真相，因为 deck 工具的设计就是「壳里不直接引用闸与后端实现，依赖由接线方从构造函数传进来」。证据与链条：

- 九个 deck 工具的静态直接引入（来源：`grep src/deck` 共 28 条；以 `src/deck/tools/map-snapshot.ts:8-14` 为例）：共用的薄壳（`../shell/call-shell.js` 的 `createDeckShell`）、执行上下文（`../shell/call-budget.js` 的 `withCallScope`）、落点判定（`../shell/edge-landing.js`）、跟踪器派生与正文解析（`../../tracker/deck-derive.js`、`../../tracker/body-parse.js`）、调用前算账（`../../shared/refresh/tool-cost.js` 的 `estimateToolCost`/`toolCostInputFrom`）。其中三个工具（`map-plan-create.ts:22`、`context.ts:11`、`issue-create.ts:17`）还直接引入 `../../shared/refresh/budget.js`；`map-plan-create.ts:19` 引入幂等（`../../shared/refresh/idempotency.js` 的 `matchAnchor`）；`context.ts:13` 引入写权限表（`../../shared/tracker/backendWritePermissions.js`）。注册装配侧 `src/deck/registration/host-assemble.ts:27` 引入判定服务（`../../tracker/detection/backendDecision.js` 的 `decideBackend`）。
- 壳刻意不留运行时边（来源：`src/deck/shell/call-shell.ts:9-12`）：「本文件不引入任何运行时的东西：闸、后端注册表、额度常量、算账函数都由接线方（或测试）从构造函数传进来」「唯一的引入是 `./call-shell-types.js`，而且是 `import type`：只借形状，运行时不留一条边」。所以用「有没有静态引入」判断闸与账本是否被调到，会得出「没调到」的错误结论。
- 运行时真正的链（来源：`src/host/refresh/wiring.js:16-17,25,47-48` 与 `src/host/index.js:239-240`）：接线处同时造出账本与闸（`createLedger` 加 `createGate`）、装好 deck 工具表（`createDeckToolsForHost`）、取好额度与算账（`budget`、`tool-cost`），再把闸与注册表注入壳；宿主代执行电话 `wf.deckExec` 经动态引入调到 `host-delegate.ts` 的 `handleDeckExec`（见 `src/deck/registration/host-delegate.ts:56-80`）。每一次后端调用都过宿主闸：先判硬顶、再记真实花费（来源：`src/deck/shell/call-shell.ts:17-19` 的四条硬要求第 1 条）。
- 进程这一路的链：deck 工具经闸放行后，经注册表选后端（`registry.select`，形状见 `src/deck/shell/call-shell-types.ts:133-139`），进房间操作；房间起 `gh` 命令前按档位定超时（读 12 秒、写 30 秒、探活 3 秒的纯判定住在 `src/tracker/kernel/outbound-tiers.ts`，见 `src/tracker/kernel/README.md:14-15`），真正起进程的是 `git-process.ts` 的 `runGh`/`execProc`；每一笔真实出站都在起进程之前报给闸（来源：`src/host/git-process.ts:6-10`，「每一笔真实出站都在起进程之前报给闸一次，这是 I1 唯一出口的物理落点」）。找 `gh` 可执行文件的兜底由平台通用层单点拥有（来源：`src/host/platform/index.js:17-20`），三底座只做各自系统的适配（来源：`src/host/platform/win32/index.ts:1-8`）。
- 超时 30000 毫秒的落点：宿主入口的 `TIMEOUT_MS = 30000`（来源：`src/host/index.js:33`），与批量上下文的单次远端调用默认钳制 30000 毫秒（来源：`src/deck/shell/call-budget.ts:29-30`「与 GitHub 房单条命令默认同值」）。#1068 票面说的「超时 30000 毫秒」对应的是这两处，不是某一行的魔法数字。
- 快照这一路的链（重要澄清）：deck 的 `map-snapshot` 工具**没有静态引入**宿主快照四件（来源：`grep src/deck/tools/map-snapshot.ts` 的引入清单，无 `snapshotBuild`/`snapshotEnvelope`/`sessionSnapshot`/`write-queue`/`scratch`）。宿主快照四件服务的是面板 `wf.snapshot`/`wf.refresh` 电话路（来源：`src/host/index.js:102` 快照组装、`src/host/index.js:212,216` 会话快照与刷新两路共用信封与在途表）。deck 读地图快照走的是注册表加后端房间的读操作（经 `deck-derive` 与 `body-parse` 拼装），写 `.scratch` 走的是 Markdown 房间操作内部的写入队列（`write-queue.ts` 的 `withSingleWriter`）。也就是说 #1070 的宿主快照四件与 deck 之间是「同名不同路」：名字都叫快照，但 deck 的读路不经过宿主快照组装；只有 Markdown 房写入队列与 `.scratch` 路径规则是 deck 写操作的必经行。宿主快照四件是否要转，取决于「面板快照路」是否在地图 #1066 范围内，票面 #1070 说在，但调用链上它不是 deck 工具的下游——这是一个必须在 grilling 里裁定的分歧点（见第六节未定项）。

## 二、「被 deck 调到」有哪些不同形态，哪些该算、哪些不该算

### 2.1 七种形态与判据建议

- 形态一，静态直接引入且运行时执行（例如九个工具对 `tool-cost.js` 的 `estimateToolCost`、`budget.js` 的额度常量、`idempotency.js` 的 `matchAnchor` 的调用）：**算**。判据：依赖图上有边，且该导出函数在 deck 调用路径上真实执行。来源：`src/deck/tools/map-plan-create.ts:17-23`、`src/deck/tools/context.ts:10-13` 等 28 条引入。
- 形态二，经由构造函数注入的间接调用（闸的 `admitAiTool`/`send`、注册表的 `select`/`get`、后端房间操作的读写）：**算，但只算形状与调用点，不算整个实现文件**。判据：接口形状（`GateLike` 在 `src/deck/shell/call-shell-types.ts:126-131`，`RegistryLike` 在 `:133-139`，必填三件在 `:157-159`）与 deck 侧每一次调用点算；闸与账本实现文件里（`gate.ts` 478 行、`ledger.ts` 417 行）只有 deck 路径真实走到的分支（AI 工具档的硬顶判定、记账、推迟队列）算，生命周期与后台档的分支、面板读数路不算。理由：这些文件另有主人（刷新机制），整文件扫荡违反 #1066 边界。来源：`src/deck/shell/call-shell.ts:9-12` 的注入设计、`src/host/refresh/wiring.js:16-17` 的装配。
- 形态三，类型引用（`import type`、接口形状、契约层纯类型与数据）：**不算迁移行**。判据：构建时擦除、不留运行时边。证据：`src/deck/shell/call-shell.ts:12` 明确只有 `import type`；契约层的定义是「只有类型与数据、没有运行时实现」（来源：`docs/adr/20261014-tracker-room-boundary.md:33`、`src/tracker/kernel/README.md:22-24`）。类型变化的跟随修改记为跟随项，不计入「被调到」。
- 形态四，注释提及（含文件头的旧路径注释）：**不算**。判据：注释不执行。证据：影响面清单里单列「三丙、只有注释提到旧路径（4 个文件 4 处，不改也能跑）」（来源：`research/1010-deck-blast-radius.md:84-91`）；`src/deck/registration/host-delegate.ts:2` 的旧路径注释、`src/host/git-process.ts:1` 的旧名注释都是此类。
- 形态五，测试引用（`tests/verify-*.js` 动态引入被测模块、读文件文本断言、散列与路径表）：**不算被调到，但搬家时必须同步改**。判据：测试到源码的边是验证边，不是产品运行时边。证据：清单分出「动态引用类 30 个文件」与「文本断言类 13 条」（来源：`research/1010-deck-blast-radius.md:6-59`）。测试改的是路径字符串与夹具（例如补 `decideBackend`，见 `research/1010-ticket-scope-1.md:108`），不扩大迁移范围。
- 形态六，构建脚本与发布包引用（`scripts/build.mjs` 复制逻辑、`package.json` 手写导出映射、门禁基线 `file-granularity-baseline.json`/`same-layer-baseline.json`）：**不算**。判据：它们是派生与门禁，不是运行时调用。证据：清单第四节到第六节（来源：`research/1010-deck-blast-radius.md:101-117`），其中 `package/package.json:21` 的手写映射是必改项但不是「被调到」。
- 形态七，经由契约层、注册表、宿主电话的运行时到达（无静态边，有运行时调用；例如 deck 写操作经房间操作内部走到 `write-queue.ts` 的队列、经 `path.ts` 的 `.scratch` 路径规则；deck 出站经 `git-process.ts` 的 `noteOutbound` 报账）：**算，且这是最容易漏的核心形态**。判据：从 deck 工具入口沿注入链做运行时追踪（以闸的 `send`/`admitAiTool` 与注册表 `select` 为锚点），凡 deck 触发的执行必经行都算，不管有没有静态引入。只看 `grep import` 会漏掉全部这类行。

### 2.2 一条反直觉但必须守住的红线

- deck 直接静态深引房间实现、共享内核、探测内部是**禁止的**，不是范围。判据是门禁 `deck-deep-import`（来源：`.dependency-cruiser.cjs:183-193`：「deck 层只许连契约层的公开入口，不许直接连房间实现、共享内核或探测内部」；`from` 覆盖 `src/deck/`、`src/host/tools/`、`src/shared/deck-tools/`，`to` 覆盖 `src/tracker/rooms/`、`src/tracker/kernel/`、`src/host/tracker/detection/`）。同款表述在 `src/tracker/kernel/README.md:34-35` 与 `docs/adr/20261014-tracker-room-boundary.md:75`。所以如果在 deck 树里发现一条直连房间实现的静态引入，正确处理是按违规修掉（走契约公开面），而不是把它计入「被调到于是要转」。

## 三、现有判据口径里可复用的部分

- `CONTEXT.md` 的零变化与判据一源（来源：`CONTEXT.md:158-162`）：零变化指同一输入下对外可观察的预期结果逐例一致，补缺口到功能本意不算改行为；判据一源指同一个判断只有一处有序规则表是真源，各家只写前置扩展。复用：转制判「调到与否」也只要一份真源（建议就是本 #1067 的结论加行级清单），各开发票只写自己那片的前置说明，不许各写一份判据；转码过程守零变化，行为差异逐例比对，不用「基本一致」糊弄。
- `docs/adr/20261014-tracker-room-boundary.md`（房间边界）：复用四个名字（契约、共享内核、房间、装配点，见该 ADR `:23-31`）、deck 只许连契约层（见 `:75` 与关联的 #1014 Q2）、房间实现只许被装配点引用（见 `:62-63`，落点 `src/tracker/registry/builtins.ts`，门禁 `rooms-imported-only-by-assembly` 在 `.dependency-cruiser.cjs:202-212`）、登记表六条自证判据（活着、有名有据、不吃自己、不被吸收、图上活着、报分母，见 `:51-58`）。本研究的形态分类直接套用它的「起点判据不写房名、按依赖图判」的思路。
- `docs/adr/20261014-error-classification-single-source.md`（错误档位一源）：复用「判据只有一个真源」（见该 ADR `:31`）、「判据的输入是事实对象不是字符串」（见 `:32`，类比：判调到与否的输入是依赖图边加运行时追踪事实，不是文件名含不含 `deck` 字样）、「原文必填」（见 `:34-35`，类比：每条「算/不算」的结论必须附证据行号，人能自己复核）、「客户端不再猜档位」（见 `:37`，类比：开发票不再各猜范围，以 #1067 结论为准，与 #1068 正文「与讨论结论冲突时以讨论结论为准」同向）。
- `research/1010-deck-blast-radius.md`（影响面清单）：复用它的分类骨架——动态引用、文本断言、源码内部引用者（不搬家但引用会断的 7 文件 21 条、随目录搬的 2 文件 2 条、纯注释 4 处）、构建脚本、发布包镜像加手写映射、门禁基线、文档标题（见该文件第一到第七节与总数 47 个手改文件）。本研究的形态一到形态六是对这份骨架的直接沿用，只是把问题从「搬家要同步改什么」换成「什么算被调到」。

## 四、两边风险

### 4.1 整文件扫荡的风险（多转）

- 违反地图边界：#1066 边界明写「只转被调到的行，不整文件扫荡——这些文件另有主人」。闸与账本另有刷新机制的主人，快照另有面板与刷新链的主人，平台三底座另有平台抽象层的主人。
- 与并行写者撞车：`workspaceCwd.js` 已有 #1003 与本轮的写者冲突（见 `research/1010-ticket-scope-2.md:70`）；#1012 并行改造与本轮抢 7 个文件（见 `research/1010-ticket-scope-5.md:90-94`）；房间正在 #1064 手里迁移、共享内核归口在 #1159（见 `docs/adr/20261014-tracker-room-boundary.md:79`「同一批文件不能有两个写者」）。
- 破坏房间纪律：把房间搬进 deck 视角或让 deck 直引房间，会与「共用归共用人家」（`research/1010-deck-blast-radius.md:97-99` 列出四个与 deck 无关却在用房间的调用方：宿主装配、面板详情、远程谓词、检查链超时常量）冲突，并触发 `deck-deep-import` 与 `rooms-imported-only-by-assembly` 两条门禁。
- 行为漂移：闸的不变量（I1 唯一出口、I2 后台零定时器、I3 首屏只付行数据钱、I4 用量与工作区数无关、I5 失败必可见必退避、I6 花费可归因可对账，见 `CONTEXT.md:133`）与额度数字（唯一真源 `src/shared/refresh/src/budget.ts`）经不起顺手改造；票面核实再三强调「原样搬、行为零变化」（见 `research/1010-ticket-scope-3.md:106`）。
- 日志附录撞车：`research/489-appendix.md` 是 deck 段、闸段、#1007 子命令字段三方共改的表（见 `research/1010-ticket-scope-3.md:35,110`），整文件扫荡容易把别人的段覆盖掉。

### 4.2 漏行的风险（少转）

- 运行时链断在新旧语言交界：漏掉注入链上的任一行（闸的 `send` 分支、注册表 `select`、房间操作的 deck 可达分支、`git-process.ts` 的 `noteOutbound`、平台 `resolveExecutable`），等于留一条 `.js` 在必经路上，行为零变化无从谈起。
- 账对不上：漏记账行会导致闸的漏网计数（`escaped()`，见 `src/host/refresh/gate.ts:16-17`）非零，即有人绕开闸发请求，门禁判红。
- 批量活丢进度：`call-budget.ts` 的剩余额度自停、单调用钳制、超时回执诚实（见该文件 `:1-8`）与游标落盘（`plan-cursor.ts`，经 `wiring.js:28` 接线）漏一行，#895 那族问题（超时但副作用已落盘）就会回来。
- 本地写丢改动：Markdown 房写入队列（`write-queue.ts` 的按文件分队）与 `.scratch` 路径规则（`path.ts`、`issues-locate.ts`）漏一行，并发写会互相覆盖（两路都回成功、盘上少一半，见 `write-queue.ts:4-7`）。
- 证据链断：漏掉 `raw` 原文必填（见 error ADR `:34`）或脱敏（凭据原文永不落盘，见 `CONTEXT.md:93` 与 error ADR `:52`），分类猜错时人拿不到原文自判。

## 五、最小够用的行级判据草案（给后续 grilling 讨论用，不做决定）

草案共五条正判据加三条排除项，逐行执行：

1. 从九个 deck 工具入口出发，沿静态引入边收第一圈（形态一）：凡被工具直接引入且在 deck 调用路径上执行的导出函数与常量，逐导出记入清单（例如 `estimateToolCost`、`toolCostInputFrom`、`budget` 的被用常量、`matchAnchor`、`parseMapBody`、`deriveDeck`、`decideBackend` 经装配的调用）。
2. 沿构造函数注入链收第二圈（形态二加形态七）：以闸（`admitAiTool`/`send`）、注册表（`select`/`get`）、房间操作读写为锚点做运行时追踪，凡 deck 触发必经的行（闸 AI 工具档分支、记账行、推迟队列行；房间操作中 deck 可达分支；`git-process.ts` 的报账行；平台 `resolveExecutable` 行；Markdown 房写队列与路径行）逐行记入，不管有无静态边。
3. 实现文件只收被走到的分支：闸、账本、进程、快照的实现文件里，没有被 deck 路径走到的分支一律不收（面板路、后台路、生命周期路、其他后端路都不收）。
4. 真源优先：额度与算账只认 `src/shared/refresh/src/budget.ts` 与 `src/shared/refresh/src/tool-cost.ts`，生成的 `.js` 副本不计行；类型只认形状文件（`call-shell-types.ts`），运行时不计。
5. 每行附证据：清单里每一行写清「哪条链走到它」（工具名、经哪次注入、触发条件），无链的行不收；行号漂移时以今天源码实际行号为准（票面行号漂移的教训见 `research/1010-ticket-scope-3.md:8`）。

排除项：

- 甲，纯类型引用、注释提及、测试引用、构建与发布脚本引用、门禁基线与文档标题一律不计入（形态三到形态六），测试与构建的同步修改另列跟随清单。
- 乙，deck 直连房间实现、共享内核、探测内部的静态边如果被发现，按门禁违规修掉，不计入范围（2.2 节红线）。
- 丙，文件头仍写旧名的注释（如 `gate.ts:1` 写 `gate.js`、`git-process.ts:1` 写 `repoKeys.js`）不作为路径证据，以磁盘真实路径为准。

验收（建议 grilling 时一并定）：清单跑三遍——依赖图边全覆盖（`deck-deep-import` 等门禁绿）、运行时追踪全覆盖（deck 九工具各至少一条含闸与记账的调用走通）、逐行证据可复核（第三人按清单能重走到同一行）。
