### 2. 票面复现数字的差异

票面写「换成 `### 这段是三级标题` 时读回 `["先给结论。", "先给结论。", "后面还有内容。"]`」。干净票上直接写 H3 只有 2 条；票面的 3 条来自「同一张票先写过 H2 评论」这个前置：第一条 H2 评论被写坏后，第二条 H3 评论被 `appendSectionBlock` 插进了第一条评论正文中间，于是读回多出一条真实评论。票面的「最小复现」没有写清这个前置，属于复现描述歧义，不是核心事实错误。

### 3. 根因逐环

1. 写侧 `src/tracker/rooms/markdown/comments.ts:51-55` 的 `commentBlockOf` 只做 `'### ' + actor + ' — ' + iso + '\n' + String(body || '').trim() + '\n'`，正文原样拼接，不转义。
2. `comments.ts:64-70` 的 `addComment` 在非 legacy 路径用 `appendSectionBlock(txt, 'Comments', block)` 把整块插进文件；legacy 路径（`comments.ts:93-109`）用 `/^\s*##\s*Comments\s*$/im` 找段、`nextH2 = /^\s*##\s+/m` 找插入点，同样按行首判断。
3. 读侧 `src/tracker/rooms/markdown/parse.ts:301-340`：`cmAnchor = /^\s*##\s*Comments\s*$/im` 找评论区，`nextH2 = /^\s*##\s+/m` 当评论区结束，`segment.split(/^###\s+/m)` 当新评论开头；`parse.ts:330` 又把 `bodyPart.split(/^---\s*$/m)[0]` 当正文结束。三处都只看行首，和评论头 `### <actor> — <ISO>` 没有区别判据。
4. `src/tracker/rooms/markdown/original-fields.ts:288-314` 的 `appendSectionBlock` 用 `anySectionIndex`（`H2_RE=/^##[ \t]+\S/`）找段结束。上一条评论正文里只要有裸 `## `，新评论就会被插到它前面，也就是上一条评论正文中间——这是写侧的结构错乱，不只是读回截断。
5. `appendClosingComment`（`issues-status.ts:251-257`）把关闭原因也用同一个 `commentBlockOf` 追加；它靠「读回最后一条评论正文 === reason」判重，读回被截断后判重失效，重复关闭会重复追加原因，文件尾部出现两份 `## 结论`。
6. `getIssue` 的 `body` 是整份文件原文（`parse.ts:407-422`），不是「票面正文段」；所以票面期望的「票面正文不被污染」按字面不成立，合理的验收口径应是「`## Comments` 之前的正文段不变」。

### 4. 影响与现状

- 影响范围：任何含 Markdown 二/三级标题行的评论都会中招；围栏代码块内的标题同样会，因为读侧不认围栏。贴 TODO 清单、贴文档片段、贴代码说明都容易带上。
- 高频路径：本仓的 triage/完成评论常用 `## 定案` 这类小节标题；关闭原因（`closeIssue({reason})`）也走同一个函数。实测关闭原因含 `## 结论` 时：读回只剩 `做完了。`；随后追加普通评论会被插进上一条评论正文中间；再以同一原因关闭一次，读回 3 条、文件尾部出现两份 `## 结论`。
- 数据现状：字节仍在磁盘文件里，通过 comments 接口读不到，属静默损坏；写侧后续操作还会继续把文件结构搅乱。

### 6. 票面「修复方向」的边界（对抗式审查）

票面的「写侧转义 + 读侧还原」方向可行，但按票面文字实现并不完整，实测有这些漏洞：

- 正文原本以两个反斜杠开头（例如 `\\## x`）时，写侧不处理、读侧按「双反斜杠去一个」还原，读回会丢一个反斜杠；`\\### y` 同理。
- 写侧只匹配行首 `## ` / `### `，覆盖不到 `##\t`、`  ## `、`    ## ` 这些读侧仍会认的变体。
- 正确的做法是读写共用同一个「什么算标题行」判据（含前导空白与 tab），并按行首连续反斜杠个数 k 处理：写侧 k+1，读侧 k-1；不能只判断「双反斜杠」和「单反斜杠」两档。
- `---` 是同一类边界碰撞，但它是旧格式的评论分隔符（`tests/fixtures/markdown-sample/01-hello-world.md` 第 14 行），新写侧今天不再产生它；怎么兼容旧文件要单独定，不能顺手删掉读侧对 `---` 的处理。
