## 一句话结论

根因在插件的 gh 可执行文件解析链：当前只有「DSH 子进程服务按宿主进程 PATH 解析 → 读同一份进程环境里的 `DSH_GH_PATH` → 失败」两层，没有任何一处去探测各系统已知安装目录；失败文案又把「已装但进程看不见」统一说成「去安装」。所以报告人（gh 2.103.3 已装已登录，安装目录不在 PATH）被要求重装，正确出路其实是「把安装目录加进 PATH，或设 `DSH_GH_PATH`，然后重启 DSH」。当前 main 上没有实施痕迹；报告人重启后已经恢复，证明这是宿主进程环境快照加解析层缺口，不是 gh 未安装或未登录。

## 本次复核：解析行为（单元探针）

探针在仓外临时目录建了两个目录：一个模拟「默认安装目录」（里面有假的 `gh.exe`），一个模拟「PATH 里只有一个不含 gh 的目录」。用当前 main 的 `composePlatform` + win32 适配器，`subprocess.resolveExecutable` 用「只在 PATH 目录里找 gh.exe / gh.cmd / gh.bat / gh」模拟生产环境行为（生产 win32 适配器只是把这一步转交给 DSH 子进程服务，没有额外逻辑）。

| 场景 | 结果 |
| --- | --- |
| PATH 不含 gh 目录，默认安装目录里有 gh.exe，未设 `DSH_GH_PATH` | 返回 null |
| 同上，设置 `DSH_GH_PATH` 指向那个 gh.exe | 返回该绝对路径 |
| 进程启动后修改 PATH（模拟「装完再改用户 PATH、不重启」） | 仍返回 null（环境快照不更新） |

结论：解析链只有 `DSH_GH_PATH` 一条兜底；哪怕文件真实存在于常见安装目录，只要 PATH 与 `DSH_GH_PATH` 都没命中，就判失败。探针没有跑在报告人的机器上，但复现的是代码行为，与报告人的日志、重启前后的对照一致。

## 为什么错误文案会把人引向「重装」

- `preflight.ts:157` 与 `client.ts:237` 的失败文案都以 `install https://cli.github.com/` 结尾；`errors.ts:96` 又把 `gh not found` 归到 ENV 档，界面只会说「本机缺 gh」。
- 现有引导里唯一提到「已装但仍报」的一句在 `src/host/publishFlow.ts:170`：第 4 步写「若 gh 已装但 DSH 仍报未安装：点环境检查『重测』按钮或重启 DSH Desktop」。按本票证据，「重测」在同一个进程里重跑，进程环境没变，结果不会变；只有重启才有效。这句话把两条出路并列，等于给了半条错路。
- 报告人第 2 条评论（旧进程实测仍报错）与第 3 条评论（重启后恢复）正好把这个差别验出来：不是「重测」能解决，而是「改环境 + 重启」才解决。
- 正确文案至少要说清三件事：当前 DSH 进程看不到这个目录；把安装目录加进 PATH 或设 `DSH_GH_PATH`；然后重启 DSH。三件事都做不到时才说「安装」。

## 对抗式复核

- 会不会是 gh 真没装、或没登录？报告人的绝对路径 `--version` 与 `auth status` 都成功，重启后同一台机器、同一个 gh 被识别；排除。
- 会不会只是用户没重启，不算缺陷？重启是在用户手工改 PATH、设 `DSH_GH_PATH` 之后才恢复；默认目录不在 PATH 的机器仍会卡住，而错误文案教人重装。首接入不该要求用户先理解进程环境快照和命令行环境变量。已知目录探测能救「默认安装」这一大类，文案能救「自定义安装」。
- 会不会应等 DSH 上游改进环境快照？上游排期不可控，而且插件侧本来就有可做且成本可控的缓解；#702 已把四条插件侧路线列出，本次只需选其中一条组合。
- 会不会 (b) 有安全风险？只在 PATH 解析失败后，按固定的候选目录列表 lstat 固定文件名，命中才拿绝对路径；与现有 `DSH_GH_PATH` 兜底的 lstat 校验同性质，不会执行任意路径。

## 建议的验收（供拍板后写 agent brief）

- 解析层：在解析单点（按仓内「单点拥有」的口径，优先 `composePlatform`）里，PATH 解析失败后按操作系统候选目录依次探测 gh 可执行文件，命中返回绝对路径；三个系统各有可测的候选清单；都找不到仍返回 null，不能把异常吞成「已安装」。
- 文案层：预检与客户端两侧的 ENV 错误区分「未安装」与「已装但当前 DSH 进程看不见」；后者给出重启 DSH、设置 `DSH_GH_PATH`、把安装目录加进 PATH 三条具体出路；不再只给安装 URL。按 #664 的口径，缺 gh 的指引文本只保留一份来源，不要在多处各写一句。
- 门禁：夹具覆盖四种情况——PATH 无 gh、已知目录有文件 → 命中；PATH 无 gh、`DSH_GH_PATH` 有值 → 命中；PATH 无、已知目录无、`DSH_GH_PATH` 无 → null；错误文案区分两种缺失。
- 真机验证：由报告人或维护者在 Windows 上按原步骤复核（默认目录不在 PATH、`DSH_GH_PATH` 未设时启动 DSH → 面板与工具能识别）；真机验证是加分项，不作为合并门槛（当前开发环境不是那台机器）。
