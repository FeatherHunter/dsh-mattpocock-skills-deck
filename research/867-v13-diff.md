# 上游 V1.3 差异盘点（票 867）

研究问题：上游 mattpocock/skills 从 v1.2.3 到 v1.3 到底变了什么？要逐个列出三类：新增的技能、已有技能的变更与优化、老的但我们还没有集成的技能，给后续定版用。

决策依赖：这份盘点的输出将被票 868（同步范围与覆盖策略定版）直接拿去定结论：每个技能是原样覆盖、合入、新增接入还是忽略。再被票 869（同步脚本与真源升级到 v1.3）拿去执行。

调研日期：2026-10-06。

来源策略：一手来源优先。结论只认上游仓库 mattpocock/skills 的 GitHub Releases、Tags、Compare、目录清单与 SKILL.md 原文。不用二手博客转述。每个结论后面都给出能打开的来源链接。本文件里的接口链接都在 2026-10-06 当天实际打开验证过，能正常返回内容。后台调研子代理另用 git clone 交叉确认了目录清单与按技能 diff 行数，与接口结论一致。

版本说明：上游没有名字正好叫 v1.3 的 tag，只有 v1.3.0 与 v1.3.1（同一天发布，前后差约 1 分钟）。本文件把“v1.3”理解为 v1.2.3 到 v1.3.0 的全部变化，并单独说明 v1.3.0 到 v1.3.1 又补了什么。建议后续定版直接钉死 v1.3.1，因为它是 v1.3 系列最新的补丁版。抓 https://github.com/mattpocock/skills/releases/tag/v1.3 会返回 404，来源是子代理实测。

本地基线：本地真源是 src/shared/matt-skills.js 里的 25 项（MATT_SKILL_PROBE_NAMES 与 SKILLS 两处导出一致），捆绑产物是 package/bundled-skills（含 VERSION 文件，内容为 v1.2.3），同步脚本是 scripts/sync-matt-skills.mjs（默认 --pin v1.2.3，只拷 engineering 与 productivity 两个目录）。这 25 项与上游 v1.2.3 的发货组合完全一致：engineering 18 个加 productivity 7 个等于 25 个，名字逐个对上。

## A 新增的技能（3 个，结论都是新增接入）

三个都是在 v1.2.3 的 engineering 里没有、在 v1.3.0 的 engineering 里出现。发布说明里用“毕业进 Engineering 桶”来描述，来源是 v1.3.0 发布说明里 [#1120](https://github.com/mattpocock/skills/pull/1120) 的三条小版本变化，提交是 https://github.com/mattpocock/skills/commit/2aecca12ea9ff047f76c8178cb64dfeafd192abe 。它们之前不在 in-progress 里（in-progress 两版都是同一 6 个），所以是对我们而言全新出现的目录。子代理用 raw 404 反查确认 v1.2.3 下这三个路径不存在。

### A1 implement-spec：整份规格一次跑完

一句话：把 to-spec 与 to-tickets 产出的整份规格（含任务图与阻塞关系）在一条集成分支上一次跑完，做法是派多个子代理在各自工作区并行做就绪任务，最后统一做 code-review。

原文在 https://raw.githubusercontent.com/mattpocock/skills/v1.3.0/skills/engineering/implement-spec/SKILL.md ，开头写明名字是 implement-spec，功能描述是实现 to-spec 与 to-tickets 的结果，且标了用户主动调用（disable-model-invocation 是 true）。发布说明里写明它由 ask-matt 推荐，作为按票逐个跑的 implement 的并行替代入口。毕业前还补了三点：目标是集成分支而不是 PR；没给 issue 跟踪器时提示人去跑 setup-matt-pocock-skills，而不是默默默认用 gh；每个子代理开工前确认工作区基于集成分支、用 tdd 做票、报完工前先合入集成分支最新进度，保证每次合入都是快进。

给票 868 的建议结论：新增接入。理由是地图 866 的终点已写明新增 implement-spec 与老技能同一机制随包可用。

### A2 pr：写 PR 正文的固定形状

一句话：规定 PR 正文只写三段：最小可视化摘要（伪代码、调用树、文件树、Mermaid 图、diff 草图里选最贴切的一种或几种）、改前改后的证据、合入危险判断（单向门还是双向门加影响面）。

原文在 https://raw.githubusercontent.com/mattpocock/skills/v1.3.0/skills/engineering/pr/SKILL.md ，功能描述是写 PR 正文时用，没有标用户主动调用，即模型被动调用。发布说明里写明它由 ask-matt 推荐，作为 PR 正文收尾入口。摘要可视化做法致谢 Dex Horthy 的 show-me，技能内有 CREDITS.md 保留致谢。

给票 868 的建议结论：新增接入。理由同上，地图终点已点名 pr。

### A3 retro：编码会话复盘，只改环境不改代码

一句话：回看一次编码会话，只提对代理环境的改进（导航指针、自动检查、编码规范、 steering 文件、工具开销、信息获取），不直接改业务代码；机械性违规必须先做成确定性检查，编码规范只留真正的判断题；没有防护栏的仓库本身就是一条改进意见。

原文在 https://raw.githubusercontent.com/mattpocock/skills/v1.3.0/skills/engineering/retro/SKILL.md ，功能描述是做一次编码会话复盘，且标了用户主动调用。发布说明里写明它由 ask-matt 推荐，放在主流程 code-review 之后最后一步。

给票 868 的建议结论：新增接入。理由同上，地图终点已点名 retro。

### 反向新增（实为删除）：resolving-merge-conflicts 被整个删掉

一句话：上游删掉了合并冲突技能，没有替代品，以后合并或变基冲突由代理自行处理。

来源是 v1.3.0 发布说明里 [#1120](https://github.com/mattpocock/skills/pull/1120) 的删除条目，提交是 https://github.com/mattpocock/skills/commit/daa01d8aa68ad5c61b68970ec2018d0ce9567be6 。原文说它退出 Claude Code 插件、README 与 ask-matt 路由，文档页 https://aihero.dev/skills-resolving-merge-conflicts 保留并标存档。子代理确认 v1.3.0 的 engineering 里已无此目录，且 deprecated 下只有 README，没有搬迁。本地 v1.2.3 原文在 https://raw.githubusercontent.com/mattpocock/skills/v1.2.3/skills/engineering/resolving-merge-conflicts/SKILL.md ，功能描述是处理进行中的合并或变基冲突。

给票 868 的建议结论：忽略（跟随上游删除）。即真源与捆绑产物里都拿掉这一项，而不是保留旧版。

### B0 全局性变化（多技能同受影响）

- 领域文档改名：CONTEXT.md 与 CONTEXT-MAP.md 改名为 GLOSSARY.md 与 GLOSSARY-MAP.md，来源是 https://github.com/mattpocock/skills/commit/006a52be23e0178375e083e30535fa8224471f3e 。受影响的技能是 domain-modeling、grill-with-docs、improve-codebase-architecture、setup-matt-pocock-skills、triage、tdd、diagnosing-bugs、ask-matt、codebase-design、wait-what、pr，共 11 个，外加文档页与仓库根改名。老用户需手动改名，技能以后只找新名字。对我们的影响是凡是读或写 CONTEXT.md 的逻辑都要跟改，否则新版技能会找不到文件。
- 去破折号：全仓去掉长破折号，逐句改写为逗号、冒号、句号、括号或连词，而不是机械替换字符，来源是 https://github.com/mattpocock/skills/pull/905 。CLAUDE.md 与 AGENTS.md 还立规以后不再引入。这是纯文字清理，功能无变化，但会导致几乎每个 SKILL.md 都有 diff。
- 跨技能调用措辞统一：原来散写的“跑某某技能”统一改为明确的“调用 Skill 工具”指令，不再假设斜杠触发语法，来源是 https://github.com/mattpocock/skills/pull/878 。涉及 code-review、diagnosing-bugs、grill-with-docs、grill-me、improve-codebase-architecture、tdd、to-spec、to-tickets、triage、wayfinder 共 10 个，外加 .agents/invocation.md 新增约定。起因是只写名字并不能可靠触发加载，直接点名工具能提高命中率。
- 禁止调用用户触发技能：上面统一措辞时误把用户触发技能也写成可调用，修复为“告诉人去运行”，来源是 https://github.com/mattpocock/skills/pull/880 ，修复了 [#453](https://github.com/mattpocock/skills/issues/453) 。涉及 to-spec、wayfinder、to-tickets、triage、code-review 共 5 个的前置条件，以及 diagnosing-bugs 第 6 阶段移交给 improve-codebase-architecture 的直接删除（该移交极少触发，且无人值守流程里没有人能接住失败的调用，所以第 6 阶段只剩清理）。还在 .agents/invocation.md 补了一段适用范围说明。
- 引号修复：to-spec、code-review、setup-matt-pocock-skills、wait-what 等 6 个的 description 加 YAML 引号，来源是 https://github.com/mattpocock/skills/pull/911 。起因是上一次去破折号残留的未加引号冒号导致 skills.sh 跳过，发现不了这 6 个。不修复则装不上。
