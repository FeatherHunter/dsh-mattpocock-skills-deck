## 1. 结论摘要

### 1.1 总判定

**在「1.9.0-beta.34（提交 2068b76b）· web profile · gitlab.com 免费档 · FeatherHunter（免费档 owner，OAuth token）· 28 张票的 GitLab 项目与 10 张票加空项目的沙箱项目形状 · DSH 桌面运行时 0.2.1-rc.5 的 web GUI（外框 2195×1235、devicePixelRatio 1.75、面板可调 330.5–1600 像素）」这组作用域六要素下，GitLab 后端在 web profile 下的支持度判定为「无法判定」。**

1. **核心 20 条没有全部在最后候选上取得完整结论。** 20 条核心场景都在某个候选上跑过，但其中 7 条（J1-02、J2-02、J3-01、J4-01、J5-01、J5-02、J5-03）只在 beta.33 及更早的 B2 候选上通过，没有在最后候选 beta.34 上重跑；另有 J7-01 的「标记挪到第一个标题之后归属丢失」、J6-06 的「指派合法用户 B」、J11-03 的 3f「不支持/空态」三条子断言未测。规格明确写「核心 20 条无未测，或未测项已写明且总判定按规则降为『无法判定』」——所以不能写「有条件可用」。

- 降级说明同 6.4 第 4 条：没有走 implement-spec 的 implementer/merger 工作树；工作树只作为候选源码的干净检出使用。

### 8.2 证据强弱

- **强（截图 + DOM + 独立读回复核）**：写操作（建票/关闭/重开/评论/指派/关系）、读路径正文与评论数、环境检查三行、错误话术与出路。这类 PASS 至少有两层独立证据。
- **中（截图 + 页面文本，无独立读回）**：面板布局、三窗形态、页签可达、设置页控件显隐。
- **弱（仅日志或文本）**：部分环境限制与工具问题（如 J9-01 的窗口内 reload 失败、J6-02 的顶栏入口未定位）。
- 判定规则：任何 PASS 必须在 result.json 里写 claim + 证据路径 + 独立读回（能读回的）；没有独立读回的只算「通过（单层证据）」并在批 INDEX 标注。

### 8.3 间接观测与模拟

- **GitLab 网页评论区被 Cloudflare 403**：评论正文改由 glab API 独立读回；这是独立通道，不是产品回包，但仍缺「网页上肉眼可见」这一层。
- **未登录态**：用空 `GLAB_CONFIG_DIR` 模拟（真实 401），没有登出真实 keyring；宿主会剥凭据形状环境变量，注入无效 token 不可行。
- **403 探针**：用 `api_host=127.0.0.1:1` 强制 transport 失败以走 401 后的提及路径，不是真实网络 403。
- **DSH 显示快照**：`dsws(snapshot)` 与宿主工具调用走显示快照，不经过真实鼠标点击；凡是用它的结论都要求有截图/DOM 对照。
- **模型参与**：驱动脚本、证据采集、命令执行由模型完成；视觉判读与 P 级判定由 Lead 人工复核。模型没有用固定提示词模拟「人类用户完整路径」（附录 A 单列），所以本报告的结论只覆盖已知操作序列，不覆盖自由探索式的用户行为。

### 8.4 模型参与层的边界

- 模型能做的：按场景卡执行步骤、截屏、抓 DOM、调 glab 读回、把结果写进 result.json 与 INDEX。
- 模型不能做的：判断截图里「看起来对不对」的细微视觉差异（如 1-2 像素漂移、颜色近似）；这类由 Lead 用像素矩形/颜色值交叉验证，仍存疑的记「未测」或 P2 并说明。
- 因此本报告的「通过」都以可复核的数据（DOM 文本、矩形、独立 API 读回、哈希）为准，不只看截图。
