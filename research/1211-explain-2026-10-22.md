## 一、封装：这批收口动了哪几层，每层只管什么

1. 手写 JavaScript 棘轮只管对账，不管行为。两份名单各管一件事：tests/handwritten-js-baseline.json 管 git 跟踪集里 src、tests、scripts 下的手写 .js/.mjs/.cjs（排除 scripts/generated 与 package 两个派生目录），判据在 scripts/typecheck.mts:383 的 compareBaseline，只许减少不许增加，名单里留着树上找不到的路径就判红（tests/verify-typecheck.mts:1-22）；tests/unmigrated-tests-baseline.json 管 tests 下旁边没有同名 .ts 的旧语言测试文件，判据在 tests/verify-unmigrated-tests.ts:18-27，双向核对（树上是基线的子集且基线每条仍在树上）。今天两份名单内容相同，都是 3 条门禁夹具（:7-9：tests/fixtures/gh-gateway/compliant/src/host/goodGated.js 等 3 条），src 下手写 JavaScript 为 0，git 跟踪集里手写范围共 3 个文件。
2. 门禁归属表只管算出哪扇门禁守着哪个目录，不管门禁本身对不对。生成器是 scripts/gate-map.mts:787-788 的 buildGateMap，落盘 tests/gate-map.json（今天 chainLength 314，attributedGates 277，graphFileCount 523，generatedAt 当天），比较时删掉 generatedAt 再逐字节比（:1025-1028 的 normalizeForCompare），新鲜度门禁 tests/verify-gate-map.ts:54-70 重新推导一遍对上才绿。今天那两条转成 .ts 的验证脚本在表里已经是 .ts（:2260-2261 与 :6515-6516 附近），链上 314 步里没有一步还指向旧 .js。
3. 类型检查只管每份源码都有人看，不管写法好不好。今天是 16 份配置（复核时 15 份，之后新增 1 份），src 下 506 份源码全部被配置看到（verify-typecheck.mts 输出行），没有没人管的源码，没有重复归属。

## 二、参数：调用时传什么，不传什么会停在哪里

1. 棘轮的参数是两份名单文件本身。输入是今天 git 列出的手写文件清单，输出是只减不增的结论；新增确有必要的 .js（例如门禁夹具）必须重录基线并在提交信息写清理由，否则判红。
2. 归属表的参数是今天 verify 链的规划结果。输入是 scripts/lib/discover-gates.ts 的 planGates 按目录约定扫出的 314 步，输出是每步守着的源码路径与目录；横切文件（package.json、构建入口、验证链自身、文档）改了就跑全链，这是设计不是退化。
3. 全链的参数是同一份规划名单。入口 npm run verify:parallel（8 路并发，墙钟约 65 秒），CI 走 scripts/verify-all.mts 再加两阶段矩阵。今天并行跑完 314/314 步，真红 1 步（tests/verify-detail-levels.ts，2 条断言：快照 ok 与存在含子票的 map），另有 2 步并发假红复跑已绿。冒烟 5 条（package.json 的 smoke 那串）全部绿。
