# deck 重构共识（2026-10-12 与维护者逐条对齐后落定，待维护者点头）

本文件是这次「把 deck 工具链改成 TypeScript」的共识记录，供开工与以后回看。决议细节见 `docs/adr/20261011-deck-ts-rewrite.md` 与地图 #1010 评论；本文件只写「我们怎么一起做这件事」。

## 一、目标（维护者 2026-10-11 亲口更正）

1. 全面采用 TypeScript 实现。
2. 源码架构清晰。
3. deck 工具加它底下的 GitHub 房与 Markdown 房，围绕 deck 工具全部能力的每一份代码，都在本次任务内。
4. 源码中有大量日志，判据是：**BUG 发生时，日志足以定位到位置与原因**。
5. 源码中有大量注释，判据是：**帮维护者看懂代码逻辑**（不是逐行翻译代码）。

## 二、维护者在这件事里的位置

- 维护者是**纯 TypeScript 新手**，每个改写单元的票面都要写明这一点，讲解必须从零讲起，用当次的代码当例子，不用抽象定义。
- 维护者会看开发过程、参与讨论；每个单元给三处请他表态：方法封装是否合理、参数形状是否合理、边界与失败路径是否讲清。
- 维护者的意见默认得到回应；若他暂时没回，按票面写的建议执行，并在票里记「默认执行」。

## 三、开发形态（维护者 2026-10-12 定）

- **一个改写单元 = 一张地图票**（挂在地图 #1010 下），下挂三类子票：`讨论`（开工前那页计划，重点是与维护者对齐想法）、`开发`、`讲解`；讲解中发现的问题另开 `修复` 子票，修完再补一张 `讲解`。
- 横切小事（某单元的尾巴、门禁夹具、构建配置）挂成对应单元下的独立子票，累了可以先做感兴趣的那一张，不被大单元卡住。
- **票号顺序按阅读顺序由外向内编**：注册与装配 → 工具入口 → 工具壳 → 日志 → 契约 → 注册表 → 识别判定 → GitHub 房 → Markdown 房 → 宿主接线 → 横切。**动手顺序按依赖顺序做**（契约 → 房间 → 壳 → 工具 → 装配），每票里另标动手顺序。理由：票号服务阅读，动手顺序服务不返工。
- **严格串行**：一个单元完成（开发绿、讲解过、维护者表态）再开下一个；支线可并行，但挂在主链单元的票下。
- 单元数量：14 个左右（房间文件多的拆成两票）；维护者明确「不嫌多，目标是吃透」。

## 四、技术口径

- 先让源码变成 TypeScript（本轮），未来再让整个项目成为纯粹 TS 项目（换加载形态等）。
- 产物**不进仓库**（主流 TS 项目做法）；留一条准备命令，让「拉下来 → 一条命令 → 能跑」成立。
- 新写的测试用成熟测试框架；老的百来个验证脚本**分批随对应单元迁移**，不做一次性重写。
- 手写代码全覆盖（含构建脚本、测试、接缝层）；四个已有计算核与派生文件不动。
- 客户端（面板）是消费者：只跟随路径改名做轻微适配，不改行为（特例除外）。
- 单包加 TypeScript 工程引用（依赖方向朝下，编译器保证），暂不拆包。

## 五、完成判据


- **开发票完成** = 该单元相关门禁全绿 + 行为对照有证据（同一输入下新旧产出一致，或写明为什么允许不同）。
- **讲解票完成** = 维护者能对着讲解把这段代码讲回来 + 他对三看的表态已回。
- 每个单元交付时加一次**日志演练**：只看日志能不能说出「坏在哪一步、为什么」，做不到就补日志点；另有一份《日志导读》教维护者怎么读、哪些行连起来代表一趟流程走通（含一个完整正确流程的样例）。

### 测试缝（2026-10-12 维护者拍板，三条半）

1. **主缝 = 工具表**：宿主装好后那张「名字 → 定义与执行」的表，是我们的最高测试缝。喂调用、看三态回执、看必备标签与进度区是否自动补、看边落在哪一列。现有门禁大多已在这一层，迁移后仍在这一层测。
2. **房间缝 = 两房产出对象**：直接调后端对象上的公开操作看行为，比工具层低一层，用来分清「问题在工具还是在后端」。
3. **契约缝 = 编译加探针**：类型层没有运行时行为，靠编译门禁（`tsc` 零错误、操作名齐、无运行时实现、名录与运行时同集）加实现性探针（按接口把两房形态实现一遍看能否编译；再故意写错一处看类型拦不拦）。
4. **新增一条构建产物冒烟**：构建之后拿真实产物跑一次最小流程（初始化看工作区与后端 → 读一张票 → 改一次字段）。今天没有这一层，它负责回答「构建出来的东西还能用吗」。

**不给每个函数单独配测试**（维护者 2026-10-12 认可）。尺子：一个函数被两个以上地方调用、输入输出是纯数据不碰外部世界、分支多到读了也可能想错——三条里中两条，值得单独测；否则交给外层。理由：BUG 多住在函数之间的接缝，而外层测试正好覆盖接缝；给薄封装与私有中间步骤配测试，会在搬家时不断碎掉、并锁死实现方式，白白增加工作量。旧的「读文件文本断言路径」那批门禁不在新架构保留，换成标准依赖检查工具。
