Node找JS、打包出什么、金标准保什么

先纠正一处复述，再答你的几个为什么，最后补两句你没问但该知道的。

纠你的复述对了一半

你说“金标准检测有没有真正引用新 TS、没有就引用旧 JS”，这句要拆成两层：

真正管“有没有走到 .ts”的，是钩子自己的那道自证：如果磁盘明明有 .ts 兄弟却解析到 .js，当场红，不假装绿。金标准启动第一行还会打印“多少模块、几个走 .ts”，含糊时宁可红。

金标准管的是另一层：九个工具的回执跟基准逐字节一样不一样。它不管你走的是 .ts 还是 .js，只管行为没变。所以钩子红是找文件错了，金标准红是行为变了，两把尺子分工不同。

记住一句：钩子保“找到对的文件”，金标准保“做对同样的事”。

问1为什么 Node 非要找 JS

从头说：Node 是 JS 运行器，里面是 V8，只能执行 JS。它看不懂 TS 里的类型写法。所以 TS 必须先变成 JS，V8 才能跑。这和安卓是一个道理，只是名字不同：

安卓：Java/Kotlin 源码 → 编译器 → dex → 打成 APK
我们：TS 源码 → 转译（esbuild）或类型剥离（Node 自带）→ JS → 装进 npm 包

源码里写 ./x.js 而磁盘只有 x.ts，Node 会直接报错，不会帮你找。这是死规矩，钩子就是来补这一步的：先看有没有同名 .ts，有就给你，没有就放行让 Node 原样走。

问2找 JS 就是在编译吗

不是。要分开三个动作：

  • 找文件（解析）：钩子只干这个，不管编译。它只换地址，不改内容。
  • 变 JS（转译）：构建里的 esbuild 干这个，把 .ts 变成 .js 写进 package/。测试时是 Node 自带的类型剥离，擦掉类型就跑，不写文件。
  • 挑错（检查）：tsc 干这个，只看不产出（noEmit）。真正的 JS 由 esbuild 出。

所以“Node 在找 JS”说的是运行加载那一刻，不是打包那一刻。打包是 node scripts/build.mjs 那 30 秒（含两遍 esbuild 各约 14.5 秒），有缓存命中就跳过。

问3最终打包出的是什么

你的类比只对一半：对的是“最后都是一堆能跑的东西”，错的是形状。

安卓打出的是一个 APK（单个安装体）。我们打出的是一个 npm 包目录，就是 package/：

package/package.json（名字、版本、main 指 lib/index.js、exports、files 清单）
package/lib/（宿主镜像）、package/deck/（工具镜像）、package/tracker/（追踪器镜像）
package/shared/（四个核镜像）、cordis.patch.yml（装机补丁）、bundled-skills（技能）

用户不用自己起 Node。用户走市场升级、软件内升级或自己敲安装命令，把这个包目录装进 DSH 的插件文件夹。DSH 宿主（自己就是跑在 Node 里的）加载 lib/index.js，工具行再把九个工具注册给 AI。你开发时敲的 npm test、node scripts/build.mjs 跑的是你电脑；用户电脑上跑的是装好的包里的 JS，被宿主调起来。

记住一句：npm 管“把文件放到位”，Node 管“把文件跑起来”。prepare 在我们这边跑，用户拿到的是建好的包。

补两句你没问但该知道的

一源出两物：根下的 client.js / host.js 是开发态（给本地调试），package/lib/ 里的是发布态（给用户）。构建只写这三处，不碰你本机已装的插件，不读你电脑的 DSH 环境。

为什么源码坚持写 ./x.js：因为产物本来就是逐文件加载的 .js，源码跟着写 .js，产物一个字不用改，风险留在测试侧用钩子扛，不进线上。
