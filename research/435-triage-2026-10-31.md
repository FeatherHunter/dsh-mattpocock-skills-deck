## GL_HOST 到底是什么（2026-10-31 补查）

- 它不是我们读的环境变量，也不是 glab 的变量：全仓只有 `src/tracker/rooms/gitlab/preflight.ts:5` 一句过时注释提到它，实现从没读过；`docs/archive/decisions/1179-gitlab-setup.html:307` 已写明不要照着它配。glab 官方变量是 `GITLAB_HOST`，另有配置键 `host` 与 `--hostname` 参数。
- 主机由 glab 选：所有读写走 `glab` 子进程，代码不传 `--hostname`、不注入主机变量（`src/tracker/rooms/gitlab/client.ts:99-138`）；`glab api --help` 明说「在 git 目录里用当前仓库已登录的主机」，`glab auth login --help` 的解析顺序是仓库主机 → `GITLAB_HOST` → 配置 `host` → `gitlab.com`。命令带工作区 `cwd`（`src/deck/tools/tracker-session.ts:413`），所以自托管实例的数据读写走同一条通道。
- 仓内口径：`docs/design/677-issue-pool-completeness-spec.md:238`「自建 GitLab / GHES：接口形状相同，沿用现有 gh/glab 通道，失败如实报」；`src/tracker/rooms/gitlab/SETUP-PROMPT.md:43-44` 要求自部署/极狐先问主机名。
- 结论：#435 剩的两条（自动识别只认文本 `gitlab`、链接硬编码 `gitlab.com`）才是「不支持自托管」的具体所指；读写通道本身支持，修那两条不需要 `GL_HOST`。
