## 三、实现时会撞上的三件事（给实施者的硬约束）

### 3.1 重挂会把同一组放回来

`SuggestStreamMount` 的初始 state 与挂载副作用都先读 `suggestGroupRecall(sid)`（`suggestStream.ts:530`、`:543`），而这份缓存是模块级 Map（`:49`、`:94-109`）。收起态与展开态是两棵不同的返回树，组件会卸载再挂载，所以：

- 只在收起分支不渲染它 → 气泡立刻消失，但重新展开时新挂载又把这组放回来，验收第 1 条后半句失败。
- 要同时调用 `suggestGroupForget(sid)`（`:115-119`，会顺手记内存关闭标记），并决定要不要写 #1853 的跨刷新关闭标记（`:154-161`，键是会话号 + 调用编号）。

### 3.2 三个自然落点都贴着 350 有效行红线

用 `scripts/lib/effective-lines.mts` 实测（2026-11-05）：

| 文件 | 有效行 |
| --- | --- |
| `src/client/statusbar/StatusBar.ts` | 349 |
| `src/client/statusbar/suggestStream.ts` | 348 |
| `src/client/statusbar/suggestBubble.ts` | 349 |

上限是 350（`tests/verify-file-granularity.ts:30`）。所以实现要么放进新叶子文件，要么等量删行；「顺手加一个 useEffect」会直接判红。

### 3.3 第三颗开关不是只加一行界面

本机设置文件的 `workspaces` 每条记录只认一张名字名单（`src/shared/config-store/src/settings.ts:62` 的 `WS_KEYS`），多一个名字整份写入会被核判成 `unknown-keys` 拒绝（`:118`、`:165-167`、`:254`）。所以第三颗开关要同步改：

- 核：`WS_KEYS`、默认值（`:178` 附近）、归一（`:185-198`）、写盘注释（`:300-301`）。
- 客户端：`settings-view.ts` 的 `VIEW_FLAG_TEXT_NAMES`（`:88-91`）、`VIEW_FLAG_SEED_NAMES`（`:110`）、`viewFlagSeedValueOf`（`:113-117`）；`deck-state.ts` 加读口与写口。

由此定下的行为（已写进 ready-for-agent 的实施说明）：

| 状态 | 气泡 | 这组建议 |
| --- | --- | --- |
| deck 开着、开关开 | 显示 | 照旧 |
| deck 开着、开关关 | 不显示 | 只隐藏；开关再打开时显示当前最新一组 |
| 只是胶囊收起（deck 工具箱仍开） | 不显示 | 只隐藏；收起期间工具仍可用，新到的组照常缓存，展开后显示最新一组 |
| deck 工具箱关掉 | 不显示 | 关闭那一刻屏上那组记为已跳过（内存 forget + 跨刷新标记），重新打开与刷新后都不补 |

一个窄边界的处理：关闭 deck 时如果正有一轮在跑、那一轮在闸门生效前已经调过建议工具，这组可能在关闭之后才到。按「关闭期间不出建议」的口径，这种组也按已跳过处理，不在重新打开时补出来。这一条不需要维护者再拍板，写进实施说明里当边界。

第七节的问题 4 推荐答案（「重开显示最新一组」）已被本节取代：它只适用于「只是胶囊收起」那一行，不适用于 deck 关掉。
