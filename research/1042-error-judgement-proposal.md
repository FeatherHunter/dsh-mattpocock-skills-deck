## 今天的事实（都带出处）

- 失败形状已经是两段：`TrackerError{kind, message}`（`src/tracker/contract/results.ts:23-27`），其中 `message` 的定义是「给人看的一句话，允许直接展示」。
- **原文今天没有固定位置**：多数地方把原文塞进 `message`（`src/tracker/rooms/github/errors.ts:110` 截 800 字、`src/tracker/rooms/github/client.ts:259`、GitLab 各处 `fail(kind, err.message)`），但契约里有一处明确不许塞（`src/tracker/contract/contract-label-colors.ts:42-43`：原子写失败的错误里带临时文件名，用户会去找一个不存在的文件）。所以「原文交出去」今天靠各后端自觉，不成规格,也不可断言。
- **判据写了四份**：
  1. 跟踪器层通用分类器 `src/tracker/preflight.ts:30-59`
  2. GitHub 后端 `src/tracker/rooms/github/errors.ts:64-106`
  3. GitLab 后端 `src/tracker/rooms/gitlab/errors.js:17`
  4. 客户端又拿 `message` 猜一遍 `src/client/kernel/api-io.js:204-206`、`:279-281`、`:318`
   仓库自己在 `src/tracker/preflight.ts:42-43` 写着「两处各写了一份判据，要同改」。
- **两处已实测的错判**：
  - `403` 加 `API rate limit exceeded`：通用判「没登录」（`preflight.ts:44` 的 auth 词表含 `\b403\b`），GitHub 后端判「被限流」（`errors.ts:91-93`）。

- **注册表里按后端名硬编码的链接兜底**：`src/tracker/registry/registryViews.ts:65`（GitHub 票网址）、`:66`（GitLab 票网址）、`:90`（GitHub 搜索页），同类还有 `:75-76`（`linkPattern` 的硬编码正则）。它们在后端没实现或抛错时替后端造语义。

## 建议方案

### 一、失败形状扩一个可选字段，专放原文

```
interface TrackerError {
  kind: ErrorKind   // 机器分支用，八档，不变
  message: string   // 给人看的一句，后端可以组装
  detail?: string   // 后端或命令吐出的原文，原样带出，截断上限统一
}
```

- 为什么不把原文塞进 `message`：`message` 的职责是「一句能直接展示的话」，原文的职责是「原始证据」；一个字段干两件事就会重演 `contract-label-colors.ts:42-43` 那个坑（把临时文件名当成给用户的建议）。加**可选**字段向后兼容：老读者不读它就等于今天的行为。
- 由构造处统一填：`fail(kind, message, detail?)`（`src/tracker/preflight.ts:67-69`），配一个共用的「取原文」函数——这段提取今天写了五份（`preflight.ts:36-38`、`errors.ts:56`、`errors.ts:77`、`errors.ts:110`、`gitlab/errors.js:17`、`github/fallback-reason.ts:38`）。
- 原文进返回值不等于原文进日志：日志仍按仓库红线脱敏（AGENTS.md「可重放的凭证原文永不落盘」），原文只随返回值交给人看。
- 兜底的意义：档位是猜的，原文是证据；两者同时交付，猜错也不堵人。

### 二、判据收成一源，各家只做扩展

- 第一性原理：哪些知识是共通的（命令没装、DNS 挂了、HTTP 状态码、进程 errno），哪些是各家特有的（gh 的 GraphQL 权限句式、GitLab 自己的文案）。共通的放一处，特有的当扩展项挂上去。
- 数据结构：有序规则表 `[{kind, pattern, note}]`，从上往下第一条命中即结果；后端的特有规则作为**前置表**先试，这样 `403 + rate limit → 限流` 能盖住通用的 `403 → 没登录`。顺序和表本身就是数据，可以被门禁断言。
- 顺序原则（从确定到含糊）：① 明确的状态码或 errno 码 → ② 专有错误码名（`ENOTFOUND`、`ECONNREFUSED`、`EAI_AGAIN`）→ ③ 专有句式（`command not found`、`rate limit exceeded`、`does not have the correct permissions`）→ ④ 含糊英文短语（`not found`）→ ⑤ 兜底网络。
- 同时收紧词表精度：`not ?found`（可省空格）要改成词边界写法，`ENOTFOUND` 才不会被吞。顺序治「一句话像两档」，精度治「子串被误吞」，两件都要。
- 客户端不再自己猜档位：`api-io.js` 那三处按 `message` 猜档位的正则删掉，改成把已有的 `kind` 映射成展示文案。

### 三、门禁：把判据变成可执行的数据

- 一张「原文样本 → 期望档位」表，样本取自真实报错（含上面两条已复现的错例），通用与各后端共跑。
- 顺序门禁：规则表顺序与文档一致；每条规则至少被一条样本触达（防死规则）；一句话多规则可命中时，断言结果等于更靠前那条（防有人悄悄调序）。
- 契约门禁补两笔：GitLab 的键快照（`tests/verify-contract-types.js:100-111` 今天只有 github 与 markdown 两份）与客户端真正读的 `links.*Template` 取值。
- 失败结果统一：每个失败都带 `detail`（原文确实为空时可以缺）。

### 四、注册表不再替后端造链接

- `registryViews.ts:65`、`:66`、`:75-76`、`:90` 的硬编码兜底去掉，改成「后端没给就诚实回空」。理由：注册表不该知道 GitHub 的网址形状，这跟本图「三个链接能力按各家语义走」是同一条原则；而且这些兜底只在后端没实现或抛错时生效，正是缺陷路径。

## 第二轮对抗式复核：上面那版要改的五处

第一版的大方向（档位 + 可展示的一句 + 原文三段式、判据收成一源、各家只做扩展、门禁咬住）不需要推翻。被推翻的是五处细节，其中一处是我自己写自相矛盾了。

### 一、原文不是一个字符串：多路证据 + 结构化码

- 今天的取原文写法 `(err.stderr || err.message || err.stdout)` 是**三选一**，会静默丢掉另外两路。而 `src/tracker/rooms/github/client.ts:248` 自己知道要把 `stderr || stdout` 拼起来——同一个决定在不同文件里写法不同，这就是「多处判据」的老毛病。原文一律**多路合并**（stderr 与 stdout 按发生顺序拼接）。
- 截断也有问题：今天 `.slice(0, 800)`（`github/errors.ts:110`、`client.ts:259`）只留头，而 gh 的错因常出现在尾部。改成「头 600 + 省略标记 + 尾 200」。
- **结构化证据今天已经存在**：`client.ts:259` 的失败结果里带 `code`，注释（`client.ts:257-258`，来自 #620）写着「gh 自己的约定是『需要登录 = 退出码 4』，只靠错误文案里的词去猜是巧合匹配；这里把 code 带上，分类才站得住」。而跟踪器层的通用分类器只吃字符串（`preflight.ts:30`），GitHub 房间的 `pickHttpCode`（`errors.ts:27-30`）**只用于日志、不参与判档**。所以：**分类的输入要从字符串升级成事实对象**（状态码 / 退出码 / errno + 文本），规则表第一层匹配事实，不再靠文本里有没有 `\b403\b`。这才是两处已知错判的根治——403 的正文里不一定写着 403，写着「not found」的正文不一定是 404。第一版把「状态码第一」写成了文本词表里的第一条，那正是 bug 的来源。

### 二、`raw` 不能是可选的

可选字段等于早晚被省略，门禁也就断言不了「每个失败都带原文」。改成**必填**（确实没有原文时给空串），构造统一走 `fail(kind, message, raw)`：TS 侧由编译器把漏填的站点全找出来；JS 侧（`src/client/kernel/api-io.js` 与 `src/tracker/rooms/gitlab/*.js` 里几处直接写 `{ok:false,error:{...}}` 字面量）编译器管不到，靠真实调用样本门禁兜。

字段名用 **`raw`**：仓库已有 `rawTip`、`vc.fail.raw` 用同一个词表示「原文」，沿用既有叫法读起来不用解释；与既有的 `code` 并存（码是机器可判的证据，`raw` 是人看的原文）。

### 三、规则表要自证，不另配一张样本表

每条规则**自带一条「必须命中我」的最小样本**，门禁断言 `分类(规则.样本) === 规则.kind`：新规不加样本就红（防死规则），也不必维护两张会漂移的表。真实长原文（含两条已实测错例）另进夹具做回归。

### 四、扩展项不许是复制 + 归一埋点提到跟踪器层

- 各家扩展只许加「通用层不该知道的」；门禁断言扩展项不与通用项同档位同模式（防止长出第五份判据）。
- GitHub 房间已有归一埋点 `error.normalize`（`errors.ts:49-62`，`emitNormalize`），**今天只有它一家有**。收口时把这件事提到跟踪器层，让所有后端都留同一趟轨迹（日志纪律：异常行写清环节、期望与实际差在哪）。

### 五、客户端那三处不是「删掉」而是「换词表」；契约边界那句我写错了

- `src/client/kernel/api-io.js:202-206` 把 kind **覆写成客户端自己的词**（`'404'`、`'notFound'`、`'rateLimit'`），与契约八档不同名；catch 分支（`:210-214`）还自己造 `{kind:'network'}`。改成只留一张「八档 → 界面档」的映射表，自造的失败也走同一个构造函数。
- **我第一版写「本图不动契约目录的结构与名录」，但 `TrackerError` 加字段本身就是契约改动**，两边都会以为对方管。修正口径：本图动**字段**（`src/tracker/contract/results.ts:24-27` 的 `TrackerError` 加一行），不动**目录结构与名录**（那是地图02 的收尾范围）；理由是这个需求由本图提出，契约只做见证。

### 另外三处补强（不改方向，但漏了就不完整）

- **展示侧**：契约写明「失败展示必须能展开原文」，复用已有语种键（`vc.fail.raw`、`lc.backendSaid`）。否则 `raw` 只是躺在数据里，兜底兜不到人。
- **脱敏**：`raw` 返回前对已知凭据样式（`ghp_`、`Bearer `、`Authorization:`）做遮蔽并留标记；日志仍按红线脱敏。给人看懂发生了什么，不等于能把凭证粘进 issue。
- **落地成本**：触碰的 JS 文件按仓库规矩「先修后转、两次提交」；收口方向（各家把分类委托给跟踪器层）会让 GitLab 那份文件变小，转换成本随之降低。
