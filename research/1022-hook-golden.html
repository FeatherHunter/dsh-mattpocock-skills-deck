钩子与金标准：从头讲到你能复述

对抗式自查：每节末尾有一句“你能说出来吗”，说不出来就是我没讲透，不是你的问题。

起先从 Node 的死规矩说起

Node 只认识 .js。代码里写 import './x.js'，Node 就去磁盘找 x.js，找不到就报错，它不会自作主张去找 x.ts。

仓库正在把 .js 一个个改名成 .ts。改名后引用处还写 ./x.js（发布产物本来就要这个写法，不能改）。于是中间缺了一步：谁把旧名字领到新文件。

钩子就是补这一步的人。它站在 Node 找文件之前，先看一眼：你要的 .js 旁边有没有同名 .ts，有就给你新的，没有就让你按原来的路走。

你能说出来吗：钩子不改代码，只在找文件那一步多看一眼。

钩四种情况，一个例子走完

例子：src/deck/tools/issue-get.ts 里写着 import '../shell/call-shell.js'。

情况1：旁边有同名 .ts（最常见）磁盘上有 call-shell.ts → 钩子直接给你 call-shell.ts。引用处一个字不用改。
情况2：旁边没有 .ts（还没转完）磁盘上只有 call-shell.js → 钩子说“我不管”，交给 Node 原样找 .js。这就是“没有就交给 Node”。
情况3：裸包名（你问的那句）比如 import 'dsh-log/host'、import 'node:fs'。它不以 ./、../、file: 开头，也不是绝对路径，就是一个包名字。钩子碰都不碰，因为它不是我们仓库里的文件，是外面装进来的包，一改就坏。这就是“裸包名不碰”。
情况4：在 node_modules 里（你问的另一句）比如目标算出来落在 .../node_modules/某某包/x.js。就算它长得像相对引用，钩子也不碰，因为那是别人包内部的事，我们的“同名优先”只管自己仓库。你可以记成：只给自己家指路，不进别人家改门牌。
你能说出来吗：1 有就给新的，2 没有就放行，3 包名不看，4 别人家不进。
还有一种绝对路径：测试里写 require(拼出来的 D:\...\src\...\x.js)。它看着不像相对引用，但说的还是同一件事，钩子同样先看有没有同名 .ts。没有这一条，转完当天那条测试就炸。

错旧电脑会看到什么

同步钩子要 Node 22.15 才有。旧 Node 上钩子根本不存在，直接调会是一句看不懂的报错。钩子第一件事就是把这句换成人话：本仓要 22.22.2 以上，见根 package.json。这是报错信息，不是门禁。

金标准里还有一道自证：如果磁盘明明有 .ts 兄弟，解析却给了 .js，说明钩子没挂上，宁可当场红也不假装绿。

秤金标准为什么能当秤

从头说：口头说“没改坏”不算数，要机器判。做法是把九个工具各调一次，顺序固定（先建票再查票再建地图，因为写操作有先后），输入固定（工作区新建临时目录、会话固定叫 s-golden、时钟固定、配额固定），回执归一化后逐字节存档。差一个字就红。

归一化只抹三样：本次的工作区根换成 <ROOT>、由根算出的钥匙换成 <WSKEY>、Z 结尾的时刻换成 <TIME>。别的时刻形状若出现，让它红，不悄悄抹。票标题正文里不许出现像日期的字，不然会被当时间戳抹掉。

对象键先排序再比（键顺序不算语义），数组顺序不动（列表本来就按 key 排过）。重建基准只有一条路：有意改行为且已评审，用 --update，顺手跑的不算。

你能说出来吗：固定输入调九次，只抹三样，差一字即红。
边界要记牢：每个工具只守一次最小调用的快乐路径回执。错误分支、契约层各有别的门禁守。秤绿不等于全对，秤红则一定是有东西变了，按分拣指南看（先看配额常量，再看归一化漏没漏，再看键多少与值变没变）。GitHub 房要联网，不进逐字节比，只对照形状。
