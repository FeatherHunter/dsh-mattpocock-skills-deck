# #756 输入区胶囊与宿主列宽联动：打开瞬间是否引发整列重排

> 落盘日期：2026-09-26。只读调查，没有改任何生产代码。
> 读的代码是当前工作区现状，行号以本次读取时为准。
> 用词只用仓库已有词与本票正文已有词（面板、状态栏、胶囊、输入框、输入卡、宿主列、会话列、观察器、计算样式、布局抖动）。新概念用完整一句话说清，不造简称。
> 凡是写了宽度数字的地方都注明是实测还是没量到；本次没有真机测量，数字一律写没量到，不猜。

## 先说结论（给第一次读的人）

1. 状态栏确实住在输入框正上方的同一个纵向列里，列宽联动是真实存在的：面板一开，宿主把会话列让出一部分给右侧边栏，输入框所在列变窄，胶囊跟着变窄。这不是猜测，是三段代码连起来的结果，见第 1 章。
2. 打开瞬间最先变的是宿主那一列的宽度，然后是胶囊的外框宽度，最后是胶囊里面每段字的显示与隐藏。胶囊里面字的增减本身不会再把整列推宽，因为胶囊外框宽度只由样式表决定，改字只改胶囊内部的显示，不回写列宽。回路是单向收敛的，见第 2 章。
3. 整列重排会不会把整个界面拖慢，本次只读代码给不出耗时结论。代码里能看到的是：胶囊的阶梯机在每一次列宽变化时都从第 0 档重新走一遍，每走一档触发两次强制重排（读一次写一次），档数随字数变多；面板头部的折叠机同样逐档重走。打开瞬间这两台机器都会被列宽变化唤醒，属于同一时刻抢同一次布局重算。贵不贵要真机量，量法与空表见第 3、4 章。
4. 宽度对照表目前是空表，没量到。量完填表即可定性，不用改代码。

### 1.2 状态栏的对齐算式与注释（`src/client/statusbar/StatusBar.js` 第 10–43 行）

### 1.3 面板的列宽观察器（`src/client/panel/Dock.js` 第 32–45 行、第 57 行）

- 第 32 行 `dockRef` 是面板根节点的引用，第 33 行 `dw` 是面板宽度的本地状态，初值 460。
- 第 37–45 行是一个尺寸观察器：盯住面板根节点，宽度一变就把新宽度写进 `dw`，卸载时断开。
- 第 57 行 `narrow = dw < 380`：窄于 380 时动作按钮折叠为纯图标。
- 这个观察器只管面板自己那一列的宽度，不管输入框那一列。它在打开瞬间会响一次（从不存在到出现），之后只在拖拽面板边框时响。

### 1.4 胶囊与父容器的两个尺寸观察器（`src/client/statusbar/StatusBar.js` 第 146–167 行）

- 第 151 行 `roFold` 盯住胶囊本身（`foldRef.current`），第 152 行 `roParent` 盯住胶囊的父容器（`foldRef.current.parentElement`）。
- 两个观察器的回调都是 `applyFold`（第 135–145 行），即重跑胶囊的折叠阶梯机。
- 挂载在第 155–159 行：先跑一次 `applyFold`，再分别观察，观察器的句柄与当前元素记在 `foldWatch` 里。
- 第 139–144 行是换代处理：胶囊这个元素在功能区收起再展开时会被重新创建，旧元素摘下后尺寸不再变化，观察器必须挪到新元素上。每次进场先对一眼，不一致就断开旧观察并重新观察。
- 第 160–161 行还接了窗口尺寸变化与字体就绪两条路，第 172 行是每次提交后重跑一次（2026-09-24 去掉了此前的 2 秒轮询，见第 168–171 行注释）。
- 胶囊本体的渲染在第 231 行：`width: '100%'`，即胶囊外框等于父容器内容宽，再受样式表上限夹住。

折叠的判据与机器（监听回路的下半段）：

- 判据 `src/client/statusbar/capFold.js` 第 50–60 行：九段字的让位单位，品牌与时间串逐字减少，其余整段一起让位；第 114–139 行排整条阶梯，相邻两档只差一个单位。
- 机器 `src/client/statusbar/capFoldMachine.js` 第 30–80 行的 `runCapFold`：每次从第 0 档重走，量一次放不放得下，放不下就往下一档，直到放得下或走完。第 49–53 行是量不到有效可用宽时的守卫（未知时不写界面，只安排一次下一帧重算），第 57–68 行是每档的写法（去掉折叠类、强制重排一次、写字、再强制重排一次）。

## 2. 打开瞬间谁先变：变化顺序与监听回路

### 2.1 变化顺序（只读代码推出的先后，不含耗时）

1. 用户点开面板，宿主把右侧边栏那一列显示出来，会话列变窄。这是宿主布局的行为，代码不在本仓库，是后面一切的输入。
2. 会话列一窄，输入卡与状态栏容器同时变窄：两者宽度都由同一套宿主变量算出（输入卡是宿主自己算的，状态栏容器是第 1.2 节那条算式算的），所以两者同一步变窄，不存在谁等谁。
3. 胶囊的外框跟着父容器变窄（胶囊宽是容器的百分之百，再夹到同一上限）。
4. 胶囊与父容器的两个观察器响起，重跑折叠阶梯机，把放不下的字逐档收起。面板头部与标签栏的折叠机同样被面板自身宽度变化唤醒，各自逐档重走。
5. 收字只改胶囊内部每段字的显示与隐藏（加或去 `display:none` 类，样式见 `styles.js` 第 165 行），不改任何列宽变量，所以不会把列再推宽。回路到此收敛。

### 2.2 监听回路图（文字版）

- 宿主列宽变化 → 浏览器布局 → `roFold` 与 `roParent` 同时响 → `applyFold` → `runCapFold` → 改九段字的文本与折叠类 → 浏览器再次布局。
- 改字之后胶囊的 `clientWidth` 与 `scrollWidth` 会变，但观察器听到的是尺寸变化，而收字只会让内容变小，不会让外框变大，所以不会形成来回震荡。极窄时阶梯走到最后一档就停（判据第 150–155 行：超界档号停在最后一档），之后再窄也不再有下一档。
- 面板那一侧是独立回路：面板根节点尺寸变化 → `Dock.js` 的 `ro` → `setDw` → 重渲染 → `narrow` 标志与头部折叠机（`applyHead`）跟进。这条回路不经过会话列，两列之间唯一的耦合点是宿主在打开瞬间同时改了两列的宽度。
- 需要特别说明的一条旧回路已经不存在：第 168 行注释写明，此前还有一条 2 秒轮询兜底重算，本票所在版本已删除，现在只剩观察器两条、每次提交后一次、字体就绪一次、窗口尺寸一次。

### 2.3 会不会拖慢整个界面（不动代码的看法）

只读代码能确认的是风险位置，不能确认耗时：

- 风险位置一：胶囊阶梯机每次都从第 0 档重走，每档两次强制重排。打开瞬间列宽从宽变窄只触发一次重走，档数等于要收掉的字数，是有界的。日常使用中列宽不变时它不跑。
- 风险位置二：面板头部折叠机（`Dock.js` 第 132–170 行）同样逐档重走，每档一次强制重排，打开瞬间与胶囊机同时跑，两台机器抢同一次布局。
- 不构成整列反复重排的理由：两台机器都没有自己给自己续命的定时器（胶囊机的单次重试见 `capFoldMachine.js` 第 178–189 行，单飞一次，跑完即摘），收敛条件都是放得下即停。
- 真正的耗时要真机量，量法见下一章。如果量的结果是打开瞬间只有一次短暂的布局抖动且在百毫秒内收敛，就属于正常开销；如果看到反复横跳（宽度数字来回变、折叠档号来回变），再查是不是观察器与提交后重算互相唤醒。

## 3. 开发者工具记录法（不动代码，只看与只记）

目标：记录面板打开前后三个宽度的数字，看清谁先变、变多少、有没有抖动。

三个宽度：会话列宽（输入框所在列）、输入卡外框宽、胶囊外框宽。会话列宽是宿主节点，输入卡是宿主节点，胶囊是本插件节点（类名 `dsws-capsule`）。

### 3.1 看计算样式（每个宽度记什么）

1. 打开开发者工具的元素面板，用拾取器分别点中输入卡与胶囊。
2. 在计算样式侧栏记下三项：`width`、`max-width`、`box-sizing`。胶囊的 `max-width` 应显示宿主变量换算后的像素值，容器应显示 `calc` 换算后的像素值。
3. 在样式侧栏确认变量来源：搜索 `--dsh-composer-card-max-width` 与 `--dsh-composer-side-clearance`，看它们挂在哪一层节点上，打开前后值变没变。如果变量值没变而像素宽变了，说明变的是列宽本身，不是变量。
4. 同一位置连记两次（面板关闭时一次、面板打开后稳定时一次），每次等面板头部时间标签不再变化、没有转圈后再记，避免把取数等待算进去。

### 3.2 看布局抖动提示（怎么看有没有反复重排）

1. 用性能面板录制一次面板打开：从关闭态开始录制，点开面板，等内容稳定后停止录制。
2. 看长任务与布局事件：只看有没有连续的强制布局长条，有没有同一节点的反复读写。如果只有打开瞬间一簇布局事件且随后归零，就是单次收敛；如果出现周期性反复的布局事件，再对照是不是胶囊折叠档号在变（胶囊节点上有 `data-fold-tier` 属性，录制前后各看一眼）。
3. 看胶囊的折叠档号：元素面板里找到 `dsws-capsule` 节点，看 `data-fold-tier` 与 `data-fold` 两个属性。打开前记一次，打开后稳定再记一次。如果档号只朝一个方向走（变大），是正常收敛；如果来回变，才是抖动。

### 3.3 记录时机（打开前后各记一次）

- 关闭态：右侧面板完全关闭，等输入区稳定，记三个宽度。
- 打开态：面板打开并显示本插件面板，等面板头部时间标签稳定、胶囊档号稳定，再记三个宽度。
- 对照态（可选）：右侧面板打开但显示别的面板，记一次，用来区分是本插件面板的内容贵，还是只要右侧边栏出现就会压窄。
