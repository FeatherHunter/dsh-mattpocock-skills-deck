- 七个动作模板与三个建票模板都写着同一句：「- [ ] 提问前用一句话说明已查阅范围，问题本身仍按本模板原有提问格式提出。」（`config/prompts/ticket-action-templates.yaml:19、61、98、249、296、337、406`；`config/prompts/ticket-creation.yaml:20、96、133`；英文各对应一份）。
- 「原有提问格式」指 grilling 技能的 `❓ Q1` + `➡️ 推荐答案` 写法（`package/bundled-skills-zh/grilling/SKILL.md:13-21`）；同一技能第 8 行「给每个问题编号，并给出你推荐的答案。然后等用户回答，再进入下一轮」与第 26 行「把每一个都摆到用户面前，然后等」，把「正文提问 + 以提问结束这一轮」写成了默认流程。分诊模板收尾还要求「结尾用提问格式收尾……等回复再动」（`ticket-action-templates.yaml:22`）。
- 所有模板共用同一段「## 工具」公共小节（`config/prompts/shared-sections.yaml:6-16`，模板里写 `{{shared:sharedTools}}` 由 `readPromptConfig` 展开）。真要改成"用工具提问"，最小落点就是这一段：改一处覆盖 40 个模板位置（动作模板 18、建票模板 6、地图推进 16，均按语言各计一次）；若单独立一个新小节，还得把 `scripts/lib/prompt-config.mts:226` 的 `PROMPT_SHARED_SECTION_IDS` 补上（那里要求公共小节的顶层键与清单逐项相等，多一个少一个都会抛错）。

## 既有决定，以及本轮核到的新证据

- `AGENTS.md:25-27`「提问方式」：需要人拿主意时把问题直接写在对话正文里，不用弹窗式提问工具（2026-09-08，提交 `99667bfbb`）。**但这是开发本仓库时的工作约定，不随插件发布**——2026-10-28 维护者指出这一点后我核过，见下一节。
- `.out-of-scope/popup-question-tool.md`（2026-10-21，提交 `75bf03788`，因 #1101 而写）：三条理由——①面板与检查链这一侧调不到 agent 工具，唯一杠杆是注入文字；②仓库偏好是问题写在正文；③现有做法已覆盖（`tpl.supplement` 问用户、`tpl.discuss` 按模板提问）。第 13 行还写了「如果以后要重新考虑，先改 AGENTS.md 的那条约定，再谈动作表与提示模板怎么加」。
- 本轮核到、当时没记的新事实：
  1. DSH 今天的问答卡**不是模态弹窗**，而是占住输入框位置的附着式卡片（`dsh-client-ui-user-questions/README.zh.md:28`），正文还在、可以跳过、关掉只是隐藏、之后能重新打开回看（`:12`、`:32`、`:38`）。所以"弹窗会挡住正文解释"这条理由对今天的实现已经不成立。
  2. 更站得住的理由是行为形态不合：工具默认是阻塞式等待（`dsh-tool-ask-user/README.zh.md:12`、`:30`），没有接手回答的人时由服务在到期后放行（`dsh-user-questions/README.zh.md:27`）；而动作会话是异步的——问题往往要等维护者几小时后回来答，用正文提问能让这一轮干净收束，答复在新一轮到达。另外问答卡的词表只装「选项 + 可选的自定义文本」（`dsh-user-questions/README.zh.md:56`），而本仓的 `❓ Q` 格式是带多段说明、还要逐个给推荐答案的开放问题，塞不进选项表单。
  3. 阻塞也不是不能改：预设可以设成 `mode: timed`（`dsh-tool-ask-user/README.zh.md:12`、`:28`），到期返回 pending、之后的回答以用户消息送达（`:66`）。所以要推翻原判，真正要谈的是"改成 timed 之后提问语义变成什么样"，比"换个控件"大得多。

## 更正：AGENTS.md 不随包发布，用户侧机制在提示词模板里

2026-10-28 维护者指出：本仓根目录的 `AGENTS.md` 是他电脑上的开发约定，**不会影响用户机器上的 AI**。核实结论：

- 发布物清单 `package/package.json:29-40` 的 `files` 只有 `lib / shared / deck / tracker / refresh / cordis.patch.yml / bundled-skills / bundled-skills-zh / scripts / CHANGELOG.md`：没有 `AGENTS.md`，也没有 `config/prompts`（提示词在构建期由 `scripts/generate-prompt-config.mts` 生成进 `src/client/kernel/prompt-data.ts`，再编进 `lib`）。
- 在已构建的 `package/lib` 里搜字面：「弹窗式提问工具」0 命中、「提问方式」0 命中、「ask_user_question」0 命中；而模板里那句「本模板原有提问格式」10 命中。
- 所以用户侧真正的机制是：**随包发布的提示词模板**要求 agent 按 `❓ Q` 格式在正文末尾提问（`ticket-action-templates.yaml` 十处、`ticket-creation.yaml` 三处），随包的 grilling 技能又定义了这套写法；发布物里没有任何一句提到 `ask_user_question` 工具。用户侧被载入的 `AGENTS.md` 是目标工作区里用户自己的那份（宿主 `agent-instructions` 载入），与本仓无关。
- 含义：想让用户侧的提问改用工具，改的是**随包提示词**；改本仓 `AGENTS.md` 对用户行为没有影响。之前 `.out-of-scope/popup-question-tool.md:10` 拿「仓库偏好 / AGENTS.md」当理由，是把开发约定误当成产品理由，这次复核应当一并订正。

## 维护者 2026-10-28 补充的理由（已原话记在票上）

- 工具会把给用户看的方案吞掉：问「A/B/C 选哪个」时三套方案内容很多，卡片只装得下短标签，人点选时看不到全貌，容易做出无效决策。
- 机制核实：问答卡词表只有「选项 + 可选自定义文本」（`dsh-user-questions/README.zh.md:56`）；问题详情限高、与选项共用内部滚动区（`dsh-client-ui-user-questions/README.zh.md:32`）；一次只有一个请求持有卡片（`:118`）。所以它是「短、闭合、选项式」的确认工具，不是「审三份长方案」的载体。
- 这条比 2026-10-21 记的「弹窗挡住正文解释」更硬：它解释的不是「为什么不该弹」，而是「为什么弹了也做不好决策」。

## 若想消除「AI 以为一定不许用工具」的误读，提示词最小改法（提案，未实施）

- 先明确：发布物里没有一句禁止或限制 `ask_user_question` 的话（`package/lib` 内该词 0 命中），所以不是「删禁令」，而是「补许可 + 写分工」。
- 覆盖面最大的一处：`config/prompts/shared-sections.yaml:8-11` 的「## 工具」小节（动作模板 18 处、建票模板 6 处、地图推进 16 处，共 40 处，按语言各计一次）。候选措辞（只是提案；2026-10-28 按维护者反馈已去掉解释性括注）：「向人提问分两种：短小的闭合选择（互斥选项、确认/跳过、要不要继续）直接调用 `ask_user_question` 问；需要人读完全文再拍板的抉择，按本模板提问格式写在正文里。」
- 配套一处：`ticket-action-templates.yaml:22` 后补一条「其中只需人做个短选择、不必先读大段说明的（要不要按 wontfix 关票、选 A 还是 B），先直接调用 `ask_user_question` 问清，拿到答复后再写这张票的收尾。」
- 措辞原则（维护者 2026-10-28 指出）：提示词正文是给 agent 的执行清单，只写「做什么、什么时候用」，不写解释、免责声明或「没有被禁用」这类元信息；解释归 `use` 字段（`config/prompts/workspace-initialization.yaml:62` 就是这种写法）。仓内提示词正文里「因为/所以」这类解释句 0 处——这条原则本来就在。
- 边界：①只给许可、不写分工，会把行为推向另一头（长方案塞进卡片，正是维护者 2026-10-28 第二点担心的事），两句必须成对；②随包 grilling 技能仍把提问写成多段正文并「然后等用户回答」（`package/bundled-skills-zh/grilling/SKILL.md:8、:26`），走 `/wayfinder`→grilling 的入口会继续按正文问，除非同时改技能，而那是上游 Matt Pocock 技能的译文，改它等于偏离上游，需单独拍板；③宿主 plan 模式那句限制与工具默认阻塞仍在，提示词改不掉；④模型行为只能被影响、不能被保证，验证只能人工看会话。
- 这段是提案，本轮没有动任何提示词文件，也还没列成票。**2026-10-28 晚维护者拍板选方向甲（问答卡片没有位置），本提案作废、不实施。**
