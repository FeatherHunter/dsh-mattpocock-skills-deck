## 0 一句话结论

仓库里已经跑通两条 YAML 路线，**剩下适合搬的是「名册、数字、清单、文案」这四类数据**，一共 22 项强候选、8 项中候选；
承载逻辑、需要编译期类型安全、或者收益低于搬动成本的部分，明确不该搬，共 18 项。
按批次排下来，建议分三批做，第一批三到五天就能见效。

22 项强候选是逐条从源码里看出来的，不等于全部都该搬。**本轮又逐条回到源码复核了一遍**：
3.4 节收出 **13 项确定要进 YAML**（那里有一张表，逐项写了现在值在哪、建议的文件、为什么确定、落地时的边界），
3.5 节把 8 项从强候选里划掉并附了理由（观感变更、要别人点头、工具只认原格式、原本那条记错了行号）。
**实施就从 3.4 那张表开始**，4 章的中候选与 3.5 节里提到「还要挑」的另算。

## 1 判据

- **强候选**：值是数据不是逻辑；人能改而不用改代码；今天已经存在第二份硬拷贝，或者同一个字面量散在多处；条目同构可枚举。
- **中候选**：条目同构，但有类型敏感的分支。搬进 YAML 会丢掉类型安全，必须写清替代做法（字符串枚举 + 校验器 + 单一真源函数）。
- **不适合**：承载逻辑、需要编译期类型安全、或者收益低于搬动成本。

每项都写了五件事：现在值在哪、谁在用、有没有第二份真源、建议的 YAML 形状、迁移代价与风险，以及机制上能不能做。

### 2.4 动手之前必须知道的几件事（前一片调查的结论，都是会踩的坑）

- **门禁归属表要跟着改**：`scripts/gate-map.mts` 按路径前缀决定哪扇门禁管哪些文件，今天 `config/` 目录零命中（见 #1283）。新增 `config/` 下的文件必须同步登记，否则不会被门禁盯上。
- **数组型校验目前只认一组**：`scripts/generate-time-config.mts:46-50` 只对 `backoff` 一个数组组做了逐项校验。新的数组字段要先扩校验器，否则写错形状不会被拦。
- **`core` 模式下 YAML 会被当文本**：`yes/no/on` 变成文字、`1.10` 变成数字。所以 YAML 里要显式加引号，别让值的意思随解析模式变。
- **忘了跑生成器会静默过期**：生成物不入库，全新检出要现场生成。靠 `--check` 门禁兜底，别指望人记得手动跑。
- **时间参数不做运行期可调**：调参走发版，这是 #1215 定下的口径。别把「运行期读盘」当成时间参数的做法。
- **文案里的时间引用只有一种形状**：`{{名}}`，且名要在时间参数里真实存在。
- **`verify-time-config` 正在隔离期**（`scripts/verify-stages.json:93-97`），归队时间看 #1215。

### 3.5 本轮复核后从强候选里划掉的项（附理由）

- **状态色散点统一**（`#3fb950`、`#f87171`、`#f59e0b`、`#58a6ff` 散在约 15 个视图文件）：搬进 YAML 顺带要选一种绿 —— `#3fb950` 与 `src/client/views/shared/chips.ts:24` 的 `#4ade80` 是两个不同的绿，选哪个是观感变更，得人拍板。
- **命名词表**：`SESSION_TITLE_MAX_BYTES = 120` 按 `src/shared/naming-titles.ts:184` 的注释「改它等于改产品边界，必须有人看见，所以这里保持字面量写法」留在代码里；剩下的词是中英成对的文案，宿主半与界面半都要读，而现有词族那条生成链只产出界面那一份，机制上没有现成路。
- **文件位置约定**：`.scratch` 是对外的工作区目录约定（散文与代码里 86 处命中），且矩阵门禁断言 Markdown 路径模块零手拼路径串（`scripts/matrix-full.ts:92`），搬进 YAML 与那条断言的意图相冲；另外 `workspaceKey.ts:68` 那处是误报 —— 那个文件只有三个纯函数，没有可搬的路径字面量。
- **日志字段白名单与事件名台账**：设计契约 `docs/design/335-logging-contract.md:96` 说以附录第 1 节为执行清单，要不要改成 YAML 得日志总纲 #502 点头。
- **发布版本门槛**：本机 PowerShell 7.6.6 没有 `ConvertFrom-Yaml`（实测），`.ps1` 脚本读不了 YAML，要么另装模块，要么改成由 Node 侧生成片段。
- **依赖放行名单**（`pnpm-workspace.yaml:19-47`）与**第三方步骤哈希登记**（`.github/workflows/verify.yml:20/25/34/77`）：工具自己只认原格式，搬进 YAML 只会多一份要靠门禁保持同步的副本 —— 与「消灭第二份拷贝」相反。
- **矩阵维度定义**（3 系统 × 3 后端）：持续集成那侧平台只认工作流文件（`.github/workflows/verify.yml:15`），脚本侧再抄一份就成了第二份。
- **引擎版本约束的派生依据**：记的是「为什么是这个下限」而不是「现在是多少」，属于决策记录而不是配置值。

## 5 明确不该搬的（附理由）

**承载逻辑的（搬了就变成用 YAML 写程序）**
- 出站分档动词判定 `outbound-tiers.ts:36-81`——是分支逻辑，不是取值。
- 语义相关性算法的阈值 `naming-attribution.ts:85-108`——阈值与循环耦合，只搬数字没有意义。
- 标题清洗的正则与截断算法——正则放进 YAML 更难读；`SESSION_TITLE_MAX_BYTES` 按代码里那句注释的要求也留在代码（见 3.5 节）。
- 命令结果的分类与重试决策——流程判断，档位名已经有真源，流程留在代码里。
- 矩阵断言逻辑——那是测试逻辑，搬走等于发明一套「用 YAML 写测试」的语言。

**架构接线的**
- seam 绑定层 `src/seam/index.ts:23-30`——只有 6 行，是架构接线。

**需要编译期类型安全或平台只认原格式的**
- 类型检查圈选清单（两份 `tsconfig.*:19-43`）——编译器只认原生文件，生成器会形成自检循环。
- 持续集成矩阵与 Node 版本（`verify.yml:13-15`、`:36-39`）——平台只认工作流文件，自己生成持续集成配置风险最高。
- 构建输入与产物清单 `build.mts:104-107`、`:673`——与指纹、清理顺序、拼接标记耦合，搬走后构建前置失败会拖垮全链。

**两端契约与兼容**
- 图标 SVG 路径——名字才是逻辑键，路径不搬。
- `wf.*` 约 37 个宿主调用名——两端契约，YAML 化会造出第三份真源。
- 槽位的 order 与 scope——由架构决策记录 #221 与 #308 治理。
- localStorage 键——要兼容老数据。
- 图标与状态色以外的排序比较逻辑、`setTimeout 0` 与动画帧调度——是行为。

**换了格式但没解决问题（收益低于成本）**
- 门禁阶段清单 `scripts/verify-stages.json` 转 YAML：读取已经收敛、校验已经严，转格式只是换皮。
- 两份棘轮基线 `tests/handwritten-js-baseline.json`、`tests/unmigrated-tests-baseline.json` 转 YAML：各 11 行、各只有一个读者，重录操作一行不少。
- `package.json` 的脚本串转 YAML 生成：重蹈「双长串」的老教训。

**单处短字面量**
- `HASH_RE`、`MARKER_LINE_RE` 这类只有一处消费的字面量——搬了只多一层间接。
