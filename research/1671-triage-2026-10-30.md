## 票面事实核对

两条主张都与本机 HEAD 一致：

1. **中文模板首行读不出**：中文三份模板首行是 `# 议题跟踪器：GitHub`、`# 议题跟踪器：GitLab`、`# 议题跟踪器：本地 Markdown`，中文词加全角冒号，命中不了 `^#\s*issue\s*tracker\s*:\s*...`。前两份只是靠正文里恰好出现的 `gh` / `glab` 掉了 low；本地 Markdown 那份正文没有英文关键词，直接落 no-keyword。
2. **第三方后端 id 读不出**：写 `# Issue tracker: notion` 同样落 no-keyword。而 `readEvidenceLayers.ts:184-189` 对任意 `explicitBackendId` 都原样回传（高置信记 hit、低置信记 abstain），`backendDecision.ts:823-825` 在 hit 之后用 `isKnown()` 问注册表：装了就是结论，没装就是 `declaration-unknown-backend`（`:454` 的文案「声明文件里写明的后端「{detail}」没有装上：装上它，或者改这一行标题，就能定下来。」）。这条路今天在生产上**永远走不到**，因为解析器只会产出 github / gitlab / markdown 三个 id，而这三个在正式装配里都装着——档位建好了，上游那个「未注册的 id」永远不会来（`f086a8e33`、`0b55ae6e7` 引入，2026-10-14）。
3. **影响链核对**：低置信在读取层就翻成 abstain（`:186-189` 的注释写明是方案 A，见 #1572），不进判定层结论。所以中文用户照插件自己的模板写好的声明，实际不产生结论：本地 Markdown 只剩 `.scratch` 目录探测，没配 git remote 的工作区于是 `no-backend`。工具装配层 `deck-tool-bridge.ts:196-229` 用的是同一个解析器，低置信也保留 id 只作证据，路径同源。

## 票面建议修法验算：两处要补

把票面给的三条正则按原样拼起来跑（`HEAD` 取票面那串，titleMarkdown / titleGitlab / titleGithub / titleOther 四条），逐条喂上面那批输入：

- 中文 GitHub / GitLab 两份模板：**会被修好**（high / title-github、title-gitlab）。
- 中文「本地 Markdown」模板：**仍然 no-keyword**。原因是它在冒号后写的是「本地 Markdown」，票面的 titleMarkdown 只认紧跟在冒号后的 `(markdown|local)`，而 titleOther 的 `[a-z0-9]` 又匹配不上汉字「本」。也就是说，按票面正则改完，中文三份模板里有一份还是坏的。**补丁 1**：titleMarkdown 改成 `(?:本地[ \t]*)?(markdown|local)\b`，模板一个字不用动。
- `# Issue 追踪器：Notion`：票面正则勉强能读到 id，但捕获出来是 `Notion`（大写 N），而注册表的 `has(id)` 是严格相等（`src/tracker/registry/core.ts:154-155` 的 `byId.has(id)`），注册 id 的推荐形状是小写点分的 `publisher.name`（`docs/architecture/third-party-tracker.md:58`）。于是本票触发场景那句首行会被判成「后端「Notion」没装上」——明明装了，报没装。**补丁 2**：捕获后 `.toLowerCase()` 再回传。
- 另有一个小口子：`# Issue tracker: other` 按 titleOther 会变成「other 没装上」，但 `other` 是已废弃的保留名（注册表直接拒收，见 `src/tracker/registry/shape.ts:148-150`），写它的人本意是「没有后端」。建议 titleOther 里排除这个保留名，让它照旧落 no-keyword。

## 修法形状（候选，尚未实施）

一处文件、一个纯函数，形状如下（行号按当前 HEAD）：

```ts
// src/tracker/kernel/issue-tracker-declaration.ts:42-44 这一组换成：
const HEAD = String.raw\`^#[ \t]*(?:issue[ \t]*tracker|议题跟踪器|issue[ \t]*追踪器)[ \t]*[:：][ \t]*\`
const titleGitlab = new RegExp(HEAD + String.raw\`gitlab\b\`, 'im')
const titleMarkdown = new RegExp(HEAD + String.raw\`(?:本地[ \t]*)?(markdown|local)\b\`, 'im')
const titleGithub = new RegExp(HEAD + String.raw\`github\b\`, 'im')
// 兜底：任意别的 id 原样（转小写后）回传，由注册表判「装没装」
const other = new RegExp(HEAD + String.raw\`([a-z0-9][a-z0-9._-]*)\`, 'im').exec(text)
```

- 互斥顺序（GitLab > Markdown > GitHub）与 `MULTI_CLAIM_ORDER`（`backendDecision.ts:325`）都不动；titleOther 排在三者之后，只接它们都不吃的情况。
- 中文标题词只用模板与说明里已经出现的两个（`议题跟踪器`、`issue 追踪器`），不造新词。
- 分隔符用 `[ \t]*` 而不是 `\s*`，避免把正文跨行吞进标题行。
- 捕获到的 id 转小写再回传；`other` 保留名排除；低置信的正文关键词兜底（`:61-69`）原样保留。
- 下游不用改：读取层回传任意 id（`readEvidenceLayers.ts:184-189`），判定层用 `isKnown()` 分「装了就是结论 / 没装给提示」两档（`backendDecision.ts:823-825`），注册表与工具装配层都不用动。
- 分辨率等级：高置信。中文 GitHub / GitLab / 本地 Markdown 三份模板与任意已注册 id 都会从 abstain / no-keyword 变成 hit。

## 可复现性（不需要真机）
