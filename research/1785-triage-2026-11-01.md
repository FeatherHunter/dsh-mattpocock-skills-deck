问题：换不到 id 就跳过（连「查人命令本身失败」也吞掉），最后照旧发 PUT；`assignee_ids=` 空串在 GitLab 那边就是「明确要求清空认领」，于是原有认领被删；写路径还按成功返回，回执只剩 deck 层写后回读给出的模糊说明。

修复后（当前 `src/tracker/rooms/gitlab/graph-membership.ts:169-198`）：

```ts
172:     const assigneeIds: string[] = []
173:     const unresolved: string[] = []
174:     for (const u of wanted) {
175:       let resolved = ''
…
184:       } catch {
185:         // 查人这一步抛错，同样算换不出 id，交给下面的整步失败处理，不再吞掉接着写。
186:       }
187:       if (resolved !== '') assigneeIds.push(resolved)
188:       else unresolved.push(u)
189:     }
190:     if (unresolved.length > 0) {
191:       // 一个写请求都没发出去，远端认领还是原样，所以原文给空串。
192:       return fail(
193:         ERROR_KIND.NOTFOUND as ErrorKind,
194:         `认领人用户名不存在：${unresolved.join('、')}。原认领没有改动，这次没有发出写请求。`,
195:         '',
196:       )
197:     }
198:     const res = await c.run(['api', issuePath(id, k), '--method', 'PUT', '-f', `assignee_ids=${assigneeIds.join(',')}`], …)
```

- 一个写请求都不发：`unresolved` 非空直接返回，PUT 在 `:198` 之后才可能发生。
- 空数组仍是「明确清空」：`wanted` 为空 → 循环不跑 → `unresolved` 为空 → 发一次 `assignee_ids=`（空串），行为与以前一致。
- 失败档位是 `not-found`，原文给空串（没有外部写请求的原文可引）。

对照票面四条修复方向建议：

1. 「先解析全部 username，有任何解析不到就在写之前失败并说明原认领未变」→ 已做（`:169-197`）。
2. 「区分明确清空（空数组）与解析失败」→ 已做：空数组走 PUT 清空；解析失败在 PUT 之前返回失败，不会再落成空串。
3. 「写后回读不一致时披露真实差异」→ 不需要了（不写就不会不一致）；「回执披露」的另一半（顶层句式）归 #1790 B。
4. 「补门禁：PUT 不发生、原认领不变、回执说明原因；空数组才允许清空」→ 已做，见 `tests/verify-1785-assign-unknown.ts`。
